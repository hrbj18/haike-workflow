# 1.2.4：Windows 镜像与源码页面更新

Windows 源码安装、前端构建及增量更新统一使用清华 PyPI / npmmirror，采集锁通过固定版本/哈希导出后安装，渲染浏览器使用固定镜像及 SHA。复用可用 FFmpeg，缺失时按已登记加速/发布方地址校验获取；源码本身仍来自官方 GitHub。见 [镜像规则](../WINDOWS_DEPENDENCY_MIRRORS.md)。

干净官方 Git 安装可从“关于海客视频”直接检查和确认 main 更新，按提交识别同版本代码差异，不再依赖 Release 包。助手固定目标并核对源码/组件检查，等待现有任务，保存旧源码引用、配置/一致性数据库及依赖版本，构建并核对新服务身份后完成。原媒体留在原位置，不复制整个旧安装；失败恢复旧源码、依赖和界面。dirty/index、开发分支、原生运行时或数据结构迁移保留现场交给 Agent。见 [页面更新](../APP_UPDATES.md)。

旧电脑需要先按 [Windows](../UPGRADE_FROM_MAIN.md) / [Mac](../UPGRADE_FROM_MAIN_MAC.md) 完成一次源码接入。新压缩包或同事物理机不会因 main 合入而自动升级。

本地验收包含325项根单元测试（10项按既有条件跳过）、更新桥接/账号写入闸门、动效运行检查、17项页面回归、实际镜像下载和前端构建；源码事务13项包含真实Git切换、两个本机服务重启、依赖/启动失败回退、SQLite与原媒体保留。浏览器确认链路使用明确标记的隔离数据，不冒充真实生产安装。双架构 Mac 的同一事务测试纳入 Source delivery checks，结果以本提交CI为准；同事物理机、真实账号、付费制作和发布另验。本轮无付费生成、无视频发布。
