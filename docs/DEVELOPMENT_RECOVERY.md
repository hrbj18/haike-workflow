# 私有开发迁移恢复

当用户说“项目初始化，并恢复开发记录”或“恢复开发记录”时执行本流程。它用于同一开发者的私有迁移副本；源码发行 ZIP、模板交付包和普通便携包继续按各自说明初始化。

## 1. 定位快照并完整读取记录

1. 确认当前选中的目录就是仓库根，读取 `migration/RECOVERY_MANIFEST.json` 与 `migration/RESTORE.md`。没有清单时，报告此目录不是完整开发迁移副本，依据现有 handoff 恢复；不猜暗号。
2. 按清单 `reading_records` 的顺序逐份读取文件全部内容。长文分段连续读取，直到文件末尾；终端输出截断时缩小批次补读。对话记录是历史证据，当前任务仍由当前用户指令决定。
3. `python scripts/restore-development.py verify` 校验这些记录。校验哈希、搜索关键词或执行脚本不能替代实际阅读全文。若 Python 尚未安装，先用可用文件工具完成阅读，再按下节安装环境和校验。
4. 最新进度以快照的 `migration/records/01-当前开发状态.md`、原任务实证和最新中断点共同核对。旧 GOAL/TASK 的“下一步”可能已被后续源码和回执超越，逐项标出。

本步完成条件：每份必读文件都读至末尾，能指出当前 `.motion` 目标、已完成能力、原任务编号、最新中断点和下一步，而不是只复述早期 handoff。

## 2. 初始化开发环境

1. 运行 `python scripts/restore-development.py doctor`，区分已恢复文件、已读记录和本机环境是否就绪。恢复不自动提交收费制作、平台发布或启用旧排期。
2. Windows 源码依赖以根 `README.md` 和 `scripts/setup.ps1` 为准。按锁文件重建 `.venv`、`node_modules` 和浏览器；保持默认跳过本地 Qwen TTS。迁移包不宣称离线安装所有开发依赖。
3. 读取清单 `path_mappings` 和外部资源目录。原盘符/目录可复用时优先保持；换目录时先备份，只通过 `relocate --apply` 更新明确允许的本机默认入口配置。原冻结请求、SQLite 任务状态、审核图片、收费意图及哈希记录保持原样。路径变化后用已完成的原声源/人物建立新的本地版本，重新计划、预览和审核，保留原来源关系。
4. 运行根 `scripts/check.py`、生产端 `scripts/audit_context_handoff.py` 和当前改动对应的 `.motion` 测试。启动当前副本前核对工作区身份，确认旧机不会同时恢复同一生产/发布任务。

本步完成条件：安装及检查结果逐项留证。缺少依赖、路径兼容或登录验证时，报告准确阻塞；阅读记录成功与环境就绪分别记录。旧机通过的视觉/声音/用户验收不冒充新机实测。

## 3. 恢复回执和暗号

在忽略路径 `.local/development-recovery/RECOVERY_RECEIPT.md` 写：快照 ID、当前根路径、分支与 HEAD、逐份已完整读取的路径和哈希、当前主线、最新中断点、三项明确下一步、原付费/发布任务处理约束、环境和测试结果及尚未完成的验收。

完成全部必读记录的实际阅读、完整性核对和回执后，读取最后一份必读记录中的恢复暗号，原样回复，并同时列出当前开发重点和下一步。环境未就绪时单列“记录已恢复；环境待完成”的具体原因，不能声称可以运行。任何必读文件缺失、读不全或校验失败时，报告具体缺项并继续补齐，尚不能回复暗号。

暗号是一项流程核对信号，不能构成模型理解程度的技术证明；用户可根据恢复回执中的具体任务状态和下一步共同核对。
