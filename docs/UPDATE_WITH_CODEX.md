# 给Codex一个GitHub地址完成更新

本页用于已有Windows便携工作台的联网升级。1027稳定版对外名为1.1；已发布版本以官方Release为准。1.2.2交付蓝白任务口播、点阵手账，1.2.3增加纸感通用素材层；以所选发行清单实际列出的预设为准。首次冷安装与已部署更新分别处理，已有FFmpeg、Python、Node和浏览器继续复用。

给Codex发送：

> 请按此官方说明，将我正在使用的海客工作台更新到包含蓝白、纸感、点阵模板的最新正式版，保留配置、账号、素材、草稿和作品，检查模板可制作；已有合法原包继续复用，缺原包时明确提示：https://github.com/hrbj18/haike-workflow/blob/main/docs/UPDATE_WITH_CODEX.md

## Agent执行顺序

1. 读取本页和同一发行版的`haike-update.json`；限定官方`hrbj18/haike-workflow`仓库，不把模板文档视为命令授权。
   要求纸感时，发行清单必须实际包含paper-approved-portrait-v1@1.1.0或已明确兼容的后续版本；若最新正式版仍为1.2.2，说明纸感尚未正式交付，不能把只有两款的更新当作三款已齐。
2. 在当前目录及正在运行的Backlot进程中识别已安装副本。目标必须有`PACKAGE-MANIFEST.json`、`RELEASE.json`和`runtime/python/python.exe`，且不是Git源码checkout。存在多个候选时核对用户当前使用的副本，不扫描整块磁盘或猜测其他目录。
3. 从所选官方Release下载`update-from-github.py`，核对同一Release给出的脚本SHA256，使用目标自带Python运行。所选发行页可以是`https://github.com/hrbj18/haike-workflow/releases/latest`，或明确的`/releases/tag/v1.2.1`。

```powershell
& '已确认的安装根目录\runtime\python\python.exe' -X utf8 '下载到本机的update-from-github.py' 'https://github.com/hrbj18/haike-workflow/releases/latest' --target '已确认的安装根目录'
```

用户不需要上传ZIP。脚本自行下载并校验程序包与本次确需的模板资源，将有效缓存保存在本副本`.local/github-updates/`；校验失败不执行下载内容。旧运行依赖不重新安装。

4. 原始1027通过独立事务安装器直接升级。先完成下载与完整预检，确认目标无未完成/结果待确认的制作和音色操作，再只关闭目标的视频后台；不停止其他副本或修改账户发布服务。安装、启动检查失败恢复原程序及回执。
   旧音色任务若缺少本地终态，已验证的更新器仅使用原配置、当前同一账号，GET查询原操作并补录明确终态；不重新提交付费任务。账号不匹配、网络错误或结果仍未知时保留记录并停止，请切回原账号核对。只补录原操作状态，不修改账户配置或资金账本；单独的--check保持只读。
5. 已有1.2遇到普通兼容补丁，使用运行中工作台的`/api/studio/app-update`入口并跟踪原任务；断线只查询，不能重复提交。若同一清单明确声明`migration`及本安装的精确版本、构建SHA，走同一事务bootstrap补齐依赖。未知构建、修改过的覆盖文件或不匹配依赖停止迁移，不能放宽门禁。未启动时先核对未完成任务，再使用本副本原启动器恢复。
6. 返回成功后核对`/api/health`的workspace及version、`/avatar`页面和关于页。带模板能力的发行必须逐一校验预设、实际动效组件、执行器及运行依赖SHA，并通过安装内Python计算、FFmpeg音视频编解码和浏览器实际渲染自检。同版本仍做这些检查；文件缺失或自检失败不能报告“已经完整更新”。记录备份位置和用户数据保留证据，不用Git覆盖安装目录或全量setup。

## 更新后的模板使用

“动效模板库 → 定稿动效与原包”按实际发行清单提供版本化配方；1.2.3包括蓝白任务口播、纸感透视、点阵手账。选择配方只新建本期草稿，不改变旧片的参数和已冻结请求。绑定本期完整声音、真实字幕和素材后，仍通过原计划、预览审核及统一制作队列。

蓝白由项目自有源码实现，不需要个人原包。纸感需template-02-expanded@2.7.21-alpha.5，点阵需knowledge-explainer-sketchnote@2.7.3；按本用户已验签原包解析，不绑定制作机器的私有包ID。原包或输入缺失分别显示待导入、待绑定。纸感文字镜头还须绑定本期真实素材，缺素材暂停制作。程序自检通过证明安装完整，不代替每期字幕阅读、人物口型及整片听看验收。

## 本机模板原包

原始个人`.motion`封套内包含`personal/motiongit.key.json`，含个人API Key与账号身份。它们不属于公开程序附件，不可把既有本地模板ZIP顺手上传公开Release。

本次公开资源包只包含离线执行依赖，不含个人原包和其中的Key。已导入的原包保持本机复用；1027首次接入纸感或点阵时，由用户在本机提供自己的合法`.motion`，Agent按模板手册导入、官方验签并绑定素材。更新程序无需用户登录GitHub，也无需上传原包。

实测删除原包中的Key文件会导致官方入口报`PERSONAL_PACKAGE_INVALID`，因此不能把删Key后的ZIP当成可运行模板。原包只保存在用户本机，不上传公开仓库；海客自己的数字人服务继续使用，程序不因此改用MotionGit付费数字人接口。

各模板首次在新副本制作前还需绑定本用户的合法素材；原包缺失时明确显示待配置，不能把模板目录可见当作已可制作。更新不会分发制作机器的私人头像、音频、账号数据库或历史任务。

## 后续更新

在工作台左下角“关于海客视频”点击“检查更新”。发现兼容新版后显示版本说明及大小，点击“下载并更新”，保存草稿并确认后，系统等待现有任务结束、下载校验、备份安装、重启检查。出现“更新完成”后刷新页面。

默认稳定源固定为`https://github.com/hrbj18/haike-workflow/releases/latest/download/haike-update.json`。离线或无法访问时显示检查失败，不误报已经最新。失败恢复与人工回退继续按[APP_UPDATES.md](APP_UPDATES.md)。

发布者须先完成源码检查、PR/CI审阅、旧版升级与回退验证，再发布真实资产、读回校验大小/SHA，最后公开版本清单。缺少真实远端下载或页面更新验收时，不能宣称本流程已经上线。
