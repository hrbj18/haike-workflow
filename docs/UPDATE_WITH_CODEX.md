# 给 Codex 一个 GitHub 地址完成更新

适用于可识别的海客旧便携安装、历史目录布局和 Git 源码 checkout。Agent统一使用 scripts/upgrade-haike.py 的 plan/apply，由它选择原更新事务或隔离源码路线；首次安装仍按[README](../README.md)和[PORTABLE](PORTABLE.md)。

给 Codex 发送这一句即可：

> 请按官方说明识别并将我正在使用的海客工作台更新到最新稳定版，保留配置、账号、素材、草稿、作品，以及 Git 未提交和已暂存修改；核验本次实际交付的18套首选动效、组件与运行能力，分别报告程序升级和模板可制作状态：https://github.com/hrbj18/haike-workflow/blob/main/docs/UPDATE_WITH_CODEX.md

## 官方稳定版与本地候选

正式更新源固定为[官方Release](https://github.com/hrbj18/haike-workflow/releases/latest)及其同一期 haike-update.json、程序包、资源包和 SHA256。版本、构建和实际可下载内容以这些附件为准；源码目录中存在新入口、模板或检查回执，不表示远端已发布。

18套统一升级的交付身份以本期Release附件和实际自检为准；历史1.2.2 compat6的蓝白、点阵交付不能代替新18套验收，本地候选也不能代表正式版已上线。统一入口随包含它的程序包或已核对的源码一起提供，是多文件工具，不能只下载一个 CLI 文件便假定配套模块齐全。旧发行尚未提供新入口时，保留真实发布状态；可从已核对的官方源码调用统一分派层，便携部分继续委托所选发行经 SHA 核验的原安装器，不把开发源码当成新稳定版。

## Agent执行顺序

1. **识别目标。** 读本页、[交付边界](DISTRIBUTION.md)和所选发行清单，在用户当前目录及明确相关的海客包装目录中定位目标，不扫描整块磁盘。先运行本地 plan；多个副本时明确本次目标。Git checkout、便携根和历史嵌套目录分别识别，不因缺少某个新版文件就直接终止升级。
2. **核对来源。** 统一入口及配套源码须可追溯到已核对的发行或源码身份。下载先核实际大小和完整 SHA256，再执行；source_commit绑定真实 Git 基线，含未提交改动的本地候选另记实际源码树 SHA和来源，不伪造已提交、已发布身份。plan --online只检查官方清单与路线，不代表依赖、备份或渲染已通过。
3. **按固定路线推进。** 在既有升级授权范围内执行 apply，复用原事务、有效缓存和成功依赖。程序/资源下载完整校验与原预检通过后，才进入对应安装步骤；未知服务结果沿原记录处理，不重新提交。
4. **核对程序与数据。** 记录原/新版本、目标绝对路径、更新任务或备份回执、保留数据证据和恢复入口。实际启动后核对 /api/health 的workspace/version、/avatar和关于页。隔离源码尚未启用时，报告候选路径及剩余依赖/数据绑定，不将检出成功写成安装完成。
5. **核对本次模板。** 按下节区分文件/合同、实际组件调用、短区间渲染及本期视频验收。未听看如实列出。引号字形、小幅位置尺寸、非关键曲线、署名细微时序或末端失焦差异仅作记录，不继续精修、反复渲染或阻断交付；只处理影响使用的明显问题。

Agent根据已识别的Python、工具目录和目标填入下列命令。便携目标优先复用包内Python；源码工具使用已经准备好的checkout Python，不为更新重装整套环境。

    $taskPython = '已核对的Python绝对路径'
    $taskEntry = '已核对的工具根\scripts\upgrade-haike.py'
    $taskTarget = '用户当前海客副本的绝对路径'
    & $taskPython -B $taskEntry plan --target $taskTarget
    & $taskPython -B $taskEntry plan --target $taskTarget --online
    & $taskPython -B $taskEntry apply --target $taskTarget --github-url 'https://github.com/hrbj18/haike-workflow/releases/latest'

需要明确Git/历史隔离候选位置时，加 --destination '原目录之外的新目录'。用户无需上传ZIP；正式路线自动下载并按清单校验程序和所需资源，缓存按完整SHA复用。合法资源不因旧200MB固定上限被拒绝，大小仍须符合本期清单和更新器的有界限制。Windows长路径在文件I/O层处理，逻辑workspace和回执保留普通绝对路径。

## 各类目标如何升级

| 识别结果 | 执行与完成边界 |
| --- | --- |
| 原1027便携安装 | 委托原bootstrap事务，核原清单、覆盖前后SHA、复用依赖及资源；备份、安装、启动检查失败沿原回执恢复。 |
| 已有1.2及后续兼容便携安装 | 普通兼容补丁走原应用内更新任务；精确迁移或清单声明的project兼容走原事务，按实际项目格式、组件、ABI和锁文件核验。项目兼容不取消用户文件校验。 |
| Git checkout，包括dirty/index已暂存状态 | 按官方精确提交建立独立worktree，保留原分支、工作树、未提交、已暂存及未跟踪内容；不在原目录强制checkout、reset、clean或覆盖配置。新源码候选完成隔离依赖/诊断和数据绑定后再切换。 |
| 可识别历史布局、来源或依赖冲突 | 保留原目录、设置备份和数据位置，建立独立官方源码候选；沿源码/便携对应准备流程继续。提交不在旧白名单、ZIP安装器拒绝Git或目录有差异不能作为最终终点，也不通过跳过SHA或覆盖用户修改强行安装。 |

只有目标的运行任务和更新事务达到安全状态时才能安装。运行中、持有有效worker/租约或仍有实际受理风险的任务，沿原记录处理；旧无worker的暂停/待核对记录是否可保留，由已核对的queue/audio guard判断，不把它们重新提交生产。更新助手只管理确认属于本目标的视频后台，保留其他副本、账号发布服务、账本和已完成的配音/ASR/数字人产物。

音色等原操作需要核对时，只使用原配置和同一账号查询原操作，不重新创建付费调用。账号不匹配或结果仍未知时保留原记录和恢复点。备份准备未完成不能当完整回退源；安装后文件又被用户修改时，回退也不得静默覆盖。具体恢复按[APP_UPDATES](APP_UPDATES.md)和实际回执，不把程序回退当资金数据库恢复。

## 18套模板与验证范围

本期实际首选以安装内 Haike_video/config/motion-preferred-production.json，以及同一候选/发行声明的全部版本化registry、schema、适配器和来源SHA为准。原三组注册用于历史兼容，注册总数不固定为三；同一模板可保留多个精确版本，不能只看到旧目录就认定最新路线已接通。

Agent在目标安装中先读实际能力；源码候选在其运行环境就绪后执行同一目标内的固定入口：

    & '目标根\runtime\python\python.exe' -s '目标根\portable\template_capability.py' --root '目标根'
    & '目标根\runtime\python\python.exe' -s '目标根\portable\template_capability.py' --root '目标根' --component-selftest
    & '目标根\runtime\python\python.exe' -s '目标根\portable\template_capability.py' --root '目标根' --diagnostic-plan

按每套分别报告：

- **合同与文件：** 首选精确版本、真实入口、动作/受控槽、可分发源码、字体/组件/运行依赖和逐文件SHA；缺件或漂移明确影响哪条路线。
- **实际组件调用：** --component-selftest验证目标内固定组件的import/计算等调用，--diagnostic-plan给出固定调用与工具映射。这两项不生成媒体，不等于已渲染。
- **运行与短渲：** 按实际诊断计划完成目标所需的Python、音视频编解码、浏览器或对应renderer短区间调用，保存工具、输入、输出SHA及具体覆盖。--selftest按该安装的实现执行；返回component-passed-media-not-performed或render_selftest: not-performed时，媒体项仍待验，不能改写为通过。身份未变时复用有效目标回执，短自检不要求反复制作18条完整视频。
- **本期制作与听看：** 已锁定的18条完整HD有声片和成功声音/人物按原身份复用。更新完整性、短渲、本期动作对照、连续听看、真机和另一台物理机分别留证；未听看明确未听看，不新增音频模型或权限作为前置。

production_ready: false、inspect_only、needs_adaptation及固定时序/输入限制按实际返回解释。组件SHA匹配不自动授予素材权限，也不把尚未接通的合同升格为生产可用；真实制作沿该首选精确合同及现有预览、明确审核、统一队列门禁执行。

## 原包、私有输入与本地候选

独立公开源码路线按实际实现和可分发组件运行，不把私人.motion原包作为所有18套的通用前置。只有实际选中的原生/历史合同声明必需原包、私有组件或工具时，才逐项核验本用户已有合法包、官方验签和权限；已有有效授权直接沿用。缺失时说明受影响路线，继续其他已具备能力的路线，不要求重复提供已成功使用的输入。

个人原包可能含Key和账号身份，留在本机。更新不把私人原包、凭据、人物、声音、历史封面、数据库、任务、作品和素材打入公开附件；已有本地内容原样保留，具体边界见[DISTRIBUTION](DISTRIBUTION.md)。

开发验收用 apply-candidate --target <新隔离根> --candidate-feed <本地候选清单>，要求明确sandbox标记、candidate_only、真实源码树SHA/Git来源及两ZIP大小/SHA。显式回环测试HTTP只在这条隔离路线使用。下载、安装、重复和回退记录属于该本地候选，不证明公网可下载或真实用户安装已升级。正式稳定打包门槛保持；发布另须当期授权、真实远端附件大小/SHA读回及最终发布清单核对。

后续日常兼容补丁仍可从工作台“关于海客视频”检查更新；断线跟踪原任务，不重复提交。网络失败、缺文件或自检未完成分别报告，不显示为“已完整更新”。
