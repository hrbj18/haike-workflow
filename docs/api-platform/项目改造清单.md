# 按最新代码的改造清单

基线：`main@05183670edca40483f4d2d212282e4c05c94cc84`。以下“新增/改造”均是实施计划，当前未修改业务代码。

## 1. 与旧离线包设计的差别

| 核对项 | 最新仓库事实 | 方案调整 |
|---|---|---|
| 仓库布局 | 四模块已整合为单仓；根 README/安装脚本优先，模块旧多仓提交仅是历史 | 后续代码改造与发布以单仓 commit 为版本，不在模块内拉旧上游 |
| 中转 mock | Git 跟踪文件不含离线包 `portable/relay`；根 `_distribution-tools` 仅保留部署辅助 | 审查旧协议和17类模拟场景后迁入新平台，不宣称已有充值服务器 |
| 配音入口 | `backlot/tts_runtime.py::generate_voice_audio` 按冻结 profile 直接分发本地/腾讯/百炼/豆包 | 增加计费来源字段及统一平台调用分支，保留实际 provider/model |
| 百炼估算 | `lib/bailian_speech.py` 的 `tts_cost` 是 float 目录价估算；CosyVoice 字符、Qwen Token | 正式资金用微元与云端价格版本；本地估算不能当扣费凭证 |
| 音色 | 创建记录包含本地供应商账户指纹、冻结模型和恢复状态 | 新建平台音色归客户账户，返回不透明平台 voice_id；上游ID/空间映射留云端 |
| 队列 | SQLite 本地父任务排队，媒体管线仍掌握阶段、预算和供应商恢复 | 保留本地生产队列；新增云端计费任务，两类ID显式关联 |
| 发布/采集 | CreatorHub与CopySkill独立职责及私有登录态 | 不为充值把平台Cookie、账号数据库或整个项目上传云端 |

已逐字节比较10个关键后端/前端文件，均与当前已部署离线包相同；区别主要在单仓交付入口、源码清理和配置管理。证据见 [baseline-evidence.json](baseline-evidence.json)。这不等于整个源码树完全相同，也不等于新源码已在本机重新部署。

## 2. 本地工作台具体改造位置

### 2.1 统一设置与账户摘要

- `Haike_video/backlot/server.py`：新增 `/api/relay/config` 的读/写/清除，以及 `/api/relay/account-summary`、`/api/relay/capabilities`。只返回 Key 已配置/掩码/状态，不返回明文。
- `Haike_video/backlot/ui/audio_center.js::bailianApiPanel`（基线第668行）：目前要求百炼Key与OSS高级设置；新增“海客统一API”配置入口，平台模式仅填客户Key，并展示余额、可用模型和充值入口。保留“自有API”高级模式但明确计费来源。
- `Haike_video/backlot/ui/index.html`、对应导航脚本：增加账户中心入口、连接摘要；完整支付页面打开云端 HTTPS 页面。
- 拟新增 `Haike_video/backlot/relay_config.py` 与 `Haike_video/lib/haike_api_client.py`：秘密保存、HTTPS、免费连通检查、版本验证、统一错误、quote/submit/query/download。不要把离线包 `portable` 运行时路径变成业务代码必须依赖的目录。
- 配置示例只列 `HAIKE_API_BASE_URL`、`HAIKE_API_KEY` 空值及模式；真实Key仍写忽略私有配置。`scripts/configure.py` 保持已有用户配置不覆盖。

### 2.2 配音与音色

- `backlot/tts_runtime.py::generate_voice_audio`（第67行）：平台分支按音色冻结的 `billing_source=platform`、`gateway_voice_id`、provider/model、rate调用。上游供应商名保留，不能把所有provider_id改成relay而丢失模型来源。
- 调用者包含音色试听、数字人口播、审核预览、素材解说和项目旁白；均须经过统一分支。不能仅改音色试听按钮，正式生产仍直连旧供应商。
- `backlot/audio_center.py`：平台音色列表、添加/删除本地引用、默认音色与冻结profile。删除本地音色引用和删除云端音色是两项操作；旧供应商账户音色不能自动迁到公司账户。
- `backlot/bailian_voice_clone.py::_execute`（第131行）：保留“不明受理不重发、已有ID只查不创建”的规则。平台模式上传给公司文件接口，由云端OSS/供应商创建与查询；原本地OSS流程保留给自有API模式。
- `tools/audio/bailian_tts.py::BailianTTS`：现有分段、下载恢复和最终PCM16单声道24kHz契约可迁移到云端adapter；原直连工具保留本地兼容。不得全局替换 `BAILIAN_API_KEY` 为公司Key，两者协议不同。
- `.wav.bailian.json` 等本地结果补充 `billing_source / gateway_job_id / gateway_bill_id / price_version_id / charged_micros`；隐藏供应商凭据。旧 `estimated_cost_cny` 字段仍标“估算”。

### 2.3 数字人、队列与恢复

- `backlot/production_queue.py::ProductionQueue`（第95行）：继续只负责本地制片任务准入、顺序、租约和恢复，不在SQLite里作为客户钱包结算。
- `backlot/server.py::_enqueue_production_parent`（第772行）与 `/api/production-queue/jobs`：入队请求冻结平台账户标识、阶段预算和计费来源，但不冻结Key明文。入队不等于立即冻结整个视频价格；云能力就绪、报价接受时才预占。
- `backlot/avatar_review_preview_pipeline.py::_generate_runninghub_avatars`（第1914行）：现有完整主持长音频、角色记录、精确帧时钟和恢复逻辑保留。先抽出“submit/query/result”边界，在平台模式由网关完成；禁止在本地和云端各执行一次供应商 submit。
- `tools/avatar/runninghub_avatar.py::RunningHubLongCatClient`：其 upload/submit/poll/download 分别对应云端adapter边界。首版限定已记录的精确时钟 profile，不开放客户任意修改RunningHub节点和工作流。
- `backlot/avatar_cloud.py` 以及每日/审核/解说其他数字人入口逐个核对；只有全部平台入口完成才宣称该能力支持统一Key。
- 每个本地阶段持久化 `call_intent_id`、输入哈希、网关任务与账单ID；重新启动查询原任务。重新编辑输入才生成新意图并重新报价。
- 一个本地视频父任务关联多个云计费任务；双主持是一个云数字人计费任务的两个子任务。UI可聚合费用，但数据库不重复扣“父总价+子价”。

### 2.4 扩展能力

- `backlot/bailian_asr.py`、`tencent_asr.py`、`doubao_asr.py`：上传、提交、查任务与时间戳结果统一；保留“ASR可选取证”以及原缓存/恢复行为，单位按具体模型配置。
- `backlot/ai_text.py::resolve_text_ai_credentials`（第326行）、`backlot/ai_vision.py`：后期可接云端文本/视觉兼容接口。模型Key+Base URL仅覆盖这类兼容协议；Agent理解/写稿默认无需平台模型消费。
- `tools/graphics`、`tools/video`、`tools/audio` 及工具注册/能力矩阵：逐工具增加计费来源、供应商协议adapter与报价。生图、生视频、音乐不能仅依靠改环境变量完成。
- CopySkill如使用其云模型，后期接同一客户端协议并标记来源；CreatorHub的平台登录/发布无需模型网关。已有名称含relay的采集配置或发布选择测试，不是本方案钱包网关。

## 3. 新增云端模块建议

```text
api-platform/                 # 建议目录，当前尚未创建应用
  app/
    auth/                    # 账户、会话、Key、scope
    catalog/                 # 模型、档位、可用状态
    pricing/                 # 价格版本、计量、报价
    wallet/                  # 复式账本、预占、结算、退额
    payments/                # 订单、验签事件、渠道查询/退款
    jobs/                    # 任务、提交意图、outbox、核对
    providers/               # 独立上游适配器
    media/                   # 上传、音色、私有产物
    admin/                   # 权限、价格发布、审计、争议
  web/                       # 账户中心与独立运营界面
  migrations/
  tests/
```

供应商worker实行能力和账户并发限制，不继承本地“全局父视频单通道”成为所有客户只能排一条任务。服务器允许多个客户并行，客户本地原制作约束继续执行。

## 4. 上线检查与回退

M1先增加新设置、客户端、云端模拟和资金回归，暂不将默认来源切为平台。M2实际验收后将新用户默认来源设为平台，自有Key模式保持显式选择。旧项目使用冻结来源，禁止升级时静默改账户或模型。

平台不可用时暂停新的云阶段，保留已完成音频/数字人/本地工程和全部call_intent；本地渲染照常可用。恢复后先查原任务。不存在“回退到mock继续真实扣费”的生产模式。

开发验证重点：

- 新客户端单测与支付/账本事务测试；以真实并发验证资金，不用仅字符串匹配测试证明安全。
- 扩展现有 `tests/backlot/test_audio_center.py`、`test_bailian_voice_clone.py`、`test_bailian_speech.py` 与 `test_avatar_review_preview_pipeline.py`，确认原本冻结模型、断点、精确时钟规则仍有效。
- 保留现有生产队列恢复测试；新增本地重启与云任务恢复联调。
- 运行根 `python scripts/check.py` 与模块实际相关测试。真实模型小样和支付验收另有费用与凭据，模拟通过不等于生产验收。
