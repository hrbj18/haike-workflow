# 海客视频应用更新

已有1027（1.1）安装要直接联网升级，按[给Codex一个GitHub地址](UPDATE_WITH_CODEX.md)操作；用户无需上传ZIP。1.2的联网修订规范号为1.2.1；已有本地1.2.0可由下述“关于海客视频”检查并下载兼容补丁。没有实际公开的资产和清单时仍显示无法检查，不把本地候选包当成已上线版本。

## 使用方式与第一版范围

工作台侧边栏底部的“关于海客视频”显示当前产品版本、构建身份、安装类型及模板补丁记录。打开时检查最新稳定版，也可手动重新检查；网络错误或尚无发布清单时显示暂时无法检查，不会显示“已是最新版本”。

兼容的 Windows x64 便携安装可下载并更新。安装前保存正在编辑的草稿；确认后由独立更新助手等待任务空闲、备份程序文件、停止本副本工作台、安装补丁并重启验证。重启期间弹窗会等待重新连接。源码开发副本可检查版本，但不会自动覆盖源码或未提交修改。

下载或等待任务阶段可“暂缓更新”，恢复正常操作；开始安装或重启后等待本次检查结束。待核对的制作/音色/发布结果阻止更新，可先暂缓后处理原任务。账号服务继续运行，较远的未来发布排期保留；正在发布或临近执行的任务须先结束。

第一版只接受相同运行环境、相同数据结构且精确匹配基线的工作台程序补丁，不更新发布、采集与云端账户服务源码。依赖、运行环境、数据库结构发生变化，或者旧包缺少新的版本身份时，须另外交付完整新版并按迁移方案处理。旧模板更新器保留其原用途；模板补丁编号不改变整包版本。

程序补丁可带公开测试源码及前端编译产物。运行环境清单保留原安装的来源记录，应用构建提交以更新后的 `RELEASE.json` 为准；打包器允许 runtime 来源记录仅应用提交字段变化，其他运行环境来源或组件变化仍拒绝快速更新。

根 `VERSION.json` 从 `1.0.0` 开始引入统一产品编号。该编号是构建输入，不代表已在网上发布：便携构建把它与真实 `source_commit` 一起写入 `RELEASE.json`；源码工作区显示开发状态。正式发行由验收后的发布清单和实际更新包共同确定，不能将 main 每次提交当作可安装更新。

首版完整便携包的清单使用 `package.kind: full`、`base_version: 0.0.0`，可由 `scripts/package-full-release.py` 从已验证 ZIP 生成。它用于发现正式版本和首次迁移，不进入程序补丁安装路径；已安装相同版本显示当前版本。后续 `package-app-update.py` 生成的兼容补丁清单沿用 `patch` 类型（省略 kind 时也按 patch 处理）。

## 数据与恢复边界

更新包仅允许明确的程序文件，禁止覆盖本机配置、账号数据库、Cookie/浏览器会话、草稿、任务、项目、素材和作品。`RELEASE.json`、`PACKAGE-MANIFEST.json` 由更新器按成功安装结果维护。应用前核对依赖锁、基线文件哈希、更新包及每个文件的 SHA256，并拒绝链接、越界路径及额外非程序文件。

备份、事务回执和更新状态放在目标安装的 `.local/app-updates/`。文件写入失败或重启健康检查失败时恢复旧程序。中断后的回执保留已写入与原始哈希，恢复时先检查完整恢复范围；更新后又被用户修改的文件不会被静默覆盖。回退不会删除或搬移用户数据。

需要人工恢复时，先处理完本副本正在进行的任务并关闭该工作台服务，保留其他副本。使用备份回执给出的绝对路径，并把端口改为该副本实际端口：

```powershell
& .\runtime\python\python.exe -s .\portable\update_worker.py --root 'D:\海客安装' --rollback 'D:\海客安装\.local\app-updates\回执中的备份目录' --port 14756
```

人工恢复命令要求目标工作台服务已关闭，不会主动停止正在运行的任务；确认目标已停止后回退程序并重新启动。目标端口仍有服务或文件发生后续修改时停止，不强行覆盖。

数据结构迁移不属于第一版程序补丁；云端 API 收费服务和账本独立管理，程序回退不回退账本。仅停止经服务身份核对属于本安装的进程，其他安装副本保持运行。正在进行或结果待确认的制作、下载与发布任务必须先处理到安全状态。

## 更新来源

默认读取固定 HTTPS 地址：

```text
https://github.com/hrbj18/haike-workflow/releases/latest/download/haike-update.json
```

维护者可在工作台启动环境设置 `HAIKE_UPDATE_FEED_URL` 指向自己的 HTTPS 发布清单。普通网页请求不能指定更新来源或任意安装地址。私有 Key、供应商凭据不随更新检查发送。

功能实现和本地隔离测试不代表更新源已上线。首次可用更新仍需要维护者实际发布兼容的清单及 ZIP；当前没有清单、访问超时或附件不存在时，页面会提示无法检查/没有可用发行信息。

公开更新包只包含可公开分发的程序。现有 40 张授权截图只获本地 ZIP 交付授权，私人样片、人物和声音继续按 [交付边界](DISTRIBUTION.md) 管理，不得顺手放进公开 GitHub Release。原安装中已有的本地资源保持原样。

## 维护者制作程序补丁

1. 从已验收提交生成两份干净便携 stage：已交付的基线与目标新版。保留各自 `RELEASE.json` 和 `PACKAGE-MANIFEST.json`。目标产品版本大于基线；版本号和构建提交必须真实对应。
2. 目标 stage 必须已包含重新构建的前端。运行源码、模块及隔离更新验证；没有真实付费、发布授权时继续使用假供应商和测试账号数据。
3. 使用同一运行环境和依赖锁。打包器会拒绝运行依赖、数据结构、资源授权范围等不受支持的变化，并校验两份 stage 的每个清单文件。前端重新构建产生新 hash 的 JS/CSS 时，安装新增文件并替换入口，原 hash 资源及其包清单条目继续保留，便于缓存中的旧页面与失败回退；第一版不执行文件删除。运行时、依赖或受保护资源在目标 stage 缺失时仍拒绝打包。
4. 在两份 stage 之外的新目录生成更新 ZIP、SHA256 和 `haike-update.json`：

```powershell
python scripts/package-app-update.py --baseline 'D:\release\old-stage' --stage 'D:\release\new-stage' --output 'D:\release\v1.0.1\haike-1.0.1.zip' --package-url 'https://example.com/releases/v1.0.1/haike-1.0.1.zip' --notes-file 'D:\release\notes.txt'
```

`--package-url` 是实际发布后的固定 HTTPS ZIP 地址。该命令只在本机生成文件，不上传、不创建 Release，也不会自动升级任何正在运行的安装。输出已存在时拒绝覆盖，避免替换已发布资产。

更新 ZIP 的根是 `UPDATE-MANIFEST.json` 和 `payload/`。清单声明目标/基线版本、运行环境、数据结构、来源提交、完整依赖锁及程序文件的更新前后哈希。下载清单声明发布说明、时间、包地址、大小和 SHA256。先发布 ZIP 并读回核对，再发布清单，确保用户检测到的附件实际可下载。

5. 在隔离的基线副本中完成成功更新、重复检查、失败回退及用户数据字节不变验证。上线发布另按当期授权、PR 检查与交付范围执行。另一台物理机和真实生产任务的验证分别记录。
