# 海客视频 UI 与组件改版

日期：2026-10-13。任务：Task Master #9。

## 目标与范围

用户明确要求重新设计 UI，改善按钮、弹窗和操作体验。保留海客科技品牌、五个共用导航入口、现有模板、原生生产队列、统一 API 接入及发布确认流程。用户已选择第一版“内容优先工作台”，参考为 selected-design.png；已实施到实际14754工作台。

## 现场发现

- 图文页面：预览过大；内容面板内边距缺失，字段紧贴面板边缘；说明和模板卡占用大量高度；保存与生成按钮在长表单底部。
- 口播页面：模板选择重复，声音来源、上传和配置按钮的层级不清楚；字号与颜色等次要设置应按需展开。
- 共用组件：两套弹窗实现存在关闭、焦点恢复和布局差异；没有统一的按钮、字段、上传、反馈和弹窗结构。
- 排期弹窗：尚无最终成片或可用账号时，仍显示常规表单及提交按钮；缺少通向解决问题的明确操作。
- 作品和 API 设置：状态、下一步操作以及空状态需要用统一的组件表达。

## 组件实现约定

1. Button / IconButton：主、次、文字、危险操作四种语义；标准尺寸与间距；提供 hover、focus、disabled、loading；图标按钮有可读标签。
2. Field：标签、输入、提示、错误统一布局并关联输入；必填字段使用原生表单校验，业务失败显示操作附近的状态；字段与外边缘保持足够间距。
3. UploadField：上传前显示文件范围；上传中反馈进度；上传后显示缩略图、名称、替换和移除；失败可重试。
4. Dialog：统一标题、内容、固定操作区；长内容在弹窗内部滚动；支持键盘、焦点恢复、清楚的取消操作；请求进行中避免重复提交。
5. Notice / EmptyState / Status：成功、处理中、失败和缺少前提有一致表达；每个需要处理的状态配一个具体下一步。
6. TemplatePicker / Preview：仅展示项目实际模板；区分版式参考与真实生成结果；不把静态参考描述为实时生成预览。
7. ActionBar：创作页主操作始终容易找到；展示费用或阻塞条件，保持一个主要动作。
8. Sidebar：五个菜单的几何位置与交互保持一致，当前项同时用形状和颜色标识。

## 验证边界

设计方案使用图文页比较布局策略，已统一应用到图文、口播、作品、发布日历和 API 设置；验证桌面与窄屏、键盘焦点、弹窗关闭、上传/替换/移除/保存与阻塞状态。验收不调用收费模型、不发布内容，不改变已有成片或人工确认结果。用户提供的海客 Key 已按本次接入需求保存到本地后台，权限0600，前端只显示末四位。

## 实际实现与证据

- src/ui.jsx：Button、Field、UploadField、Dialog、PreviewPanel、ActionBar、Notice、EmptyState；原生dialog支持Esc、焦点返回与内容内部滚动。
- 图文：三行标题和三景横排输入；口播：保留三套模板与声音来源；窄屏预览按需展开，创作主操作保持可见。
- 日历：今日标识、过去日期不可选；无最终版或账号时明确下一步并禁止提交；作品审核操作固定在弹窗底部。
- API设置：六项能力列表与实际余额；当前4项开通、2项采购价待确认，生成按钮明确受阻；价率显示保留小数精度。
