# 下载凭据集成与账号登录态方案

日期：2026-10-16。适用独立副本 `haike-workflow-2`。

当前状态：新版素材库已接入“账号与下载登录”和“网络素材”。快手和视频号两轮账号服务重启后无需重扫，下载和创作中心只读检查通过。抖音复用用户提供的本机 Cookie 文件，仅导入抖音域、保留有效期等属性，账号3下载检查及服务重启复用通过。MediaCrawler 已装好，机器人关键词三条下载链均完成真实下载、完整解码与素材库登记；3个新文件按SHA正确去重为2份素材。没有发布或付费模型调用；隔夜、系统重启和长期有效性仍未验证。

用户补充的主要触发条件是“重启工作台或隔天使用”。已补独立进程回归：第一个进程通过真实保存回调写入临时数据库后完全退出，第二个进程重新读取账号并通过真实 BrowserManager 桥接至空的模拟浏览器；快手、视频号均恢复最新 Cookie，且新 manager 没有旧内存 checkpoint。测试全程使用隔离配置和模拟令牌，不证明真实平台隔夜有效。

## 用户体验目标

素材库增加“网络素材”和“账号与下载登录”。用户选择平台和账号，打开项目管理的浏览器，完成扫码，点击检查；此后粘贴素材链接即可下载和登记素材库，无需导出或粘贴 Cookie。已有发布账号可以只读提供下载凭据，也可单独添加下载账号。

项目已经控制自己的浏览器 context，可以直接从浏览器 Cookie API 获取包含 HttpOnly 的 Cookie，不需要额外安装扩展。这是受控账号浏览器的能力，不是读取用户日常浏览器的全部账号。完整浏览器需在安装时检测或安装；Remotion 的渲染 Headless Shell 不能代替登录浏览器。

## 已查明的问题与修复

1. 打开账号窗口时，旧数据库快照曾无条件覆盖浏览器中的更新 Cookie。真实路由隔离复现失败后修复为保留当前 Cookie、仅补缺失项并过滤过期快照。
2. 快手/视频号日常会话轮换缺少统一保存。现补开窗导航后、每 30 秒、受控关闭前，以及发布/评论临时窗口关闭前的 checkpoint。回调核对账号、平台和 Profile 路径，不改变账号登录状态，也不延长服务器会话有效期。
3. 冷启动使用的 Identity 可能在关闭旧窗口前就已读取旧快照。现让同账号、同平台、同 Profile 的最新成功 checkpoint 作为补缺失来源；浏览器中已有的 Cookie 仍优先。
4. 视频号探针曾因暂态登录页而误判失效，也可能接纳错误响应夹带的昵称。现在仅成功 HTTP、明确业务成功及有效资料共同确认；未知、冲突和网络错误保持未确认，不据此写成失效。
5. 快手主站与创作者中心的登录作用域应分别理解。现有创作者中心兜底离线测试通过；打开浏览器的默认首页对齐已有登录流程的 `/new-reco`。
6. 真实扫码联调发现，下载探针在首个成功但无资料的 auth 响应后过早结束，并将它误作冲突。修复后等待后续明确成功的本人资料响应；快手另核对返回 userId 与当前账号 Cookie 身份，创作中心用独立 CP 业务响应检查，不用公共资料或主站可用代替发布登录。

以上证明应用内缺陷可复现并已修复，不证明它们是用户历史掉登录的全部原因。真实服务端过期、主动退出及重新验证仍需按实际账号证据区分。

## Cookie 获取与下载统一接入

原先存在三套来源：CreatorHub 分享下载读取账号数据库快照，新版 AI 采集使用独立 MediaCrawler Profile，旧单条下载脚本读取工作区 Cookie 文件。现在三条入口均接入本机按平台和账号隔离的共享凭据服务；旧显式 Cookie 文件只保留开发兼容。

实现遵循以下边界：

1. 建立按平台和账号绑定的下载凭据服务。下载前复用对应受控会话并读取目标站点 Cookie，保持该账号 UA、网络代理一致；已有发布 Profile 只读，不清理或强制回灌 Cookie。
2. 下载凭据保存在本机私有目录。后端按目标域过滤，转换为下载器支持的临时 Netscape 文件，保留 HttpOnly、Secure、路径和有效期；成功、失败、取消都清理临时文件。值不进入前端响应、日志或通用安装包。
3. CreatorHub 分享下载、新版 AI 素材采集、旧单条脚本统一调用该服务；旧显式 Cookie 文件仅保留开发兼容。不得让两个浏览器进程同时占用同一 Profile。
4. 登录状态区分“发布可用”和“下载可用”，进一步区分未检查、检查中、可用、需重新登录、需验证、网络失败。保存了 Cookie 不代表登录验证通过；移除只记录“我已登录”的布尔确认方式。
5. 工作台账号入口连接本副本实际配置的 CreatorHub 地址。前端只展示账号昵称、平台、检查结果和操作按钮；扫码页可在工作台内预览，避免原生窗口位于后台时用户看不到二维码。

下载任务先持久化 UUID，再提交；刷新页面按原编号恢复查询，提交结果未知时不自动重发。仅登记任务自己目录中的实际视频文件，并保留来源和使用权确认。所选账号在执行前重新读取和校验，后台周期快照仅刷新已启用的对应账号凭据，不伪造最近检查时间。

启动器自动准备本副本的账号服务，以根目录指纹匹配已有服务；端口被其他副本占用时明确阻断，不结束其他进程。真实发布登录证据只短时缓存五分钟，并绑定账号、Profile 和会话摘要；轮换、重启或过期后回到待确认。`checkpoint-close` 在发布占用或扫码未完成时拒绝关闭，验证浏览器归属并保存成功后才关闭。

MediaCrawler 可选环境于2026-10-16安装完成：官方提交 `8f583999006d5b692272c608440e193ca282e73b`，Python3.12.8、Playwright1.61.0，90项锁定依赖一致性检查、抖音模块导入及CLI帮助通过。复用本机Chrome，不额外下载Chromium。官方声明为非商业学习许可1.1；本次使用单独默认关闭的本地学习CLI，未打开商业授权配置。快手主站下载与创作中心发布分别验证；视频号下载范围仍取决于账号实际权限。

验收后核对原素材基线、完整SHA、文件范围和项目引用为空，再经正式CAS接口归档这2份测试记录，精确将本次3个新视频放入Windows回收站。未删除旧素材、账号、Cookie或运行环境；测试文件可从回收站恢复。工作台已重启加载修复，抖音账号3再次检查通过，发布状态仍未确认。归档后不应将已回收的测试文件显示为可用，已通过正式健康检查更新状态。

真实联调修复：Windows工作台补齐tzdata；libcurl中文CA路径改用同字节、摘要校验的ASCII缓存，保留原信任集和TLS；直接详情HTTP403时在同账号/Profile及风险门禁内只读正常作品页响应，遇到验证停止；Studio抖音媒体入口与CDN的fake-DNS经固定DoH核对公网IP并固定连接。采集登录改认本次导航成功的本人资料响应，不伪造Cookie/页面登录标志，不进入上游自动验证码处理。签名媒体URL可能在上游私有临时JSONL短暂存在，子进程结束后立即清理；已核验最终两轮JSONL各10条，不含媒体直链或Cookie字段，临时下载Cookie文件为0。

失败尝试保留原编号：本地缺时区在发搜索前停止；旧登录标志检查停止；搜索成功但fake-DNS阻断时未下载视频；分享链CA错误和详情403均未生成媒体。修复后采用新编号显式复测，没有重复付费任务或把旧文件冒充新下载。

## 知识库修订提案（未改正式手册）

现象与证据：旧下载手册默认工作区Cookie文件，当前源码三条链已支持账号服务，且已完成本机三链真实入库。首次安装手册中的MediaCrawler环境、旧私有提取函数和时长输出与当前上游有差异；中文CA路径、Windows时区依赖和页面旧登录标志也有真实修复证据。建议维护者核对新源码后，更新独立环境与当前运行器步骤，将统一账号作为新版入口，显式Cookie文件保留开发兼容，并分别说明下载、创作中心、隔夜验证范围。当前仅提出修订，未改正式知识库，也不把本机结果扩大为通用或长期实测结论。
