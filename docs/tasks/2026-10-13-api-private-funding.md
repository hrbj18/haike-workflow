# API 中转站：用户管理与私域充值

实现：`api-platform/`；本机服务 `http://127.0.0.1:17894/` 已更新。升级前通过 SQLite backup 保留原数据库私有快照，新增表不改原账户、会话、余额或既有账单。测试没有向真实账户充值或调用付费供应商。

## 业务闭环

用户自行注册，或由管理员开户。线下私域付款时提供注册邮箱；管理员核实收款后选择手动入账，或者发放绑定用户的兑换码。手动入账立即增加余额；签发兑换码只登记收款，用户预览并确认兑换成功后才到账。充值 100 元到账 100 元；模型调用按成本 × 1.5 结算，充值不再次加价，也不计入模型消费。

新页面填写收款渠道、交易凭证、备注并确认收款，再显示二次核对。收款凭证在手动充值和发码之间共同去重；幂等重试不会重复加余额或签发新码。兑换码原子领取、可绑定用户、有有效期，已使用码不能作废回扣。丢失明文时可重新签发未使用、未作废、未过期的码，旧码立即失效，金额、绑定用户、有效期及原收款凭证保留，不登记第二笔收款。签发明文仅展示一次，后续不回显。

旧接口兼容只带 note/batch 的请求；未提供 payment_ref 的请求不参与跨请求凭证去重。用户只能查看本人的已到账明细，内部收款单号和备注仅后台可见。管理员充值记录区分收款登记与余额到账，可导出 CSV；每个列表最多 500 条。

## 登录与用户管理

注册确认密码、密码可见切换、忘记密码联系入口、自助修改密码；管理员可开户、搜索、停启用普通用户、核实私域身份后重置临时密码。管理员开户及重置后的首次登录必须改密，未改前不能申请 Key、充值或调用 API。自助改密撤销其他登录会话，当前浏览器更新会话，API Key 保留。

停用撤销会话并暂停新 API 调用；旧任务按原计费继续结算，余额/历史记录保留；启用后原 Key 恢复，浏览器需重新登录。管理员账户不能通过普通用户管理操作被停用/重置。私域联系方式与充值说明在管理员「用户与充值」底部设置，未设置时提示通过原渠道联系。
