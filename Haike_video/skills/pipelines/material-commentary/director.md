# 素材解说导演（自由编排与精剪 V2）

用于用户要求制作或返工素材解说视频，包括电影、直播切片、产品演示、现场互动。运行清单为 [material-commentary.yaml](../../../pipeline_defs/material-commentary.yaml)，入口为工作台 `/material-commentary` 和 [素材解说 CLI](../../../scripts/material_commentary_cli.py)。执行细节及恢复点见 [素材解说视频 runbook](../../../../Haike-Videohub/agent-runbooks/素材解说视频.md)，字段合同见 [MATERIAL_COMMENTARY_V1.md](../../../docs/MATERIAL_COMMENTARY_V1.md)。

这是一条素材先行的生产流程。当前 agent 或人负责观察、理解和叙事判断；程序负责证据身份、源区间、音轨时钟、版本、缓存、队列及技术检查。`content_kind` 是描述性标签，不选择固定故事框架。

## 1. 确认本次输入

读取用户目标、选定素材、现有草稿和配音。通过 `list`、`brief`、`versions` 核对同类项目及队列，已有结果优先复用。冻结画幅、配音来源及音色、音乐选择、费用边界和待审交付要求。创建项目后保留 `artifacts/commentary-workflow.json`，正式合成使用本地 FFmpeg。

完成判据：本次项目可识别，素材来源可追溯，制作范围与声音方案明确；已经获得的生产授权直接沿用。缺失的付费供应商或音色选择只阻断相关付费步骤，继续可独立完成的本地取证。

## 2. 从素材建立观察

先按 [视频快速理解与分层分析](../../../../Haike-Videohub/agent-runbooks/视频快速理解与分层分析.md) 概览。电影、长直播先定位章节、人物、事件和已有转写，再对采用的窗口精查；本流程单次精查不超过 120 秒。

每个候选窗口通过 `evidence` 生成对应实际裁切的多宫格及可播放片段。实际查看后用 `review` 保存：可见事件 `observation`、前后文 `context`、听辨台词 `transcript`、未知项 `unknowns`、原字幕与原配乐状态。只有确实回听才能填 `audio_reviewed=true`。抽帧、转写和连续播放分别说明它们能支持的判断。

- 电影：核对人物关系、场景顺序及因果；倒叙须让观众辨认时间变化。未知身份或动机保留为未知。
- 直播：保留问题、回答、限定条件和反应的对应关系；判断一句话之前看足上下文。
- 演示与现场：确认动作是否完整、结果是否实际出现；台词、现场反应和画面各自引用证据。

完成判据：拟采用镜头均有可用性确认和合法源区间，关键结论有证据；证据不足的部分已补看、删去或明确限定。素材热度、文件名及自动分数不能替代这些观察。

## 3. 由观察决定叙事

读取 `brief` 中的全部相关观察，再填写 `intent` 和 `structure`。自由组织段落：可顺叙、倒叙、对照、问答、按问题解释或由原声主导；段落数、镜头数和长短取决于素材。每段写 `purpose` 和 `basis`，后者说明所用证据及编排理由。

先确定值得讲的内容，再写旁白。可以只取一个完整问答，也可以跨多个素材说明一个问题。无需凑开场、正文、结尾；无需凑三镜头或 30—60 秒。当前实现的段落上限和一小时输出上限只是资源边界。

新精剪任务使用字段合同中的 `editorial.version=2`：先声明候选集合，逐项记录采用证据、范围排除或待处理；由观察形成前因、动作、结果和原声价值的事件卡，口吻随素材。段落绑定事件，实际语音字幕逐句关联镜头及依据。用 `editorial` 检查覆盖与重复区间，完整问答和情绪长镜按价值保留，有意回调填写理由。返工时保留基线冻结签名，用 `compare` 对照实际切点和原声占比。

完成判据：每段有明确作用、已确认镜头及编排依据；全文事实和时序与证据一致，未知项未变成断言。

## 4. 配音、原声与字幕

每段选择 `narration`（旁白）、`original`（原声）或 `mixed`（两者混合）。旁白段先导入匹配文案的音轨，或用配音中心已有音色报价并按授权冻结后生成。相同文案与配置复用已登记配音；更换镜头或顺序无需重新付费。

旁白和混合段以实际 PCM 音轨样本数决定时长，再匹配足量已确认画面。原声段跟随镜头源时长。预检返回 `needs_material` 时补镜头或改短旁白，不循环画面或拉伸语音凑时长。

原声及已烧录字幕不会被自动移除。原字幕存在或未知时，新字幕需置顶并记录处理说明，或关闭新字幕；需要新裁切时重新取证。估时字幕只用于预览，保留待听辨提示；需准确字幕时提供逐句时间戳。新增音乐前核对源配乐，明确混合策略。

精剪 V2 导入真实逐字/逐词时间戳，或复用腾讯 TTS 已返回的对齐元数据；旁白两端空白按语音范围修剪，保持原语速。用独立 `source_audio` 设置原声提前进入或延后退出，核对整句与完整反应的切口；声画各自引用合法证据。新字幕和源烧录字幕分别检查，转写只辅助定位，听辨未完成保留警告。

完成判据：配音和文案逐段一致，原声与字幕处理明确，覆盖时长预检通过；未回听、估时字幕等提示保留到交付。

### 可选出镜的空间判断

启用自动出镜避让时，在冻结前按[自动布局合同](../../../docs/MATERIAL_COMMENTARY_V1.md#素材空间判断与自动布局)执行。复用已匹配配音的嘴型素材；先对实际采用的出镜源窗口运行 `layout-prepare`，用 `layout-task` 读回并查看全部图片。保护叙事相关脸部、关键动作、核心主体和原字幕的整个移动范围；坐标取自裁切源图，确认实际换镜才填 `cuts`。用 `layout-protection` 提交记录，再用当前草稿 `revision` 执行 `layout-apply`；已有完整匹配记录可直接复用。程序联合选择左上/右上和新增字幕位置，尊重手动锁定。缺失或不确定判断时隐藏出镜并保留声音，继续交付待审片；按返回任务/原因补查后重新应用。

完成判据：每个实际出镜时段均有匹配的空间判断或明确的隐藏原因；同一真实镜头内位置稳定，人物移动范围和原/新字幕已核对，锁定冲突已提示。查看代表帧及播放成功分别记录，不把约4FPS抽帧声明为逐帧语义检查。换位置或字幕无需重新生成配音与嘴型。

## 5. 冻结、排队与交付

使用读回的 `revision` 保存，预检通过后经工作台或 CLI `submit` 入统一队列。每次提交冻结源指纹、证据、镜头、音轨、字幕及格式，并登记逐镜头素材引用和使用台账。新版本只能使用未归档素材；历史冻结版本可以按同一指纹恢复归档或重定位后的原片。内容修改产生新版本；重复提交同一 `revision` 恢复原版本及已有段落缓存。有意更换字体内容时也先保存修改说明以产生新草稿版本。

结构/语义审查核对证据与叙事；视觉/输出审查查看代表帧并连续播放、回听字幕与切口。遵循项目最多两轮独立审查约定。输出 `completed`、`qa.status=passed` 只表示技术完成；`review_status=pending_review` 仍待人观看。

完成判据：目标页面可播放该版本，技术检查通过，观察和声音方面的未决项明确交付，旧版本仍可追溯。生产到待审为止；发布由另行授权的发布流程处理。
