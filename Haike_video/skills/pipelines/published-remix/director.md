# 已发布成片二剪 V1

这是 `/published-clips` 工作台专用流程；使用 `backlot/published_remix.py` 的草稿与冻结版本合同，通过统一队列 `published_remix` 执行。不要另起生产线程，也不要套用通用口播脚本流水线。

## 方案与运行时

向用户说明本版本仅处理已有媒体的切割、顺序编排、缩放补边及原声音量。`render_runtime_selection` 固定为本地 FFmpeg，零外部调用；`render_runtime` 不走 Remotion 或 hyperframes。两者适合后续新增图文动画，但本版没有动画场景合同，不能把它们描述为已接通的可选引擎。

选材前明确素材与目标结构，避免只改变包装而不改变叙事。自动候选保留待核对标记；歌舞语义不能由运动/音量指标推定。入出点、片段音频和用途在草稿中保存，提交后冻结，后续修改生成新版本。

## 编排与合成

先读 `skills/core/ffmpeg.md` 与 `skills/creative/video-stitching.md`。工作流清单为项目 `artifacts/remix-workflow.json`；草稿在本地索引数据库，渲染请求及结果在 `artifacts/remix/<签名前24位>/`，完整签名保留在清单/数据库中。

720×1280 / 30FPS；每段保留原声、压低12dB或静音；无音轨补静音。既有烧录字幕和混入原声的配乐不自动消失。队列负责本地串行执行、幂等和恢复。只使用经登记且指纹匹配的素材；不能接受任意路径。

合成后检查编解码、帧数、音视频时长及完整解码。检查通过只表示技术可审；输出仍待人工观看，不自动发布，不承诺平台风控结果。详细验收见 `docs/development/2026-09-30-成片二剪工作台V1-单次开发指导文档.md`。
