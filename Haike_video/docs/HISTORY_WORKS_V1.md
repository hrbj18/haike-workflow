## 作品与版本

层级是项目 → 独立作品 → 成片版本。`project_id + work_key` 决定作品身份；完整 SHA256 决定版本内容。同内容不同路径属于同版，最新修改时间不决定最终版。

指定任务首先登记候选，再根据用户明确选择确认最终版。自动任务只有有效视频和明确 QA 通过依据才自动确认；资料准备失败保留成片，并留下补齐资料的下一步。自动任务不会自行发表。

新增版本保留旧版本和发布记录。发布记录绑定当时版本与资料修订；切换最终版不改写历史。日期筛选优先使用项目记录中的带时区创建日期；缺少可靠项目日期时使用登记日期。版本列表显示登记时间。

网页可搜索、筛选、查看视频、确认候选、编辑发布资料、选择目标账号、安排北京时间排期及导出接手摘要。标题、详情、话题和封面记录独立修订；指定任务必须记录本次用户要求。

第一版封面接口使用项目内现有图片路径，3:4 校验由既有发布适配器执行。自动任务用已完成视频截取 720×960 封面，标题和详情来自项目资料或 `project.json.work_policy`；此过程不调用付费生成服务。若需专门设计的 AI 封面，由制作端按用户要求提供图片及对应来源证据。

## Agent 接手

工作目录为 Haike_video。下面两条命令只读：

```powershell
.venv\Scripts\python.exe scripts/work_catalog_cli.py list
.venv\Scripts\python.exe scripts/work_catalog_cli.py handoff work-514b2224387d6d3330b87383
```

接手记录包含最终版哈希、可用路径、用户确认依据、版本历史、发布资料修订、目标、账号任务/核验状态、素材归属、归档状态和下一步。项目稿件及参数可用路径记在 `handoff`。`published_metadata` 是旧发表时的资料，不能当作新版已获批准的文案。

2026-10-09 起，公共 `handoff` 直接提供 `publish_handoff`：发布标题（区别于作品名称）、详情、话题、封面及来源证据路径、资料修订、已选目标和可选账号。读取时核对最终视频、封面、AI原图及证据的实际哈希和图片尺寸；不查询发布器、不创建任务、不从旧草案反向补值。`materials_ready=true` 只表示当前最终版的发布资料已准备，`ready_for_publication` 还要求目标、来源使用范围及具体公开授权均满足；未决项单独列在 `publication_blockers`，不能再报告为所有文案缺失。

兼容旧接手方式时运行 `.venv\Scripts\python.exe scripts/work_catalog_cli.py export-handoff <作品编号>`，刷新该项目 `artifacts/publishing/待发布交接.json` 和 `.md`；文件标明只读快照及作品库 revision。网页下载的是同一公共交接结构。候选账号只供选择，不自动成为本次目标；来源未知只允许离线 dry-run。授权说明如需入账，放在 `handoff.publication_authorization`，必须包括用户实际依据 `evidence`、`authorized: true`、确切 `version_id`、`material_revision` 及完整 `targets`；任何版本、文案或账号/排期变动会使旧授权说明不匹配。真实提交仍需执行者根据本次用户指令确认冻结计划。

YC V4 发布标题、详情、话题与独立 1080×1440 AI 封面已落库；用户已选三平台“檬檬和雅雅”账号并写入目标，离线 v2 包可读取。剩余的素材使用范围与公开发布授权分开记录；尚未真实上传或发表。项目 `artifacts/publishing/发布资料-v1.md` 为文案与封面说明，`交接验收-v1.json` 为本机验收证据。

导出的 JSON 是只读快照；真实更新经 API/CLI 完成。所有修改带当前 `revision`，过期修订会被拒绝，避免两个 agent 相互覆盖。数据库需用 SQLite backup 或停写后备份，不能复制一份旧快照再覆盖当前库。

`register` 的参数文件示例：

```json
{
  "project_id": "your-project",
  "path": "renders/final.mp4",
  "work_key": "short",
  "mode": "manual",
  "event_id": "render-job-stable-id",
  "summary": "独立短版，等待用户确认"
}
```

`change` 使用同一份规则，示例：

```json
{
  "action": "confirm",
  "revision": 1,
  "version_id": "v-实际版本编号",
  "evidence": "用户明确采用该版本的原话或确认记录路径"
}
```

不能因为用户要求管理作品，就推断其已授权发表或永久删除。取得具体操作授权后，执行下面的冻结计划流程。

## 发布与核验

1. 确认最终视频，准备标题、详情、话题、项目内封面，以及既有发布契约要求的来源资料。
2. 选择抖音/快手/视频号及具体账号；支持平台子集、同平台多账号。网页设置统一北京时间排期；API 可为各目标分别设置带时区的未来时间。
3. `preflight` 或网页“预览发布计划”冻结视频、封面哈希、资料修订、账号和时间，仅生成本地计划。
4. 确认具体计划后，网页“确认提交发布”或 CLI `publish <计划编号> --confirm` 才提交真实任务。CreatorHub 此时再次检查契约版本、账号平台及创作者登录、指定文件哈希。预约时间为空可能立即发表。
5. 查询/重试同一计划。提交意图先落账，网络调用使用稳定幂等键；响应丢失不得改键另发。
6. 网页刷新结果或 `sync <作品编号>` 读取任务结果。系统 `done` 和平台作品 `verified` 分开记录。
7. 完成实际平台作品核验，提供唯一作品编号、作品列表截图及视频/标题/封面匹配结果。核验转交 CreatorHub 的既有接口；作品模块只接受对应账号、平台、视频哈希及完整匹配依据。

空目标不代表全部已发布。旧发布账号不自动变成本轮目标；历史记录可以显示“已有发表”，但不能据此推断其他目标均完成或开放清理。

## 历史导入

网页“整理历史项目”，或 CLI `import-preview` 先生成持久计划；`import <计划编号>` 只导入依据充分的记录。

来源包括显式用户成片确认、自动任务完成/QC记录，以及 CreatorHub 历史发表记录。发布数据库用只读连接，仅读取白名单字段；路径对应但缺少匹配哈希的旧任务仍待确认。多个完成版本冲突时不按时间猜最终版，已有最终版也不会被旧证据自动替换。

网页可以勾选待确认候选并填写确认依据；同一作品一次只能选择一个最终版。独立长短片可用不同 `work_key` 登记。无视频/文件变化的候选不能导入。

本轮扫描 32 个项目、114 条候选记录；19 条有依据记录合并/导入为 9 条作品（含已确认 YC V4），其余 95 条保持待确认。另有原先登记的候选作品，未自动确认。扫描与导入报告保存在 `.backlot/history-works-development/`，不提交到 Git。

## 空间与归档

空间报告包含本作品已登记文件、项目内未归属的普通文件，以及显式登记的项目外专用产物；其他作品已登记文件单独统计。未登记的其他外部目录不会按名称猜归属。封面、稿件、参数、确认/发表/付费凭证与必要证据保留。

可通过网页空间报告勾选文件、填写任务/来源依据，将其登记为本作品专用；或 `change` 的 `asset` 动作登记具体绝对路径、`ownership: exclusive`、`ownership_evidence` 和 `kind`。允许根为本项目或仓库 `.backlot`；用户外部原片、数据库、配置和模型不能通过此接口作为媒体删除对象。生产端应在生成媒体后使用同一接口登记归属，避免事后猜测。

“本作品专用”不是共享检查的替代。公共素材库已登记的位置、其他项目引用、其他作品素材/版本/封面、归属未明文件都会被保护。目录联接和符号链接不跟随，硬链接的估算不会重复计为释放空间。

清理必须同时满足：当前最终版存在，已明确选择目标账号，每个目标当前版本都已发表并完成平台核验，没有排队/运行/状态不明的生产或发布任务。

批量选择作品 → 预览 → 核对逐文件保留/删除/跳过清单及预计空间 → 一次确认永久删除。CLI 为 `cleanup-preview --data 文件.json`，随后 `cleanup <计划编号> --data 摘要参数.json --confirm`；仅给作品编号不能执行删除。

执行会核对作品修订、文件身份/哈希、活动任务和引用；作品更新、生产入队与清理共享锁。每个文件先记删除意图，再执行并落账。中断或文件被占用时显示部分完成，可从“查看未完成清理”继续原计划，或结束计划保留剩余文件；不会重复累计已删空间。`cleanup-cancel` 不恢复已删除文件。

保留当前最终版及实际发表过的旧版，冗余副本仅在必要副本仍有效时删除。原发表记录保留原始路径与哈希；再次准备发布使用当前可用路径建立新包，不改写旧记录。

报告同时记录删除字节和磁盘空闲空间前后值；后者可能受到其他进程写盘影响，不保证等于逻辑字节。归档后只声明已登记专用素材已清理；共享及归属未明文件可能继续保留。完整工程返工需要重新准备已清理素材，参数记录不能代替原音频/视频。
