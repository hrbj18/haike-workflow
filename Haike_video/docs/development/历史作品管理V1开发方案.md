# 历史作品管理 V1 开发方案

日期：2026-10-08

状态：2026-10-08 已完成 V1 本地实现及历史记录导入；当前入口 14756，原工作台未重启。使用与实际验收范围见 [使用说明](../HISTORY_WORKS_V1.md) 和 [验收报告](历史作品管理V1验收报告.md)。下文保留开发基线与已确认要求；本轮未真实发表或删除用户素材。

适用仓库：Haike_video 为作品管理主体；creatorhub 承担既有发布执行和作品核验；Haike-Videohub 提供现行发布契约与操作入口。

## 1. 目标与第一期范围

用户希望管理已经完成的视频：找到确切的最终成片，换 Agent 继续修改，准备并交接发布资料，查看三平台各账号发布结果，发布完成后批量清理原素材并释放磁盘空间。

第一期按“项目 → 作品 → 成片版本”组织。一个项目可以制作多条独立作品，每条作品分别管理版本、发布资料、目标账号及归档状态。网页、Codex 和 WorkBuddy 在同一电脑上使用同一份持久记录；聊天记录和 Agent 私有记忆不作为唯一交接依据。

第一期包括：作品列表和详情、最终版确认、自动任务入库、指定任务人工确认、发布资料管理、网页及 Agent 发布/排期、发布结果核验、旧项目导入、专用文件占用统计和批量归档清理。

第一期不包括：未完成制作项目的完整任务管理、项目外独立视频导入、多电脑同步、多人权限体系、小红书、费用/流量分析、公共素材库垃圾回收。现有制作项目库、素材库及生产队列继续承担其原有职责。

“待确认导入”是历史数据整理区，不把其中的试片或证据不足的文件当作正式历史成片。

## 2. 已确认的产品决定

| 编号 | 决定 | 实现必须保持的含义 |
|---|---|---|
| D01 | 只管理已完成的视频 | 不因存在任意 MP4 就宣布作品完成。 |
| D02 | 优先覆盖最终版、续改、发布交接和发布追踪 | 一期不收缩为只有待发布清单。 |
| D03 | 网页与 Agent 共用记录 | 两种入口读写相同模型、遵循相同校验。 |
| D04 | 自动任务自动入库；指定任务人工确认 | 每日科技模板等自动任务按完成检查入库；复刻等指定任务在用户确认成片后入库。 |
| D05 | 一条独立作品一条记录 | 项目可含多个作品，作品可含多个版本；项目目录不是作品唯一边界。 |
| D06 | 第一阶段同机共享 | Codex、WorkBuddy 可通过公共 API/CLI 读取和更新；无需同步私有记忆。 |
| D07 | 返工保留旧版，新版确认后切换 | 已发布历史继续绑定原版本，不随当前最终版变化。 |
| D08 | 自动任务自动准备发布资料；指定任务人工指定 | 自动任务准备标题、详情、话题、封面；指定任务由用户给出要求或指令，再由 Codex 准备，不能擅自补成最终稿。 |
| D09 | 网页能提交发布和排期 | 提交前展示确切视频、文案、封面、目标账号和时间；保存资料不触发发表。 |
| D10 | 按证据导入已有项目 | 明确确认/发布证据的作品自动导入，其余待确认；不能默认最新文件为最终版。 |
| D11 | 清理后保留成片和少量记录 | 保留封面、稿件、参数、审核/发布记录及必要证据；删除专用原素材、音频、数字人中间片、废弃预览和缓存。 |
| D12 | 全部目标平台及账号发布并核验后才可清理 | 发布任务 done 不等于平台作品已经核验；本期不设置任意一平台成功即可清理的捷径。 |
| D13 | 批量预览，一次确认后删除 | 展示保留文件、删除文件、跳过原因和预计释放空间；真正删除，不能仅移动到同盘回收站。 |
| D14 | 保留当前最终成片及实际发布过的版本 | 未采用预览可以清理；相同内容的重复副本按引用关系保留必要位置或统一归档副本。 |
| D15 | 只清理作品专用文件 | 公共素材库、其他项目使用的文件及归属不明文件不纳入删除。项目外已登记的专用产物可以纳入。 |
| D16 | 抖音、快手、视频号 | 目标、进度、任务和核验均按“平台＋账号”记录。 |

用户选择了 D12 的全部目标核验条件，未选择单独“手工标记即可绕过核验”的清理模式。将来增加此模式须另行确定需求。

## 4. 用户使用流程

### 4.1 自动任务与指定任务

自动任务完成渲染及适用质量检查后，以稳定任务输出编号登记版本，自动确认作品成片并进入列表；生成失败、QA 失败、事实待核验等不满足既有完成条件的结果继续留在原生产入口。系统不得伪造人工审核事件：自动确认记录采用 `automatic` 模式并保存任务及策略依据。

自动任务同时按已配置的文案/封面生成工具和预算准备发布资料。资料失败不抹掉有效成片，作品显示缺项并可继续补齐。自动入库和自动准备资料均不构成自动公开发布授权。

指定任务先保留可观看候选。用户在网页确认，或在 Agent 对话中明确指定“这版作为成片”后，针对确切版本及哈希记录确认并入库。发布资料按用户指令准备；未提供要求时明确显示待指定，不伪造已审核文案。

### 4.2 返工与接手

用户从作品详情发起“继续修改”，或让 Agent 接手指定作品。接手方先读取最终版本、候选版本、已确认要求、制作参数、素材可用性、付费产物引用、发布情况和下一步。

返工通过原生产工作台和统一生产队列执行，产出新版本并说明修改内容。仅本地可完成的改动复用已有产物；改变稿件、音色或数字人时沿用现行供应商及费用规则。此功能不引入另一套制片引擎。

指定任务新版仍需用户确认；自动任务新版按其自动完成策略确认。切换最终版仅改变今后默认使用的版本，不修改旧发布包、旧作品记录或自动重发。旧版在任一目标账号上已发过，就属于归档保护集合。

已清理原素材的作品显示“原素材已清理，完整工程返工需要重新准备素材”。仍可播放、再次发布、修改发布资料或基于成片二剪；不能保证按原工程只改一行烧入字幕或重混原人声。

### 4.3 发布与核验

作品详情选择目标平台、账号和立即发布/预约时间，展示最终媒体、各账号文案、封面、当前资料修订号以及缺项。网页和 Agent 均先走同一预检，再提交同一发布服务；资料保存和预检不调用真实发布创建入口。

正式提交冻结成片版本、封面及文案修订，并持久保存幂等编号。超时先查原提交，不创建新编号碰运气。失败平台或账号单独处理，已成功项不重发；发布中和结果不明项保持原任务查询。

分别展示“发布系统已完成”和“实际平台作品已核验”。核验保存目标作品 ID、链接（可取得时）、时间、证据和视频/标题/封面匹配结果。全部目标账号均完成且核验后，当前发布计划才能计为完成。

### 4.4 历史导入

只读扫描已登记项目、版本登记、明确确认记录、发布包和回执。产生可预览导入计划，包含拟建作品、成片依据、历史发布关联及冲突。

有明确完成证据可自动入库，但历史版本绑定仍须有内容证据。只有目录名、最新 mtime、同名文件、发布任务 done 或同一路径时，不推断确切最终版、当时内容或平台核验结果；无法确定的部分单独待确认。

多条作品关系不明时不按文件数量机械拆分；保留候选组、来源证据及待整理原因，支持用户/Agent 指定归属。重复扫描使用相同导入身份，不重复建作品。旧项目只做增量登记，不原地改写历史文件。

### 4.5 发布后批量归档

用户或 Agent 勾选可清理作品，生成一份清理计划。页面显示当前占用、保留内容、删除内容、保护/跳过原因、独占空间预计释放量及清理后的可修改能力。

确认绑定确切计划和版本。执行前重验发布、引用、文件和计划状态；符合条件的专用文件永久删除，成功后记录实际结果。归档不删除作品记录，不重新发布，也不清理公共素材库。

## 5. 页面设计要求

新增“作品管理”导航，保留现有项目库作为制作项目入口。布局和组件复用现有工作台风格。

### 5.1 列表

默认按入库时间倒序，可搜索作品名、所属项目、作品编号；按日期、任务类型、平台/账号、发布情况和素材保留状态筛选。提供全部、待确认、资料待补、待发布、部分已发布、已发布、可清理、已归档等视图。这些是条件视图，可重叠，不建一个承载所有含义的大状态枚举。

每行展示缩略图、作品名、所属项目、入库日期、最终版本、资料完整性、目标账号进度、异常原因和磁盘占用。点击进入详情；可批量选择符合条件的作品生成清理预览。已归档作品仍能搜索和播放。

### 5.2 详情

| 区域 | 必须展示的内容和操作 |
|---|---|
| 成片 | 播放当前最终版、确认模式和时间、文件校验状态；打开原制作项目。 |
| 版本 | 候选/最终/历史已发标记，生成来源及修改说明；确认新版；已清理版本保留说明。 |
| 发布资料 | 标题、详情、话题、封面及来源；自动生成/人工指定来源；编辑、预览、保存修订和缺项。 |
| 发布 | 按账号逐项显示版本、资料修订、排期、任务状态和平台核验；选择目标、提交、查询及核验。 |
| Agent 接手 | 已确认要求、冻结参数、素材/音频是否可用、供应商产物引用和下一步；复制接手指令。 |
| 空间与归档 | 总量分类、专用/共享/不明文件、可释放空间、清理计划、结果和能力变化。 |

作品资料区给出实际错误及下一步，如“封面待准备”“发布系统完成，作品待核验”“有其他作品使用，保留”。不要求用户理解 API 字段名才能操作。

## 6. 建议数据模型

本节是开发建议，不是已存在的数据格式。建议以 SQLite 事务作为统一写入真值，沿用本机持久化和 revision/CAS 习惯；导出可读 JSON/Markdown 交接快照。实现时先确定 schema，再同步网页、API、CLI 和迁移适配器，不能让 JSON、数据库和私有记忆分别成为可独立编辑的真值。

| 实体 | 关键字段及约束 |
|---|---|
| Work | work_id、project_id、名称、任务类别、入库策略、入库依据、时间、current_final_version_id、revision；一个项目可有多条。 |
| Version | version_id、work_id、完整 SHA-256、媒体信息、生成任务、修改说明、文件位置、可用状态；同一内容可有多个位置。 |
| Confirmation | version_id、SHA-256、人工/自动模式、操作者或策略、依据、时间和结论；不可因新版自动覆盖旧确认。 |
| PublicationMaterialRevision | work_id、revision、适用版本、各平台或账号文案、封面/证据哈希、来源、缺项、确认依据；已提交修订不可原地改。 |
| PublishPlan | plan_id、work_id、version_id、material_revision_id、revision、冻结目标集合、排期；目标以平台＋账号为单位。 |
| PublishAttempt | 目标、包 ID/修订、幂等键、任务 ID、系统状态、来源服务和回执；重试关联原意图。 |
| Acceptance | 平台作品 ID、核验结果、证据、核验时间、核验操作者；与系统 done 分离。 |
| AssetOwnership | 具体文件位置、文件身份、专用/共享/不明、所属作品、当前引用、来源、托管根目录及生产任务；哈希相同不等于路径归属相同。 |
| Handoff | 已确认要求、参数快照、稿件、素材可用性、原生产入口、产物引用及下一步；包含各真值记录的修订号。 |
| CleanupPlan/Result | 所选作品、所用修订、保护集、删除集、跳过原因、预计空间、文件身份、计划摘要、确认记录、逐文件结果及实际释放量。 |

记录 Agent 来源、动作时间和变更依据；凭据、Cookie、API Key 不进入作品记录或交接导出。时间持久化采用带时区时间，网页展示北京时间；预约提交按现有发布器契约转换并读回。

内容哈希用于识别成片内容和防止同路径替换。版本身份仍关联作品及产生原因，不能将两个不同作品仅因哈希相同自动合并。相同内容复制到其他路径也不生成虚假的新修改版本。

### 6.1 相互独立的状态

| 维度 | 说明 |
|---|---|
| 入库/确认 | 历史待确认、人工确认、自动策略确认；保存依据，不把自动确认标成用户审核。 |
| 发布资料 | 未指定、缺项、可预检、已修订；资料修改使旧预检失效，已发修订继续可读。 |
| 发布目标 | 计划/待提交、已排期、发布中、系统完成、失败、结果不明、取消；进度按账号。 |
| 平台核验 | 未核验、需处理、已核验；旧历史只有路径时保留版本待核对。 |
| 素材可用性 | 完整、部分缺失、原素材已清理；不把自然缺失当已成功归档。 |
| 清理执行 | 已计划、已确认、执行中、完成、部分完成/失败、计划失效；重新查询可恢复原结果。 |

“可清理”是实时计算条件，不是永久写死的标签。没有选定目标、存在未完成或未核验目标、仍有活动发布/生成/返工任务、媒体保护副本无效、归属/引用无法证明时，不得进入有效执行计划。修改目标或版本后，旧计划失效；不能通过删掉未完成目标偷偷满足条件。

## 7. Agent 公共接口与交接契约

建议新增统一作品 API 及本地 CLI，提供列表/详情、导入预览、最终版确认、资料修订、发布预检/提交/查询、平台核验、空间报告、清理计划/执行/结果。具体命名在实现前统一确定；本文件列出的能力不是当前可调用接口。

所有状态修改走相同服务方法，带期望 revision；两个 Agent 同时编辑时返回明确冲突，不能后写者覆盖前写者。发布执行和清理执行需要互斥：有未完成提交、文件上传或返工任务时不能删除输入；清理期间阻止新任务取得即将删除的素材引用。

同机 WorkBuddy 的接手指令应包含 work_id、服务/CLI 入口及动作目标，而不是依赖固定会话 ID。接手摘要至少能回答：哪版用于后续操作、哪些要求已经确认、哪些东西可以复用、哪些资料还缺、哪些账号已发、当前允许的下一步是什么。

可导出人可读的接手摘要和机器可读快照；写操作仍回到公共入口。源服务离线时快照注明生成时间和 revision，不能凭过期快照提交发布或清理。重启后身份、确认、回执和执行结果可恢复。

## 8. 发布适配要求

复用现有指定封面 v2 合同、持久回执、CreatorHub 能力检测和三平台发布器，不重新实现浏览器上传。

1. 扩展作品侧发布包组装，以支持三平台内任意选定子集和同平台多账号；一个明确媒体/封面版本共用稳定包身份。检查需要在当前 build_package 上改造还是增加兼容组装层，保留已有调用者。
2. 当前 POST /api/publish 可能立即执行。作品资料与本地计划在 Haike 保存；用户实际提交时才调用发布入口。未实施的 CreatorHub 真草稿 API 不能假定存在，也不能用旧 POST 冒充保存草稿。
3. 提交冻结版本、封面、文案和目标修订。文案或封面变更创建新资料修订，不能借换编号绕过已提交任务去重；重复发布同视频至同账号先核对既有任务和作品。
4. 自动任务可以自动准备资料，但来源使用范围、目标账号、封面或必要证据不满足现行合同，仍是明确阻断项。不得把自动入库当作 unknown 来源变成 confirmed 的依据。
5. 新增同步/读取核验结果的适配，将系统完成与平台验证准确映射。需要 creatorhub 增加字段或接口时明确能力版本和兼容处理；服务缺失时显示未连接，不声称成功。
6. 排期记录同时保留用户看到的北京时间和提交后的标准时间。网页/Agent 查询同一任务，不各自建立调度器或重复派单。

## 9. 磁盘占用与清理合同

### 9.1 文件分类和保护集

| 类别 | 默认处理 |
|---|---|
| 当前最终成片、实际发布过的成片内容 | 保留可播放且哈希可验证的必要副本；未知提交结果相关版本也先保护。 |
| 封面、稿件、参数、确认事件、文案修订、发布包和回执 | 保留。 |
| 必需的封面来源/生成证据、素材使用范围、实际作品核验凭证、付费任务元数据 | 保留足以验证和审计的证据，不能删掉后伪造通过。 |
| 专用原素材、配音/混音、数字人中间视频、废弃预览、暂存缓存 | 条件满足且确属作品专用时列入删除计划。 |
| 公共素材、音色配置、模板、模型、其他作品引用文件 | 保留，不属于本期清理范围。 |
| 归属不明、未登记的外部来源、无法验证共享关系的文件 | 跳过并显示原因，支持先整理归属；不以同目录为删除依据。 |

一项目含多个作品时，不能用整项目清空实现某条作品归档。专用判定必须有生产登记/托管归属依据，并结合其他作品、活动任务和共享素材引用核对。共享库无引用结果只作为一项信息，不能作为独占证明。

项目外产物需登记具体文件、所属作品、允许托管根目录及来源任务，再纳入占用报告和删除白名单。例如 YC 的音频和中间视频在 `.backlot/video-understanding/` 下，需要补登记专用文件；不能递归删除整个复刻批次，因为同批次还有其他视频。用户提供的外部原片默认保留，只有明确纳入作品专用托管并列入确认计划的文件才可清理。

### 9.2 清理执行协议

1. **计划**：根据所选作品的确切 revision、版本、发布核验、引用和活动任务生成逐文件计划。记录规范化绝对路径、内容/文件身份、大小及保护原因；保存计划摘要。
2. **预览**：显示独占候选删除量、共享/不明保留量和成片保护集。相同路径去重；硬链接、符号链接和同内容不同副本分别识别，不能把逻辑大小直接当作实际释放量。
3. **确认**：一次确认绑定同一批计划摘要。API/CLI 也遵循此协议，不能用仅给 work_id 的调用直接删除。
4. **重验**：取得对应资源锁，确认版本/目标/计划未变化、保护副本仍可解码且哈希匹配、活动任务已结束、引用未增加。文件被替换、路径离开托管边界或出现 junction/symlink 时，不跟随链接扩大删除范围。
5. **执行**：仅删除计划明确列出的普通文件，按原执行身份逐文件落账。Windows 使用同一原生文件操作体系并校验最终绝对路径，不构造跨 shell 字符串删除命令，不对推算目录直接递归清空。
6. **结果**：保存已删、跳过、失败及错误原因。中断后查询/恢复同一执行；文件已删除时识别已有结果，不能重复计算空间。尚未完成的归档显示部分完成。
7. **空间回读**：报告实际删除字节及磁盘空间变化（可能受并行磁盘活动影响）；只有实际删除才计为释放，移入同盘回收站不计。

本期是人工确认后的永久删除，不是自动延时清理。删除后的原素材无法由系统凭空恢复；保存制作参数只能帮助重建，不代表仍具备原工程编辑能力。归档后，历史资产引用保留“已清理”的墓碑状态，不删除来源链或让素材解析器误报完整可用。

内容去重不能跨作品擅自搬移公共文件。若要删除受保护成片的冗余路径，先建立并校验归档保留副本及版本位置映射；旧发布包是不可变历史记录，不能原地重写它来适配新路径。后续再次发布从当前可用位置建立合法新包修订，原记录保留当时路径和哈希。旧任务仍在执行、预约或状态不明时，原上传路径必须保留。

## 10. 开发模块与建议实施顺序

模块名为建议，开发时结合现有职责细化；不得将全部逻辑继续堆入 server.py 或 workbench.py。

| 阶段 | 交付 | 涉及入口与完成门槛 |
|---|---|---|
| T0 基线和合同 | schema、状态转换、旧数据兼容、隔离夹具及基线清单 | 记录相关源码差异；开发/测试不使用真实发布引擎、付费接口或正式删除对象。 |
| T1 作品与版本 | Work/Version/Confirmation 持久化、API/CLI、自动/人工完成接线 | 建议拆 work_catalog/work_versions；完整哈希、幂等登记、最终版切换、并发和重启读回通过。 |
| T2 页面与导入 | 作品列表/详情、原项目导航、旧数据导入预览及确认 | 复用项目库组件，增作品页面；不确定数据可见、重复导入不增条、旧入口仍可读。 |
| T3 资料与接手 | 资料修订、自动准备/人工指定接线、接手摘要及快照 | 建议 work_handoff/work_materials；换 Agent 可读确切版本和已确认要求，缺项不伪造。 |
| T4 发布与核验 | 网页/CLI 发布和排期、目标子集/多账号、回执/核验同步 | 接 publish_package/adapter/CreatorHub；未提交零发布调用，重复请求单任务、账号进度准确。 |
| T5 空间与清理预览 | 专用文件登记、空间分类、保护集及批量计划 | 建议 work_storage/work_cleanup；先开放报告和预览，真实执行仍关闭；隔离夹具覆盖共享和外部边界。 |
| T6 清理执行与集成 | 一次确认、锁、逐文件删除/恢复、归档展示 | 仅在临时目录进行破坏性测试；保留成片和证据、空间真实减少、重新接手能力准确。 |
| T7 文档与验收 | 接手说明、迁移报告、验收矩阵、最小 handoff 更新 | 同机 Codex/WorkBuddy 读写演示，实际验证和未验证项分列。 |

T1 → T2/T3 → T4 → T5 → T6 为主要依赖顺序。空间归属合同在 T0 定义，新产物从 T1 接入时即登记，避免等到清理时再猜归属。可分阶段交付页面，但整体验收必须覆盖用户确认的全部范围。

自动任务适配以实际生产入口的稳定任务 ID/输出 ID 为依据，不能根据名称包含“每日”来猜自动模式；每种接入流水线提供明确模式和完成事件。指定任务可通过网页确认，也可由 Agent 将用户明确确认写入同一公共入口。

## 11. 验收矩阵

| 编号 | 场景 | 必须达到的结果 |
|---|---|---|
| AC01 | 自动任务有效完成、完成事件重复、生成/QA 失败 | 有效结果自动入库且只建一次；失败不入正式作品。 |
| AC02 | 指定任务渲染多个版本，用户确认旧版 | 未确认候选不作为成片；确认确切旧版后入库，最新文件不能覆盖。 |
| AC03 | 一个项目含长版和短版作品 | 分别管理版本、资料及目标；一条归档不破坏另一条。 |
| AC04 | V4 已发，生成 V5、随后确认 V6 | 新版候选独立；确认切换后旧发布仍指 V4，保护 V4 和当前 V6。 |
| AC05 | 自动准备资料失败、指定任务未给资料要求 | 有效成片保留，缺项准确；指定任务不能被默认自动补成最终稿。 |
| AC06 | Codex 写入、网页编辑、WorkBuddy 接手、并发写入 | 状态一致；接手不依赖原聊天；冲突不覆盖；重启后可读。 |
| AC07 | 资料保存、预检、正确提交、重放、请求超时 | 前两者零平台发布请求；提交冻结正确版本；重复/超时只有原任务。 |
| AC08 | 同平台两个账号，另一个平台失败/待核验 | 按账号计数，分别显示系统及核验状态；无假“全部已发”。 |
| AC09 | 三平台子集发布、预约时间跨北京时间日期 | 不强制生成未选平台任务；排期读回与用户确认时间一致。 |
| AC10 | 旧项目有明确确认、只有最新 mtime、只有历史路径 | 证据充分导入；不足部分待确认；不伪造旧哈希绑定和核验结果。 |
| AC11 | 目标全部核验、目标为空、仍在发布/排期/返工 | 仅第一种且无活动任务时进入有效清理计划。 |
| AC12 | 批量清理，当前版/旧已发版本/封面/证据/专用音频并存 | 保护集合全部存活，专用候选删除；页面保留记录、正确显示素材已清理。 |
| AC13 | 共享素材、其他作品引用、未登记外部原片 | 全部跳过且有原因；公共素材和其他作品不受影响。 |
| AC14 | 项目外已登记专用产物，同一批次目录内有其他作品 | 只删除计划文件；不递归删除批次；报告覆盖专用项目外占用。 |
| AC15 | 预览后新增引用/改版本/替换文件/junction 指向外部 | 旧计划失效或明确跳过，边界外文件存活。 |
| AC16 | 清理中断、部分文件锁定、重复执行同一请求 | 逐文件结果可恢复；无整项目假成功、无重复释放量。 |
| AC17 | 同内容重复副本/硬链接、同盘回收站 | 保护必要副本；预计/实际空间不重复计量，回收站移动不报释放。 |
| AC18 | 归档后播放、查发布历史、再次准备发布、请求精确返工 | 成片及记录可用；新包合法；返工能力提示准确，不引用已删音频做完整工程。 |
| AC19 | 外部服务离线/版本能力不符/损坏记录 | 明确未连接或待修复，不假成功、不覆盖坏数据、不降级触发意外发布。 |

验证用临时项目、短小可播放媒体、临时 SQLite、假供应商和假发布器。清理测试目录必须明确位于隔离临时根下，真实用户素材、正式项目、发布数据库均不作为破坏性测试对象。

自动化测试需要核对持久化状态、服务重启读回、外部调用次数、文件存活及删除量；UI 验证覆盖筛选、版本确认、账号进度、预览和单次清理确认。实际平台发布与实际 WorkBuddy 接手验证单独记录；没有执行就标未验证，不用离线测试冒充。

## 12. 开发交付与启动检查

交付包含正式模型/API/CLI、作品管理页面、完成事件适配、资料及发布接线、历史导入工具、专用文件归属台账、清理预览与执行器、兼容说明、接手指南和按 AC 编号记录的验收报告。

实施前先读根入口、当前 handoff 和相关专项合同；检查本机源码与此方案的差异，保留其他任务的未提交变更。对相关持久数据做可恢复备份，在隔离副本验证迁移；不借开发测试提交真实平台或重新生成付费产物。

本方案涉及的新名称和接口均需落地后才能写入可执行 runbook。正式知识库默认只提修订建议；正式手册修改遵守其维护委托及证据要求。
