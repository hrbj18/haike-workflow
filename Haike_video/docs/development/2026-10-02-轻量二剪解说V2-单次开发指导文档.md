# 轻量二剪解说 V2 · 单次开发指导文档

日期：2026-10-02。状态：方案已编写，功能开发未启动。2026-10-03 用户调整顺序：先由 Codex 完成真实成片并检查效果，再决定能力模板化范围。本文件作为后续工程候选方案，不是当前执行计划；ds4.1 验收也不作为本轮实片制作的前置条件。

## 授权、现状与本次目标

用户授权先制定任务和验收标准，再自主实施、测试和修复。目标承接「规划素材二次混剪流程」：用本地或 CopySkill 已登记素材，通过新的解说及现场原声重新组织主题视频，复杂媒体处理由程序完成，生产模型只提供主题、短文案和有限候选 ID。

已有 V1 支持成片索引、选材篮、CAS 草稿、冻结请求及统一队列；共享素材库已接图文模板。两者尚未接通；二剪执行器只有源音轨。不能用成功拼接替代解说、内容或模型生产验收。

本次交付 **V2 完整工程闭环**：共享素材秒段 → 解说/原声段落 → 实际音频时钟 → 字幕/可选音乐 → 冻结请求 → 队列待审预览 → 局部修改和缓存复用。提供页面和单一 JSON CLI，不要求模型手工拼 FFmpeg。真实验收使用独立项目，不修改正在另一个聊天制作的机器人视频、原素材或旧成品。

本轮内容识别沿用证据确认，保留未知和待审；不声称自动歌舞分类已通过。电影/两小时直播分析、发布、数字人和复杂转场留在后续。ds4.1 真实验收独立记录：若无可调用入口，交付可复现的任务/指标入口并明确待实测，不能用模拟模型替代真实模型成功率。

## 前期准备与实现决策

1. 阅读入口、交接、二剪/素材库合同和 FFmpeg/拼接技能；核对脏工作树、队列、另一个聊天进度。只修改本轮相关文件，不重启或争抢现有生产服务。
2. V1 默认创建/保存/渲染行为保持兼容；V2 明确标识 `published-remix-v2`，仍使用同一草稿表、revision、冻结目录和 `published_remix` 队列类型。新增模块隔离数据合同和执行器，避免把通用工作台推倒重写。
3. V2 段落分 `narration` / `original`。每段拥有稳定 ID、叙事用途、文案及镜头列表。镜头引用共享库 `media_id` 与可选 `clip_id`；保留源秒段、裁切、内容 SHA、确认及来源。自动候选采用必须经确认；手工选段可明确标记待审，不自动伪造确认。跨画幅等比留边。
4. 解说音频通过上传/CLI 导入或已有配音中心音色生成；保存文本、音色/模型参数、内容 SHA 与实际 PCM 样本数。修改文案不能继续误用旧配音。TTS 操作按文本和冻结音色形成稳定身份；完成音频复用，提交不明停止自动再收费，不静默换供应商。实际云端调用需明确供应商/模型和费用边界，本轮优先复用已有音轨完成真实样片。
5. 解说音轨为段落主时钟，按 30FPS 向上对齐且不裁掉语音。镜头按可用时长顺序截取覆盖，素材不足返回具体缺口；不默认拉伸语音、循环视频或长时间定格。现场原声段沿原片时长。解说段默认源静音，也可压低；现场原声保留/压低/静音。音乐为独立全片轨，解说和现场原声下压低。
6. 字幕用显式时间戳或短句按长度分配的估计时间；后者明确标记估计，不宣称词级对齐。只支持有限纯文本及固定安全区样式，拒绝重叠/越界，输出 SRT 并烧录同一套字幕。处理 ASS/过滤器字符转义，字幕保持在竖屏安全区域。
7. 所有输入在提交和执行时检查；冻结请求记录确定的素材位置与哈希、音频和时间轴，避免后续草稿/全局设置变化影响旧版本。已处理段落按内容身份缓存，换一个镜头或一句解说仅重做该段，最终混音/编码可以重做。缓存命中也校验文件身份；半成品不作为成功输出。
8. 源音频、新解说及音乐汇成 PCM 后按项目响度偏好规范化；实际 AAC 输出再测响度、真峰值。技术通过仍是 `pending_review`。保留历史版本、失效原因和安全恢复点。

## 具体验收标准

### A. 数据、兼容与来源

- V1 专项全部通过，旧冻结请求仍可渲染/下载；V2 保存重开、顺序、入出点、裁切、文案/音轨/原声设置一致；过期 revision 返回409且不覆盖。
- 支持至少两份共享素材及三个段落（含新解说和现场原声），网络/本地来源可回溯。未知证据不被自动标确认；按确认区间采用时不可越过已核对范围或换裁切偷用旧证据。
- 无效 ID、任意路径、越界/NaN/布尔时间、重复段ID、跨项目音轨、文案与配音不符、源内容变化/丢失均阻断。原素材、旧成片、已完成付费音轨哈希不变。

### B. 音频、字幕与时间轴

- 解说时长来自实际音频样本，不做语速拉伸；源画面不足返回 `needs_material`，不能输出缺镜头的成功视频。总输出按整数帧计时，音画时长差和预期时长差均≤0.08秒。
- 原声保留/压低/静音可测；解说段不会默认叠加原博主口播；可选音乐在段落交界连续、在人声下压低。无需音乐也可完整生产。
- 字幕开始/结束与同一冻结时间轴一致，无跨段越界或重叠；有SRT可下载。估计字幕明确标示，中文安全区样张可读、不超出画面。
- H264/AAC、720×1280@30、yuv420p、48kHz；完整解码通过、帧数准确、切点没有程序新增空白。AAC成片响度误差≤1.5 LUFS、TP≤−1dBTP；失败不能标成功。

### C. 队列、恢复与局部修改

- 由既有统一队列执行；同冻结版本重复提交返回同任务，后续草稿变化不影响已提交版本。部分失败可从同版本恢复，完成音轨不重复合成。
- 一段修改后，其余段落缓存命中且缓存内容哈希不变；旧预览仍可播放。缓存损坏/输入变化不会被误认为命中。供应商受理不明保留账本且禁止自动重复提交。
- 浏览器播放与下载使用同一QA通过文件；失败版本不暴露半成品。状态始终显示待人工审核，发布不在执行器内。

### D. 真实生产与入口

- 独立项目产出30—60秒真实素材样片，含至少2个解说段和1个现场原声段。完整检查结构/事实依据及代表画面；现场原声回听若工具无法播放则明确标记待人工听辨，不冒充听验。
- 页面完成创建、选材、音轨、保存重开、提交、版本列表、预览和下载；CLI可以用同一份短JSON完成保存/预检/队列提交，不另写媒体脚本。模型最多看到12个候选、具体缺口和可执行下一步。
- 自动测试覆盖合同、API、CLI、字幕、真实编码、缓存与故障恢复；既有二剪、素材库及队列相关回归通过。JS语法、Python编译和交接审计通过。
- ds4.1验收记录模型入口、任务内容、真实调用/人工介入、耗时和费用。没有实际调用只记 `not_run`，不以JSON合同测试代替模型能力结论。
