# 单次开发指导文档：项目追溯与生产安全 V1

更新时间：2026-09-24
状态：开发前计划，功能尚未实施，验收结果尚未产生
任务编号：PROJECT-TRACE-SAFETY-V1
适用仓库：Haike_video、creatorhub、copy_skill 的素材目录生产字段；Haike-Videohub 仅提出契约与 runbook 修订清单

## 1. 本次要达成的结果

用户从项目库进入一条作品后，能够回答五个问题：素材来自哪里、何时采集；当前是哪一版成片；该版是否经过人工审核；计划发往哪些账号、实际发布到哪里；中途停止或返工时哪些云端结果已经付费且可以继续使用。发布入口和任务状态必须表达真实的系统行为。

本次交付拆为六个可验收成果：

1. Haike 的发布操作区分「保存草稿」和「确认提交发布」。草稿不会被发布引擎处理；提交使用持久幂等编号，回执明确显示进入发布队列。旧 CreatorHub 发布接口的语义、CLI 提示和契约与现行行为一致。
2. 统一生产队列的取消请求在阶段边界生效。已受理的供应商任务继续保存结果；完成产物不被最终取消标志误写成未完成。
3. 每个可交付成片有内容摘要、版本状态、明确的人工审核事件。平台发布记录绑定成片版本、平台及账号；发布系统回报完成与平台后台人工核验分开显示。
4. 项目素材可见来源发布日期、采集日期、导入日期和当前使用位置；未知日期明确为待确认。复用现有素材库的 SHA-256、来源及引用关系。
5. 提供原任务恢复和局部返工的只读决策说明及可执行入口。仅改字幕、画面或音乐时复用云端产物；真正需要新付费生成时列出变化与费用预估。
6. 形成项目级测试证据、数据迁移说明及知识库修订提案。正式跨仓 runbook 只在相应功能已落地并完成治理流程后更新。

用户可见的项目摘要建议采用固定结构：创建日期｜当前成片 Vn｜审核状态｜按目标平台和账号分别显示待发、发布中、已发、待核验、需处理。项目创建日期与素材日期各自独立。

- 工作区当前有多处未提交改动；开发前逐文件检查相关差异，记录各仓实际 HEAD、未提交文件及活跃任务。不得重置或顺带提交其他工作。
- 真实项目数据、队列库、CreatorHub 数据库和付费账本先做一致性备份；验证迁移使用隔离副本。密钥和登录态只在现有本机秘密机制中保管，测试证据只记录脱敏元数据。

### 3.1 T1：发布草稿、显式提交与防重复

1. 保留旧 POST /api/publish 的现行兼容语义，并在 API 契约及适配器中准确写明「创建待发布任务，后台可能尽快执行」。清理“只创建 draft”“仍不发布”等错误提示。
2. 在 CreatorHub 新增草稿创建入口。复用已有参数校验与 submit_once，事务内持久化 status=draft；返回任务 ID、草稿修订号、提交身份和状态。保存草稿不触发平台执行器。
3. 草稿编辑保持 draft，采用修订号/CAS；编辑后旧确认摘要失效。新增明确的草稿提交入口，要求本次确认、期望修订号及成片版本/摘要匹配；事务内由 draft 改为 pending。
4. Haike 调用新入口时为一次意图持久保存 UUID、请求摘要和回执；请求超时后用原 Idempotency-Key 查询或重试获取原回执，不自动创建新编号。服务端 409/410 分别提示核对内容或原任务，不静默换键。
5. 提交时冻结账号、平台、视频和封面 SHA-256、文案、预约时间。发布执行前重新核对媒体内容；缺失或内容变化则阻断并给出修复动作。新接口不存在时，Haike 停止并提示升级 CreatorHub，不回退旧 POST。
6. 现有 draft 编辑接口会自动变 pending 的逻辑须随新草稿模式修正；直接 run-now 对 draft 保持拒绝。兼容旧客户端的调用范围在发布契约中逐一说明。

### 3.2 T2：取消语义

1. 为 worker 和各执行阶段提供同一轻量取消检查点，至少覆盖开始执行、开始每个本地阶段、每次付费提交之前、已受理云端任务取回之后。
2. 已提交云端请求后，即使用户点击停止，也应保存供应商任务 ID、用量、费用和可下载产物；不会在结果不明时推断“未扣费”。取回之后停止后续阶段。
3. 本地 FFmpeg 阶段可在当前步骤完成后停。界面明确显示“已请求停止”“正在等待当前步骤结束”“已停止后续步骤”。
4. finish 只按执行器确认的实际终态收尾。取消请求到达时任务已全部完成，保留 completed 和产物；云端结果不明，保留 ambiguous；真实停止后才标 cancelled。保留安全恢复点。

### 3.3 T3：成片版本与人工审核

1. 在正式渲染或全片预览完成且文件稳定后，流式计算完整 SHA-256；登记版本 ID、相对路径、大小、时长、画幅、生成时间、来源任务 ID、QA 摘要和状态。写入必须原子化并使用现有 revision/CAS，文件失败不生成可发布版本。
2. 建立明确的人工审核事件：版本 ID、该版本 SHA-256、审核人或本机操作者、时间、结论、备注。新文件哈希或关键渲染内容变化时，新版回到待审核；旧版审核记录保留。预览 ready 仅表示可观看。
3. 发布目标至少按平台及账号保存；同一平台多个账号分别计数。发布记录保存任务 ID、该次冻结的版本摘要、系统状态、结果链接、平台后台核验状态和核验时间。CreatorHub done 只表示系统任务完成，平台核验单独记录。
4. 旧的路径/大小/修改时间签名继续可读。历史记录保持原有来源和“历史版本待核对”；不能因当前路径相同自动写入新 SHA-256 并标记历史确认。
5. 项目库展示日期、当前版本、审核、目标账号发布进度及异常原因；可筛选待审、待发布、平台待核验、失败。旧记录仍能打开和人工补录。

### 3.4 T4：素材日期与使用索引

1. 在现有资产的来源信息上增加 source_published_at、collected_at、imported_at 及每个字段的来源/精度。日期可只有年月日；仅当原始数据带时区时才转换时区，不凭文件时间推断来源发布日期。
2. CopySkill 候选的 published_at 通过交付详情进入 00-素材目录.json 的可选字段；原片清单有日期时同样传递。Haike 导入时保留日期和原文证据；缺失则留空。已有素材只做非破坏性增量读，人工更正保留修订历史。用户自行导入的文件也可手工登记来源。
3. 使用位置取现有项目引用扫描；跨项目视图由已登记项目的当前引用与已冻结交付清单建立可重建索引。素材原始台账仍归项目所有，内容哈希只用于辅助发现重复，不能自动合并权利状态或删除文件。
4. 素材库增加“来源日期、采集日期、导入日期、当前使用项目、待核对来源”筛选。日期不明显示待确认；过期提醒应依据具体内容类型和证据，首版仅供人判断。

### 3.5 T5：安全恢复和局部返工

1. 队列详情提供只读返工计划：输入变更类型及项目当前指纹，返回要重做的阶段、可复用的云端产物、估算费用和需要人工核对的记录。
2. 字幕、标题、镜头、音乐的本地改动通过既有 full_preview 排队生成新版本；TTS/ASR/数字人提交增量应为零。原任务下载失败或本地合成失败，从原任务的安全点继续。
3. 开新付费父任务前持久保存旧父任务摘要、供应商 ID、产物引用和费用。脚本、音频、头像、模型改变时展示差异；请求结果 ambiguous 时停在核对状态，不开放盲目重提。
4. 页面区分“继续原任务”“只重出全片”“重新付费生成”，并显示清楚的预算与预计操作。费用不明时显示待估算，不写零元。

### 3.6 T6：知识库和跨仓契约

- 核对并修订 Haike 的 publish_adapter.py 说明、Videohub/contracts/publish-v1.md 中预约时间、草稿、自检、真实发布历史的旧结论。
- 修订 Haike docs/handoff/DEPLOYMENT.md 中 RunningHub Plus 默认规则，与 AGENT_GUIDE 的新任务/旧任务冻结区分一致。
- 对 Videohub 现有《短视频三平台发布》提出“版本固定、后台独立核验、项目库对账”补充；对《生产任务中断与付费结果恢复》提出新 runbook 大纲。正式维护遵循 agent-runbooks/README.md 的委托与证据规则，未实测步骤标待验证。
- 新的素材日期与使用说明优先更新 Haike 项目文档；完整采集交付、跨仓备份恢复和版本升级另设专项指导文档。

1. 对照各仓 AGENTS/AGENT_GUIDE 与当日 handoff；核对当前代码相对于本文的变化。记录各仓 HEAD、所涉及文件的未提交差异、活跃队列和发布任务。本文是任务计划，实际代码与当前用户指令优先。
2. 列出本次会触及的项目 JSON、队列 SQLite、CreatorHub SQLite 和生成文件。形成可恢复的隔离备份，记录文件摘要和恢复位置；正式数据库只读检查，不在其上做迁移试验。
3. 定义 API 请求/响应、版本、审核、来源日期和材料引用的 schema；先写旧数据兼容读法和状态转移表，再修改写入路径。
4. 按 T1 草稿/幂等→T2 取消→T3 成片版本→T1 版本提交校验→T4 素材日期→T5 返工→T6 收口分批开发。每批先在临时数据库和假供应商上验证，再做前端读回；跨仓变更以明确版本能力检测连接，缺能力直接提示。
5. 每批核对一次费用和副作用：真实平台请求数、真实云端提交数均为零；测试夹具只含虚构账号和媒体。任何真实付费或发布验证都单列任务和预算。
6. 完成后更新最小 handoff 文件，运行项目要求的上下文审计；保留未通过项、回滚步骤和所有待人工核验项目，不以“页面看起来正常”代替持久化读回。

## 5. 验证方法与测试矩阵（未来实施时执行）

所有自动化用临时项目、临时 SQLite 和假服务，检查接口响应、落盘状态、重启后的读回与外部调用次数。针对性执行既有队列、工作台、发布提交测试，并增加覆盖本次状态转换的数据驱动用例；跨合同变更完成后再执行相邻模块回归。语法检查和页面浏览只能作为辅助证据。

| 验证组 | 输入和故障注入 | 必须读回的结果 |
|---|---|---|
| P1 草稿 | 创建、编辑草稿，多轮运行调度器；直接 run-now | 始终 draft，平台执行次数 0；编辑后仍 draft |
| P2 提交 | 无确认、过期修订号、内容摘要不符、正确提交、重复提交 | 前三种不入队；正确提交只有一个 pending；重复返回原任务 |
| P3 幂等 | 同键同内容、同键异内容、服务端已提交但客户端超时、原任务已删除 | 分别为原任务、409、原回执、410；客户端不自动换键 |
| P4 媒体冻结 | 提交后同路径替换视频、修改封面、删除文件 | 执行前阻断，平台调用次数 0，原任务可核对 |
| P5 兼容 | 新草稿接口缺失、旧客户端明确调用旧 POST | Haike 拒绝降级；旧入口行为与文档一致 |
| Q1 取消 | queued 取消；在下一个付费阶段前取消 | handler/下一付费调用次数均为 0 |
| Q2 已受理 | 供应商返回任务 ID 后取消；查询/下载失败后重启 | 提交总次数 1，ID/费用/产物保留，停止后续阶段 |
| Q3 终态竞态 | 全部完成同时取消；ambiguous 同时取消 | 前者 completed 且文件可用；后者保持 ambiguous |
| V1 版本 | 同名文件重新导出、相同路径替换内容、重新审核旧版 | 新哈希生成待审版本；旧审核和旧发布留在旧版 |
| V2 发布 | 同平台两个账号、某账号 done 未平台核验、某账号失败、历史仅有路径 | 逐账号计数；done 显示来源系统完成但待平台核验；历史不自动绑定新版 |
| M1 日期 | 完整时间、仅日期、无时区时间、缺失、跨日北京时间 | 各自按来源精度显示；不确定项保持待确认，不假造“今天” |
| M2 素材使用 | 同内容跨项目复用、同 URL 不同内容、已回收素材 | 引用位置准确；仅提示重复；不删除或合并权利记录 |
| R1 局部返工 | 仅改字幕、镜头、音乐；下载失败；本地合成失败 | 云端提交增量 0；只做必要本地阶段；旧产物可读 |
| R2 差异与不明结果 | 修改脚本/模型；供应商响应 ambiguous | 列出重新生成的阶段与费用；ambiguous 不重提 |
| D1 数据迁移 | 空项目、旧索引、坏 JSON、并发修订冲突、源库离线 | 旧值保留；坏数据阻止覆盖；冲突返回明确信息；缓存注明旧时间 |
| U1 页面 | 项目库、素材库、队列详情、发布草稿/确认 | 状态与后端一致；刷新及重启后读回；中文说明可操作 |

手工审核在隔离项目中用短小可播放媒体完成：播放所选版本、确认审核事件、修改一处字幕后生成新版，确认该新版重新待审；随后用假的三平台任务回报检查项目库展示。媒体时长、画幅、音频、字幕与 QA 使用现有本地工具读回。此流程不触发真实云端调用。

## 6. 验收标准

以下各项均为硬性通过条件。任一条未达到，本次功能交付状态为未完成；记录差异与安全恢复办法后继续修正。

1. **发布真实语义**：保存草稿、编辑草稿和读取草稿时，假平台执行次数均为 0；只有明确提交后任务进入 pending。CLI、网页、API 文档均用相同的名称与说明。旧 POST 清楚标明其真实行为。
2. **发布防重复**：同一提交意图在响应丢失或重试后只有一个 CreatorHub 任务；同键异内容返回冲突；不支持新草稿能力时 Haike 不能偷偷使用旧发布入口。
3. **媒体与审核绑定**：审核与发布均能指向可复算 SHA-256 的确切成片。文件内容改变时旧审核不覆盖新版；目标平台和账号的完成比例准确。系统 done 与平台人工核验分列。
4. **取消状态可信**：queued 取消不执行；运行中取消不开始下一付费阶段；已受理结果保留；最终 completed、cancelled、ambiguous 与实际产物一致。重启后可从安全点读回。
5. **局部返工控费**：只修改字幕、镜头或音乐时，假云端 TTS/ASR/数字人调用增量全部为 0；供应商已成功且本地失败时恢复原任务而不重复提交。
6. **素材日期可信**：来源、采集、导入日期分开展示并带来源；缺失和无时区日期不被猜测；现有素材引用与重复检测仍可用，跨项目查询不自动移动或删除素材。
7. **旧数据可用**：已有项目、手工发布记录、CreatorHub 历史记录、百炼音色与已生成音频能够读取；旧历史版本和未证实素材日期保持待核对。迁移失败可以用开发前备份恢复。
8. **界面和文档一致**：刷新/重启后状态不丢；异常有明确中文下一步；所有本轮相关自动化测试、隔离集成验证、代表性手工页面检查通过。正式 runbook 只写已完成且有证据的现行步骤。

验收报告逐项记录：条目编号、各仓代码版本、测试环境、夹具或项目副本 ID、输入文件 SHA-256、执行入口、预期与实际、持久化读回、外部调用计数、证据位置，以及“通过/失败/未执行/待人工核验”。不复制密钥、Cookie、完整日志或私人媒体。真实平台作品验证、真实付费恢复和完整跨仓灾难恢复没有实施时，报告必须明确写“未验证”，不冒充通过。

## 7. 交付物与后续专题

本次功能实施完成时应交付：Haike 与 CreatorHub 的代码/兼容迁移、CopySkill 的可选素材日期字段、项目库/素材库/队列及发布界面、离线测试、验收报告、更新后的项目说明和 handoff、Videohub 契约与 runbook 修订提案。正式知识库修改由其治理流程决定。

后续独立专题：跨仓一致性备份及恢复演练；稳定版兼容矩阵和独立机器升级回滚；CopySkill 采集候选的新鲜度与主题质量门；跨项目付费产物自动复用。这些工作要分别冻结数据范围和验收环境。
