# 通用素材管理 V1.1：单次开发指导文档

日期：2026-10-03。状态：已按本指导完成开发；A1—A10 验收通过，证据与边界见文末。

## 1. 目标与边界

本次目标：在现有按内容 SHA256 去重的素材库上，提供可检索、可维护、可跨项目追溯的通用素材管理，并以已有九秒模板和粤仔 41.7 秒实片验证兼容性与复用。

另一个聊天“规划高效通用视频模板”（01a0fdab-f2c0-7201-8c9a-e4957dbc316e）正在开发素材驱动叙事、旁白/原声、混音、时间线和渲染。本次只提供资产、观察记录、冻结引用与使用台账，不开发第二套叙事或生产引擎，不修改对方模块、workbench.py、队列、TTS、生产清单和 server.py。共享入口采用现有素材库 router 挂接，现有页面增加管理入口。

旧 template-band-v1 中央带证据、三段三秒选择器、旧 spec 全部保留；新通用观察不能自动升级为旧模板确认，也不能把旧中央带确认解释为全屏审核通过。素材管理标签不等于画面事实。原片有字幕/原声是事实，能否采用由消费方按使用目的判断。

## 2. 开发前准备与基线

已读取 AGENTS.md、AGENT_GUIDE.md、handoff README/CURRENT_STATUS/CODE_MAP，核对另一个聊天仍在开发。本地 material_library* 等文件是已有未提交成果，必须增量修改，不能整文件重建覆盖。开发前留存本轮相关文件 SHA 基线和 SQLite 在线备份；所有故障/并发测试使用临时库。实库只执行用户授权的粤仔源登记、来源映射、管理标注和使用台账增量写入。

已有能力：完整文件哈希、多位置、来源记录、裁切证据与不可变选材历史。缺口：管理元数据、筛选分页、批量修改冲突保护、文件健康修复、跨项目身份映射、通用区间观察和使用关系。实际视频源及成片不改写，不重新付费配音或渲染，不发布。

## 3. 实现方案与任务拆分

### T1 管理底座与健康维护

新增独立 material_library_management.py，在原 SQLite 中以增量附表保存管理信息，保持 library_meta.version=1 与旧表兼容。提供标签、集合、备注、归档、revision；批量更新在单事务中检查每条 expected_revision，任一冲突整批回滚并返回 409。归档只影响新管理检索/新引用，不删除文件、不破坏历史引用。

查询支持关键词（标题、来源、观察）、标签、集合、平台、时长、画幅、审核状态、归档、已记录健康状态及稳定分页。统计区分素材数、不同时间区间数、审核版本数。健康检查验证完整哈希，记录每个位置的 valid/missing/changed/error 和时间；显示历史检测时间，不把未检测当有效。重新定位必须完整哈希与旧素材一致，再登记位置。

### T2 通用观察、引用与使用台账

新增 material_library_refs.py，独立附表保存来源身份映射、通用观察、冻结引用、使用台账。来源映射支持 namespace/external_id 到 MAT-ID，冲突拒绝覆盖。项目导入使用显式清单，不扫描所有项目；路径指向原片或项目副本，先完整验证整批再登记。

通用观察以原片秒区间（半开区间 [in,out)）为单位，不限制三秒或片段数量。不可变版本包含源 SHA、观察、文本/原声/字幕事实、审核者与证据来源；候选和确认明确区分，确认须具备审核者和可核对证据。渲染画幅适配结论单独限定 profile，不提供全局 usable 捷径。

冻结引用至少包含 schema_version、media_id、source_sha256、source_in/source_out、usage_intent、证据快照及 scope。消费方保存引用；解析时核对源文件哈希和区间。管理标签修改不改变引用。旧中央带证据只以原 scope 引用，不能越域放行。

使用台账包含 project_id、project_version、asset_id、scene_id/slot_id 与 ref_id。相同使用键重复提交幂等，不同引用占用同一版本同一键时拒绝，避免静默改写成片历史。提供素材到项目、项目到片段的双向查询。

### T3 可用入口与接口文档

新增 /material-library/manage 管理页：筛选分页、勾选批量标签/集合/归档、详情编辑、视频播放、位置检查/修复、观察和引用台账。原 /material-library 保留旧选材流程。日常管理不要求填写 JSON。所有可见文案为中文，错误可理解，提交期间禁用重复操作，冲突要求刷新。

新增 /api/material-library/manage/* 与 refs/observations/project-import 子接口，旧 API 不变；提供独立 scripts/material_library_manage_cli.py 供 Codex 和其他模板调用。发布文档描述版本、字段、半开区间、幂等/CAS、审核作用域和调用样例。第三模板接入使用此合同，不修改它的业务实现。

### T4 集成与真实素材验收

为粤仔实片两份原片登记稳定 MAT-ID，同时保存 published 视频 ID 和项目源身份映射。预检发现 S-001/S-002 实际为 portrait-contain 衍生文件，不能把其身份映射到原片；分别登记原片 SRC-USA/SRC-FRANCE 与实际 S-001/S-002，并保留显式派生关系。由已有 source-baseline.json 和 edit-plan-v2.json 生成显式项目导入/引用清单，登记 7 段的 9 个源区间及使用关系。沿用已有审阅状态，不把导入动作当新的画面确认。将新增追溯清单置于项目 artifacts/material-library，不改原剪辑计划/生产清单/成片。

旧九秒模板运行既有真实 FFmpeg 测试与冻结 spec 回归；粤仔验收使用已有成片和原片核验，不进行无关重渲染。第三模板未完成时以公开合同和独立消费者测试验证可接入，不宣称其生产联调已完成。

## 4. 开发流程

1. 保存本指导文档，记录文件基线与数据库备份。
2. 并行实现 T1/T2/T3；每组只修改分配文件，主线程负责 API/CLI、合同与集成测试。
3. 先跑新增模块测试，再跑现有素材库、模板 spec、API 与相关导入回归；发现同范围缺陷即修复。
4. 启动独立本地验证服务，使用真实浏览器检查管理页、筛选、详情、保存、错误反馈和旧入口；不重启正在使用的生产服务。
5. 执行粤仔增量登记与反向追溯核验，留存机器可读报告与 UI 截图。测试报告明确自动验收和第三模板后续接入的边界。
6. 回填逐项验收结果，更新最小 handoff/CODE_MAP，执行 audit_context_handoff.py。
