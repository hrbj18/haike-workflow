# 成片二剪工作台 V1 · 单次开发指导文档

日期：2026-09-30。开发前制定，实施后在末尾追加验收证据。

## 本次目标

在 `/published-clips` 接通检索/复核 → 选材篮 → 顺序与边界编排 → 逐段原声设置 → 草稿保存/重开 → 统一队列渲染 → 页面预览及 MP4 导出。用至少两条已登记原成片、三个片段完成真实端到端验收。原片只读，成品停在待人工审核，不自动发布。

## 实现方案与边界

- 在现有本地 SQLite 增加二剪草稿与渲染登记。草稿使用 revision 乐观锁，保存冲突返回409；稳定片段ID与来源视频内容指纹，顺序即时间轴。
- 项目在现有 `projects/` 中建立独立二剪项目及 `project.json`；注册 `published_remix` 统一队列类型、执行器与恢复逻辑，不另开绕过队列的生产线程。项目工作流清单写明本地 FFmpeg、零外部费用、9:16、720×1280、30FPS。
- 每次提交冻结独立请求清单，队列只持有版本签名；渲染读取冻结版本，不读取之后修改的草稿。同版本重复提交幂等，失败可从同版本重试；旧成品不覆盖。
- 每段支持入点/出点、开场/主体/结尾用途、说明和原声保留/压低12dB/静音。跨画幅使用等比缩放加黑边，避免拉伸或自动裁掉人物；先逐段归一帧率、采样率和声道，再拼接。
- 切割按固定帧数生成、声音补齐到同一时钟；每段音频轻微淡入淡出防爆音，无声片补静音轨。预览与下载使用同一经QA的MP4文件。
- 旧片头片尾通过边界排除，界面提示烧录字幕/混入原声的配乐不会自动消失。此次不实现去字幕、人声分离、解说生成、新BGM、复杂转场或平台风控判断；避免把处理成片包装误称为去重保证。
- 自动事件候选可选用，但明确保持待审。人工未确认不被程序自动改成已确认。二剪可先选已核对片段，不等待全库语义真值完善。

## 任务拆分及顺序

1. T1：核对现有索引、队列、渲染、项目合同和脏工作树；先完成本文。
2. T2：实现草稿数据合同、创建/列表/保存/读取，来源与边界校验、revision冲突和内容不变时不增版本。
3. T3：注册队列执行器；冻结版本、幂等提交、技术QA、失败记录/恢复、受限预览及下载路径。
4. T4：在索引页加入选材篮、片段加入/删除/排序/边界与音频编辑、保存和重开、渲染状态/历史版本、预览/下载。
5. T5：新增单元、API、真实FFmpeg与队列回归测试；覆盖无音轨、混合画幅、静音、乱序、旧版本一致性、无效路径和原片变化。
6. T6：至少2源3段真实素材经统一队列渲染，核对时长/音轨/画幅及关键帧；浏览器完成添加、重排、保存重开、预览下载入口验证。最后更新交接与本文验收结果。

## 验收标准

### 数据安全与保存

- 仅允许已登记且当前内容指纹匹配的原片，不接受浏览器传入任意路径；时间必须有限、非负、入点早于出点且不超过源时长；最多30段/总时长600秒。
- 修改顺序、边界和声音设置后保存，再重开不丢失；过期revision保存拒绝且不覆盖其他编辑；来源ID、片段ID、原声选择进入冻结清单。
- 不修改或覆盖原片；无效源及替换文件停止渲染；已有预览仍保留。

### 渲染、队列和恢复

- 新类型在统一队列中串行执行，重复提交同版本得到同一任务；编辑草稿不影响已提交版本；失败可重试原版本，完成文件有QA清单且播放/下载使用同一文件。
- 输出 H.264 / AAC、720×1280、30FPS；输出总时长与帧时钟清单差≤0.08秒；音视频时长差≤0.08秒；无音轨输入可正常合成；静音段实际静音、压低段音量变化在测试中可测。
- 自动检查可解码、无拼接新增空白帧/错误时长；原片本身的黑画面及人为硬切保留，不声称自动语义审核通过。
- 本地渲染结果标为待审预览；页面可播放、下载MP4及查看旧版本。中途失败不暴露半成品，不覆盖上一版。

### 界面与实际产物

- 从搜索/复核片段加入选材篮，支持至少2源3段、顺序调整、片段原声、边界编辑；总时长随编排更新。未保存改动提示，渲染先保存成功再提交。
- 存在真实测试项目与待审成片：清楚记录来源区间、处理方式、生成版本和技术QA；浏览器操作与后端读回一致。
- 新增测试、索引回归、生产队列回归通过；JS语法和交接审计通过。完整测试命令及实测结果写入本文；未验收项明确标记。
