# 动效模板定稿与复用

蓝白 v7 的竖屏效果于2026-11-01获得用户定稿确认。[定稿约束](../templates/hum-production-v1/quest/approved-look-v1.json)记录七段编排、允许替换项及成片SHA，布局真值仍在原组件和layout.json。以后增加实拍时保留打字、换位、路径接力与转场，用已有素材窗承接内容。定稿的是这套效果；新声音、新画幅和新增动作各自验收。

## 同一方法，按协议执行

| 模板 | 从哪里复用 | 本次测试内容 |
|---|---|---|
| 蓝白任务口播 | 选择“保留原动效与实拍融合v7”草稿，复制为新视频 | 已定稿的竖屏编排、旁窗、连续路径与人物变窗；原完整声音与字幕保留 |
| 点阵手账2.7.3 | 复制已完成的native草稿，改公开recipe | 换标题、关键词、步骤标签和结论，保留手绘标注、留页与相机接力；公开协议没有局部人物/实拍槽 |
| 纸感透视 | 复制已完成的motion-kit草稿，改timeline | 换实拍取段，恢复quote/reveal，保留原六种控件和末段同源人物 |

1. 复制已完成草稿，保留模板版本、素材身份和原期次。工作台使用“复制为新视频”；本机CLI为`Haike_video/.venv/Scripts/python.exe Haike_video/scripts/motiongit.py clone <草稿ID>`。通用“新建”的示意参数不等于已定稿的本期编排。
2. 保留或绑定完整口播、真实ASR字幕和来源。换声音后按真实整句/词证据重新安排场景与事件；声长是主钟，不能按旧片总长度等比缩放，不能循环短人物。只改画面文案时也核对与现有口播含义一致。
3. 只替换当前协议开放的字段。保留动作类型、持续对象ID、转场与阅读窗，核对原片取段足够长。删除一个素材窗时同步清理它的mediaPolicies；否则原生计划会拒绝未使用素材的策略。不存在的槽进入适配开发，不能伪称已支持。
4. 结构检查后冻结。相同草稿、参数、素材及工具重复冻结应得到同一请求；重复提交应得到同一任务。改输入另存版本，保留失败工程。
5. motion-kit先核对计划的完整台词、目标、取段及人物显隐，再生成全部预览；native按自身预览合同。实际查看后提交绑定SHA的审核。结构通过不能自动批准图片。
6. 整片进入现有统一队列。完成后核对1080×1920、原帧率/全片帧数、视频流≥20Mbps、完整解码、混音峰值和所有场景的实际编码画面。恢复已完成任务应返回原作品及同SHA文件，不再调用配音或数字人。

本期草稿、请求、原生计划/预览、最终文件和重复提交/完成恢复回执保存在忽略目录`.local/template-upgrade-20261101/reuse-tests/`，以实际回执为准；未完成项保持待验。个人原包与媒体不随公开源码分发。协议入口和未知包边界见[原生接入说明](NATIVE_TEMPLATE_PROTOCOLS.md)。

### 1. 固定可执行预设，保持历史兼容

增加项目自有的公开预设目录与清单。每份预设有独立的`preset_id`、`preset_version`、参数结构版本、引擎要求、文件SHA与验证范围；引擎文件和布局仍是动作/几何唯一真值。预设持有动作组合、对象ID、素材槽及时间安排规则，不复制一套布局数字。

蓝白预设由已认可v7提取：完整打字后出现照片、原ID榜单换位、地点与实拍、白底至深色的同图路径、旁窗、人物变窗、五照片收尾及现有转场/声音事件。冻结的是动作关系和容量；30.6秒和侯总22.8秒出镜位置属于本期输入，不能写成所有新片的固定时刻。

清除开发机路径、草稿/作品ID、私人字体/图片/声音绑定和旧审核回执。保留必需槽的类型、比例、数量、长度与不足处理。缺输入时进入待绑定状态，不能用示例文案伪造完整ASR或复用旧口型。

新增预设选择和“用此模板制作”入口，仍通过现有草稿保存、资产上传、冻结和统一队列；Agent与网页使用同一创建逻辑。预设列表/创建入口是本计划新增能力，现有`/api/studio/motiongit/packages`和`/drafts`继续兼容。

不能直接覆盖`params.example.json`来升级默认效果：当前包SHA从它计算，覆盖会让已有草稿的`package_sha256`不匹配。旧包和旧示例保持身份；新预设单独版本化，新草稿显式记录采用的预设版本，已有草稿不自动迁移。任何需要迁移的旧参数先复制新版本，原参数与原作品保留。

| 纸感透视 | `template-02-expanded@2.7.21-alpha.5`，motion-kit，已验证helper | 本机有合法原包则核验复用；缺原包则待导入 |

适配器按模板ID、精确版本和执行协议匹配用户已导入的原包。个人封套的SHA/包ID可能因用户不同而变化，应在该用户本机验签后冻结；不把制作机器的个人包SHA、Key或registry.sqlite3作为公共依赖。未知版本保持待适配。

本次可交付“蓝白自有内置＋两款合法原包的预设/适配器”。若要求所有老用户无需原包就能用三款，则先独立实现两款自有模板或取得相应分发授权，再按各自新身份验收。没有原包的安装不能显示“三款全部可制作”。

### 3. 按本次功能清单打包

程序包包含引擎/适配器、公开预设与规格、必要API/CLI、从已验收提交重新构建的前端，以及用户操作说明。资源包只包含核对可分发的字体、图形、音效及确需补齐的执行依赖，保留各自来源/许可和SHA；私人人物、成片、原包封套、账号及运行数据库不进入公共附件。

资源清单需要覆盖本次实际使用的helper和各路线公开依赖，不能只打包旧console缓存。Python环境、FFmpeg、Node、浏览器及字体必须在目标安装根内或经明确支持的本地发现入口解析；本机C盘虚拟环境、临时PATH、硬链接与`.local-bin`修复不能被当成另一台机器已有的能力。

沿用现有事务更新，原1027走独立bootstrap；已有1.2仅在运行环境、依赖锁与数据结构兼容时走程序补丁。新增依赖必须纳入可核验的资源/迁移方案，不修改兼容门禁使不兼容补丁强行通过。原来有效的运行环境优先复用，缺失的必要组件按清单处理。

目标产品版本必须大于已发行版本，以验收后实际发布值为准；不复用旧发行号。现有bootstrap下载总量上限为200MB，程序包与资源包合计须实测；超限时重新设计资源交付或迁移路径，不能直接提高上限掩盖变化。

### 4. 让更新器识别“本次定稿能力”

在发行清单中增加有SHA绑定的模板交付清单，声明每款预设版本、引擎/协议要求、文件与资源哈希、是否需要用户原包、可验证画幅及最低应用版本。同步扩展下载、校验、打包和本地诊断；清单只是数据，不执行其中任意命令。

更新器继续执行：识别安装副本与基线→检查原队列/音色/更新事务→下载与校验→备份→停止本副本视频服务→安装→启动→读回目标版本与精确预设能力→记录成功或恢复旧程序。现有空闲门禁已经检查统一队列与音色操作，本次补验各新路线都受门禁保护，不另起一条更新执行器。

不能仅以版本号相等或模板数量大于三判定成功。现有`already_current`分支需同时核对请求的模板能力及文件完整性；缺失时报出修复需求或提供新的修复发行版，不静默绕过基线哈希检查。不要把10/30旧三款目录存在当成本次三款已安装。

把“程序更新完成”和“模板可制作”分别记录。每款至少显示：待补运行组件、待导入合法原包、待绑定本期素材、可制作或本地渲染自检失败，并给出具体补齐位置。已知缺用户原包/素材可以正常完成程序更新，但回执必须保持待配置；程序文件缺失、依赖失效或本应通过的本地自检失败则阻止成功，进入既有回退流程。

安装阶段只检查程序、资源与渲染能力，不调用付费TTS/ASR/数字人。短自检采用独立测试目录、合法公共测试素材和现有队列；只证明对应局部机制。用户下一条真实视频仍用自己的服务、预算和素材，不能继承制作机器的审核结果。

### 5. 在升级后的1027副本实际复刻

建立独立验收目录，从真实1027包开始，保留其清单与基线身份。只通过候选更新包安装；验收进程不得读制作机器的`.local`、历史草稿数据库或原工程临时路径。测试输入在副本内单独导入，兼容原包由本地合法测试资源提供，不进入公开发行包。

| 验收项 | 完成条件 |
|---|---|
| 程序与模板身份 | 版本/提交/资源清单一致，三款精确预设可查，页面与Agent调用同一预设，不依赖旧v7草稿ID |
| 蓝白复刻 | 从正式预设新建，以原已验素材复刻关键动作；实际核对打字后照片、榜单换位、同图路径接力、旁窗与人物避让、转场及收尾，不只看目录/封面 |
| 两款原包复刻 | 有合法原包时各从正式预设新建并完成计划、全部预览、整片与作品记录；缺原包时显示待导入，不能被计为出片通过 |
| 新输入复用 | 同源回放之外，使用另一份已有完整口播及真实字幕，按其原时长重新绑定文案/素材；声音与可选人物必须同源，证明不依赖本期30.6秒常量 |
| 片子质量 | 完整解码、声明的尺寸/帧率/帧数、视频流≥20Mbps、AAC真峰值≤−1.5dBTP；各场景实际画面、字幕、声音与参考分别验收，连续听看不由静帧代替 |
| 数据保留 | 关键配置、Key、账号/草稿/作品/素材测试文件在升级前后保持；公共预设不通过覆盖用户数据库来安装 |
| 重复/恢复 | 重复更新不重复安装；重复提交返回原制作任务；重启能找回原作品；下载中断恢复原事务，不重做成功的收费阶段 |
| 故障/回退 | 包损坏、依赖缺失、启动失败、模板自检失败分别模拟；原程序可恢复，用户数据及其他副本不受影响 |
| 路径隔离 | 移动安装目录、中文/空格路径、禁用开发机缓存与临时PATH后仍通过声明范围；这仍是隔离副本，物理异机另记 |

新输入测试覆盖的实际时长与内容边界逐项登记，不把两条样本称为任意稿件自动适配。效果无需压缩编码后逐字节相同，但预设/源身份、对象状态、动作关系、可读性和声音时钟必须符合定稿契约。

### 实施顺序与发布门槛

1. 先做正式预设与创建入口，保留旧身份；在当前源码副本完成不依赖历史草稿的新建制作。
2. 再补资源清单和模板能力诊断，接入现有bootstrap与兼容更新器。
3. 从干净、已提交源码构建候选包；执行上表的1027升级、真实出片和回退验收。
4. 按当期发布授权完成PR/CI与正式发行：先上传资产并读回大小/SHA，再公开稳定清单和一句话更新说明。更新版本和清单标识不得指向尚未可下载的附件。

实施代码主要落在`studio_motiongit.py`、其API与前端模板库、`package-legacy-release.py`、`update-from-github.py`、`portable/legacy_upgrade.py`及兼容更新模块；验证沿用`test_legacy_upgrade.py`、`test_github_online_update.py`、`test_app_update*.py`和MotionGit测试，并补升级后出片的集成验收。具体新增预设/诊断文件在实施时登记。

本计划的完成判据：1027副本仅取得正式更新包和本用户合法输入，就能从同一版本正式预设生成通过验收的片子。当前已有的本机同源测试不替代这次升级后验收。
