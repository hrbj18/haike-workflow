# 项目库日期与发布索引

## 页面使用

- 项目库按创建时间倒序，分「今天 / 昨天 / 具体日期」显示，时区固定北京时间。每行显示创建、更新时间及当前成片文件名。
- 支持名称/编号搜索、创建日期、制作进度、发布状态筛选；可切换最近更新排序。
- 点击发布摘要打开记录面板：选择目标平台、管理的成片版本，必要时补录创建日期。默认跟随最新发现的成片；手动指定旧版时会提示另有更新成片。
- 人工登记需选择成片、平台、账号及状态；「已发布」还需实际发布时间。可填写作品链接与说明。修改人工记录保留旧值，版本冲突要求重新打开后操作。
- 面板只登记和读取记录，不执行上传或发布。项目有成片只表明文件存在，不自动视为审核通过。

## 数据来源与边界

- 创建时间优先使用人工补录，其次项目 `project.json.created_at`；无时区或缺失时显示待确认，不从目录名、复制时间猜测。
- 更新时间来自工作台更新时间及现有状态文件活动记录。超过 15 分钟无活动但仍留有运行状态的制作记录显示「进度待核实」，不自动宣称任务完成或失败。
- CreatorHub 的 `publishtask` 通过 SQLite `mode=ro` 读取，默认同级 `creatorhub/data/creatorhub.db`；自定义位置用 `HAIKE_CREATORHUB_DB`。不读取账号凭据表，不修改 CreatorHub。
- 仅绝对媒体路径落在该项目目录内时关联历史任务；不按标题相似度匹配。复制到外部上传目录的历史任务需人工补录。
- CreatorHub `done` 显示「已发布」，注明来源和任务编号；这代表发布系统记录，不声称本次重新访问平台核验。`done_at` 与 `created_at` 按该模型定义的 UTC 读取。
- 历史任务只有文件路径，不能证明当时内容与当前文件相同，因此标注「历史版本待核对」，不直接计入当前版本完成比例。
- 当前版本通过相对路径、字节数、纳秒修改时间形成文件签名。正常重新导出会产生新签名；刻意保留全部文件元数据的外部替换不在此签名检测范围内。
- 已发布比例以用户设置的目标平台为分母，只统计当前版本的确认记录。未设目标时不显示「全部已发布」。同一平台多账号逐条保留，但目标比例按平台计算。
- 可见页面每分钟读取一次发布状态，也可手动刷新。打开记录面板时暂停后台轮询以保留输入。同步缓存 `.backlot/library-publish-cache.json` 在连接失败时保留，明确标注离线和上次同步时间。
- 本机编辑保存在项目 `artifacts/library-index.json`，含 revision、目标平台、选定版本、日期补录、人工记录及修改历史。读取损坏记录时阻止覆盖。

## 代码与交付

- 后端：`backlot/library_index.py`、`state.py` 的日期/成片摘要，以及 `server.py` 的 `/api/projects/{id}/library-index` GET/PUT。
- 前端：`ui/library_index.js`、`ui/library_index.css`，由 `library.js` 和 `index.html` 引入。
- 本次进行了 Python 编译、JavaScript 语法检查及页面查看；读取了现有项目日期和 CreatorHub 历史记录。没有真实上传/发布，也没有将不确定历史版本批量标成已确认。
- 素材来源日期、拍摄日期及跨项目复用索引属于后续独立优化，本轮落地项目日期与发布记录。
