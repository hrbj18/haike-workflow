# 模板6 · 六风格声画动效版（art-v5）

独立于历史 art-v4。六套版式保留，新增原创配乐、低频击打／冲击／过门／轻击，以及短句弹入、实词重点回弹、合作金额三连和要点落版。画布仍为1080×1920、30fps，完整文字与人物、源语速保持。

`index.tsx` 注册 `HaikeInvestmentArtV5`；`layout.json` 保存六风格强度，`shared.tsx` 保存真实词边界短句和字幕状态，`Motion.tsx` 将真实发声或已登记音效落点映射为一次衰减动作。短句从首个有效帧就完整可读，稳定后持读；只给选定词组重点，不逐字随机抖动，不摇晃人物或闪整屏。

当前v5六风格均不再绘制左下角“数字人演绎”页脚，品牌、栏目、真实素材来源标签及其余版式保持。v002／v3／v4历史不变；旧成片和其通过记录仍属于原SHA，删除页脚后的新成片须独立核验，不能直接沿用旧六片通过结论。

声音资源在 `assets/sound/`，来源见同目录 `PROVENANCE.json`：118BPM主电子配乐、124BPM赤红配乐、100BPM纪实配乐及四类短音效，均为本地确定性DSP原创，无外部采样。旧三套装饰图来源继续由 `assets/PROVENANCE.json` 记录。模板可分发资源不包含用户人物、口播音轨或真实互动视频。

从仓库根使用 `Haike_video/scripts/avatar_investment_source_art_v5.py`，输入原MP4、真实cue与完整word-clock、`variant=art-v5`艺术配置和`--audio-plan`。音效只允许真实词／cue／章锚点，`triple-hit`为同一锚点上的编辑三击，不造词时钟。资产 `sync_ms` 为声音自身的同步点；过门可铺前430ms，词时钟不移动。

原生准备阶段冻结唯一48kHz立体声 `mixed-master.wav`，预览与最终封装共用此母带。口播轨一次-2.5dB；配乐按六种风格设底电平并由实际人声侧链压低；音效按事件单独增益。母线峰值保护和必要总增益均透明写在回执，最终AAC真峰要求≤-1.5dBTP。最终mux不重复volume/loudnorm、不改语速，不再强制单声道。

完整视频通过统一 `studio_investment_recompose` 队列和全局单lane导出。已有成功任务按原request恢复；不要覆盖旧request、旧成片或收费数字人。当前验证范围由同目录正式规格与同名runbook记录；制作授权不代表用户已确认成片或允许发布。

新准备的已有原片任务默认 `--render-profile high-fidelity-20mbps-v1`：人物 MP4 逐字节复制到 `public/avatar.mp4`，保留原始帧率，由既有静音 `OffthreadVideo` 按秒采样；不先转30fps或产生CRF23中间代。原片视频必须覆盖最后成片时间戳，长度不足会拒绝，不自动补帧或拉伸。1080×1920／30fps画布、版式、字幕／素材时钟、原声及冻结母带保持。

默认配置采用PNG无损画面帧、H264目标20Mbps平均码率、slow预设、yuv420p，通过本机Remotion的 `--video-bitrate=20M` 编码；不同时设置CRF，不添加填充数据凑文件大小。实际平均码率随内容变化，成片需按真实视频包字节／时长测量并如实报告，20Mbps是目标而非已测结论。最终封装复制视频流并保持既有AAC音频策略；没有文件体积上限。画质配置进入项目身份、request指纹和导入清单，实际人物SHA、渲染命令与视频流复制写入 `render-quality-receipt.json` 并由结果回执绑定。较大文件不等同于新增原片细节，原始人物分辨率仍是上限。

原 `--render-profile high-fidelity-v1` 保留PNG／CRF16／slow全部参数；`--render-profile legacy-v1` 明确准备旧参数的新请求。历史缺少 `render_profile` 的请求保留原语义，不按新默认改写；源码指纹变化时未完成请求继续受原runtime校验约束，需另建高清请求而非覆盖历史。旧产物与其已冻结参数独立保留。高清能力的真实导出／视觉验收按本次新请求单独记录，参数与测试通过不代替成片验收。

只调整画质并需音频完全一致时，准备阶段指定 `--reuse-audio-request <已完成v5的request.json>`。入口会核验原生队列已完成、来源与完整结果回执、原声PCM、音频计划（仅导入位置可变）、素材SHA、时钟、混音器及FFmpeg身份，逐字节复制该请求的母带／诊断母线／原生成plan及receipt，不重混音。旧生成回执保留原身份，新 `audio-reuse-receipt.json` 单独绑定复用来源；donor请求副本、复制文件及复用证明进入本次指纹和来源清单。校验失败会拒绝，不悄悄回退重混，也不覆盖任何旧请求。最终AAC仍以同母带和既有封装参数编码，是否逐包一致以实际成片核验为准。
