# v2 candidate validation sequence

1. Verify `motion_public_execution_v2.component()` and `runtime()`. Runtime identity binds all five v2 modules, reused IO, every candidate file, original public upstream verifier/inventory/files, Python dependencies and interpreter bytes. `environment` independently verifies the unchanged external tool/runtime descriptors and actual files. Nothing installs or downloads automatically.
2. Prepare fresh `/2` input through `backlot.motion_public_production_v2.prepare`, using `input.schema.json` or `dark-v2/input.schema.json`. Keep complete approved script, real ASR and word times, original-speed source media, font and audio bindings. Do not edit or resume `/1` requests. Use new `motion-public-v2-*` work IDs and controller artifacts.
3. The controller injects `invocation['_phase_guard'] = lambda: _guard(queue, job, request)`. It owns admission, concrete current approval, real claim/lease/cancel and final registration. The executor invokes that guard before and after each subprocess, and at build/render boundaries. Direct executor use without that callback is rejected before media.
4. Await an assigned sole media slot. Produce a fresh target preview through the common controller. Preview receipts bind current request SHA and actual ordinary PNG identities. For dark, compare s01 and s08 target regions and pixels outside them against the retained same-input baseline; preserve geometry, frame strip/highlight and legitimate notes. Reference demonstrations must retain their labels. Readiness-only scopes cannot admit full exports.
5. For observed controls, inspect actual complete paper typing/author entry and poster title, mixed Latin/CJK, exact declared line boundaries and completed/current/future step states. Do not treat the old font-prefix probes or static DOM tests as media acceptance. Keep unresolved font/container identities explicit; retain licenses and source evidence.
6. Review all actual selected preview images through the controller. Only current `approve`, its exact `approval_id`, entire review-record SHA and exact image/request bindings can admit render. There is no comparison-export magic string. Any withdrawal stops further command boundaries and prevents artifact registration.
7. Complete the original renderer export and whole-file decode/loudness checks. The dark path retains Remotion 4.0.506, Chrome149, the original H264 CRF1/PNG/yuv444p intermediate and same-SHA FFmpeg9 CBR20.5Mbps/yuv420p/AAC48k stereo export. HTML uses its original renderer/frame/decode gates with the existing fixed CBR encoding adaptation. Actual visual comparison and continuous listening still decide acceptance.

Current candidate state: static work only, no new provider calls, renderer media runs, installs, releases, updater or default-gallery promotion. Root integration and the B controller remain separately owned.
