文档类型：video-template-runbook
标准版本：video-template-v1
模板规格：[规格](template.spec.json)

状态：本机开发验收，当前逐项范围见 [VALIDATION.json](VALIDATION.json)。最近核验：2026-10-30。权威入口为本目录源码、[队列适配器](../../backlot/studio_chalkboard.py)及[项目 Guide](../../AGENT_GUIDE.md)。

适用范围：月相/地影等同一球体模型的连续运动、放大归位、倾斜轨道与双实验比较。输出为真正重排的4:5和9:16；原参考八章动作节奏与全局时钟可保留。字体、笔触及右实验曲线为独立实现。没有实现原包全部机制，也不声称任意 `.motion` 自动转换。

## 触发、规格与前置条件

呼叫「粉笔黑板知识讲解双比例」；ID `chalkboard-explainer-v1`。实现规格与阶段从 JSON 读取；本次完整开发测试已获授权，正式复用还须核对适用 gate。项目工具执行，Agent负责理解和实际审片；未授权付费生成或发布。

参数真值为 `types.ts`、`Board.tsx`、`physics.ts`及本期冻结请求。规格中描述的是当前210秒八章测试；新片时长由实际音轨/帧时钟决定。主对象跨章连续，不在换句或切标题时归零。控制范围见 `slots`，不以替换文案自动改变物理关系。

必需输入：本期 JSON，包含 `template_id`、`props`、`assets`、`tools`、`reference`。`props.example.json`是不含私人素材的起点；`types.ts`声明全部绘制参数。`assets`以平面文件名绑定本机绝对路径和SHA256；`tools`绑定node、ffmpeg、ffprobe、Chrome绝对路径及SHA256；`reference`绑定原片SHA与已提交理解记录的绝对路径。字体需合法绑定，源码不分发系统字体。

有口播时使用真实音轨及实测字幕时钟；已有ASR结果可规范化复用，不重复收费。源混合音轨只合入一次。换音频后重建句时钟和语义触发，不拉伸人声凑时长。没有逐词证据时保留句级锚点。

## 当前操作

在仓库根目录使用本副本Python，所有本期输入/媒体留在忽略目录；命令帮助是参数真值。

1. **核对。** `chalkboard.py check --input 本期JSON`检查props；`prepare`再核验素材/工具/理解证据SHA并冻结源码。输出固定project、request和原队列编号；gate为输入完整、时钟覆盖全片、权限与引用一致。缺输入补齐，不覆盖旧请求。
2. **预览。** `chalkboard.py prepare --input 本期JSON`进入统一队列，输出每章前中后共34帧。实际查看所有预览后，写证据 JSON `{seen:["0.png", ...], description:"真实观察和范围"}`，通过 `review --request 冻结JSON --evidence 证据JSON`登记。gate为标题、字幕、物理状态与替换边界均可读；图片存在不等于看过。
3. **完整测试。** `chalkboard.py render --request 冻结JSON`沿相同输入和队列导出。输出 `renders/<render_id>/chalkboard.mp4`、`quality.json`及作品ID。gate为完整解码、实际画幅/fps/帧数一致且视频流≥20Mbps，再检查编码后的关键过渡。开发完整测试按本期明确授权执行，不自动变为正式生产验收。
4. **交付。** 逐项记结构、技术、视觉、连续听看、真机、用户和接入状态；提供实际视频和报告。抽帧、响度测量均不冒充连续听审。用户未授权发布时交付本地测试产物。

完整入口为 `Haike_video/scripts/chalkboard.py`，不要直接调用底层node渲染器。所有动作都保存既有音轨与请求；源码改变后新建冻结版本，不让旧预览批准新源码。

## 验证与恢复

验证矩阵、测试条件及产物身份见 `VALIDATION.json`；本期详细路径和逐次日志在根 `.local/chalkboard-understanding-20261030/`。本机统一队列不等于产品下拉选择器已接入；异机、手机和正式发布单独验收。

`status --request 冻结JSON`找回project及render_id，并查询原队列编号。预览完成可复用；渲染正在运行时继续观察原任务。中断留下MP4时，仅有匹配SHA且完整解码通过的quality回执才会复用；其余文件自动保留为 `incomplete-<唯一编号>.mp4` 后重新执行。实际故障恢复范围见VALIDATION。

只纠正字幕文字时，可在新输入加入 `caption_patch_from`，指向本机已完整解码版本的冻结请求。必须保持音轨、句ID/时间、模型、布局及视觉源码完全一致；当前支持片内不超过60秒的改字区间。新请求重新预览审核，仅重绘受影响帧，再合回完整画面。最终整片重新核对帧数、解码、画幅、色彩范围及码率；不是把旧审核批准到新文字上。更换音轨/时钟/布局时使用完整渲染。

有声导出统一从已绑定的原始音轨封装native AAC，写入正常的编码延迟元数据，避免Remotion内置编码器残留约两帧AAC的偏移。整条源音轨只合入一次，不改语速；画面流复制保留。已有同一完整画面只修订音频编码时，输入可用 `audio_remux_from` 指向旧冻结请求，要求所有props、工具、资产及视觉源码一致；复用已审核的同一组预览文件并核对SHA，重新绑定本期review。此入口不允许换音轨或偷换文案，实际同步仍需本期音轨测量和听看检查。
