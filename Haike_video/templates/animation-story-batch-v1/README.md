# 五款动效口播模板 · 完整低清对比

当前用户结论：这五款观感同质化，应视为同一母版的五种视觉变体，未满足五种独立动效模板要求。技术检查不代表差异化通过；后续执行[设计与差异检查](../ANIMATION_DESIGN_GATE.md)，历史产物保留作对照。

文档类型：video-template-runbook；标准版本：video-template-v1。
模板规格：[柠紫](specs/lime-rail.json)、[蓝橙](specs/blue-broadcast.json)、[珊瑚](specs/coral-album.json)、[黑金](specs/darkroom-film.json)、[青蓝](specs/cyan-blueprint.json)。
状态：implementation + specification；授权为五条各30.8秒完整开发测试片，有声音和真实动态数字人。不是正式制作模板上架或生产ready声明。

## 需求与真值

用户已明确允许极低分辨率、速度优先：输出270×480/15FPS、约700kbps视频，初次编码96kbps AAC，交付音轨从原PCM以128kbps AAC重新编码。只验证排版/动效编排/声画关系。正式画质规则本轮被用户低清测试要求覆盖，原素材不改动。

执行[动效编排与密度规范](../../../Haike-Videohub/agent-runbooks/视频动效编排与画面密度控制.md)；当前用户更严格：任何帧都须有可辨认的大人物或真实素材，背景/标题不单独算主体。口播整句和逐句字幕禁用；短主题常驻，每拍只一个主动作，辅助层可为空。核心动作沿时间轴轮换，禁止同一帧堆动效。

`build_plan.py`生成`layout.json`，后者是冻结实现使用的唯一参数输入：五种配色/材质、场景切点、声轨顺序、运动范围和taste_profile。`index.tsx`/Backdrop/Header/SceneView给出各自构图，MediaRail复用固定Snapcn CardRail几何与测量曲线，仅将图片槽改为实际视频；上游未改。PhoneFrame为本地原生组件。未宣称全部五款都是上游成套模板。

本地Taste Direction控制视觉/运动/密度三项；已实际阅读与查看Hallmark brutal/cobalt/coral/darkroom/blueprint的MD/JPG，来源commit为本地catalog记录。采用部分材质、结构和字重原则；本次撞色、真实人物、密集动态素材要求优先，不声称逐条照搬网页主题。未调用图像生成或外部素材。

## 五条的实际差异

| 模板 | 构图/材质 | 主运动与节奏 |
|---|---|---|
| 柠紫透视影轨 | 酸柠黄/紫斜面、立体动态影像卡、大手机 | 横向揭示、两次卡轨甩动、留稳；九段 |
| 蓝橙现场演播室 | 电蓝/亮橙硬色面、直角大窗口、设备同组上下镜头 | 短竖向揭示，前短后长；九段 |
| 珊瑚薄荷生活相册 | 彩色底、纸边、轻倾角、大幅动态照片 | 软交接，较长停留；八段 |
| 黑金现场纪实 | 黑白动态影像、暖黑底、稀疏金色、无卡壳 | 低幅镜头推进，少切镜；七段 |
| 青蓝科技观察窗 | 深青底、切角大窗口、清楚的局部框线 | 遮罩展开后单次框线引导，短拍穿插；十段 |

动效编目及互斥规则见`MOTION_CATALOG.json`；节奏和数值以layout为准，不因组件数量而强行补装饰。每个主动效结束后有稳定观察期。

## 声音与动态人物

上一条紫色5秒卡轨使用presenter.jpg，是静态图片，且样片无声，所以人物不说话。本版所有人物槽改为同源实际视频，不用静态截图、循环嘴型或与新稿无关的讲话顶替。

已有侯总源片只有22.8–30.8秒是这段声音对应的有效动态口播。将既有声音/配乐按[26.8,30.8)、[0,22.8)、[22.8,26.8)重排，共30.8秒，语速不变。前4秒是周末邀请，中间22.8秒解释体验，末4秒给位置。开头与结尾人物视频使用同样源时间；中间只放真实现场，不显示不匹配的数字人。

实际素材/声轨由prepare.py核SHA后制360px/15FPS代理，记录原片和派生身份。原混音保留，输出声轨做不自动抬升的限峰，源PCM实测30.8秒、-13.5LUFS、真峰约-1.7dBFS；编码后的音频另核。切音位置位于已有语音边界，不做拉速、补字或新生成。

## 输入→动作→产物→gate→恢复

1. `prepare.py --source <暖光本期目录> --data <本次私有目录> --ffmpeg <运行时>`：核原SHA，制作七视频代理、字体和重排混音→episode/public→对照源区间、人物仅用同步动态8秒、无收费调用→已有原身份正确则复用，来源变化重新冻结。
2. `build_plan.py`、`build_specs.py`、单规格check_spec；宿主Node执行`render.cjs bundle <data>`→五份规格和bundle→来源/人物时间/每拍动作预算/最短稳定期/字段与路径静态检查→只修改失败真值再构建。
3. `../../scripts/animation_story_previews.py --install-root <隔离副本> --data <私有目录>`→五条完整低清视频、同源关键帧、原队列和SHA/ffprobe→462帧/30.8秒/270×480/15FPS/AAC，逐条完整解码→由jobs/latest-job及原render.log恢复；结果未知不重复发起，已完成文件保留。
4. 解码全帧、抽取场景关键点及全部转场、持续听看→验证矩阵和本地预览→实际看图判主体/遮挡/风格，技术指标不替代听看；用户观感另验→只修失败项，不用另一条未经核对的视频冒充。

音轨交付步骤：`../../scripts/animation_story_audio_finalize.py --install-root <隔离副本> --data <私有目录>`从已完成的原任务和原PCM生成独立队列子任务，视频流逐包复制，声音降低3dB后编码128kbps AAC，核真峰值≤-1.5dBFS。原96kbps编码曾产生+0.1dBFS真峰，不能作为最终交付；本轮五条修订后均为-4.8dBFS，视频包哈希均不变。用`finalized-job.json`及其输出proofs恢复，不覆盖原任务回执，不重渲染画面。实际听感仍需单独确认。

## Gate、降级与交付边界

初版是当前输入的一组比较片。画布/声轨/真实人物范围已确定，因此可执行完整开发测试；与正式ready模板复用分开。各维度分别记在本次私有validation.json，未验证的声音听感、连续观看、真机、用户确认、换稿与正式入口保持待验。

可替换短标题2–6字；溢出先缩短，不缩成小字。现场素材至少五类；缺素材时保持上一有效主体并停止标记模板可复用，不插纯字页。人物缺少对应动态片段时只用现场旁白，不能把截图放进人物槽假装在说话。异常画幅需重新校准主对象裁切；原样片通过不自动证明任意新素材都通过。

新机、长短稿、缺素材和比例边界目前只做静态约束，不额外生成边界影片拖慢本轮五片比较。最终按用户选中的视觉与节奏继续，正式上架、高清交付和发布另验。私人原片、字体和人物不进入公开源码。
