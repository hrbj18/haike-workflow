# 科技控制台口播模板

文档类型：video-template-runbook。标准：video-template-v1。
模板规格：[规格](video-template-spec.json)。模板ID：`motiongit-console-story-v1`。
状态：`implementation + ready`（本轮受控范围）；已有完整声源两画幅已出片。本轮满幅人物、原生圆窗和30.4秒4:5整片已通过55预览/56编码状态实际检查、全解码与下载；不同新人物、新源API和真正第二期待验。
最近核验：2026-10-29，本机源码副本。原包：`template-04-dark-console@2.7.20-alpha.3`。

本手册用于五组完整原生动作：描边巨字、光环声明、六路实拍展陈、双面板比较、终端收尾。下期改文案和来源数据，沿同一会话服务、原生准备器与统一队列制作。

## 当前范围与真值

| 项目 | 唯一参数来源与边界 |
|---|---|
| 41个可编辑文案字段 | [profile.json](profile.json)；类型、长度、可选第三比较项、胜负值和多行正文由同一字段合同校验 |
| 原生组、锚点与停留上限 | [公开合同](source-contract.json)及本期官方`params.json/plan.json`；动作和退场保持原速 |
| 音频主时钟 | `studio_motion_console.fit_segments()`以完整原声、真实句间隙和0.2秒公共帧时钟分配合法完整组；规格30.4秒仅是验收实例 |
| 原比例 | 官方原生1920×1080/60fps，人物载体随原版动作 |
| 4:5 | 官方原生`portrait`先在1080×1920重新排版；最终视窗/输出只由`studio_motion_native_viewport.CONSOLE_45`持有。辅助顶部HUD省略，主文案、实拍、人物与字幕逐帧检查 |
| 人物显示 | `auto`保持原生；4:5支持`opening/closing/hidden`，默认开头大窗。项目自有`studio_console_presenter.py`和`presenter.js`持有窗口/显隐帧钟，开头最长3秒、结尾最长5秒，完整人声持续 |
| 人物源适配 | `studio_motion_presenter_framing.py`测量六个原源帧，取最大且保留头部的9:16窗口；原视频保留，另制720×1280 talk。随后`studio_motion_face_crop.py`按七个官方导入帧求圆窗，不把原视频坐标当导入坐标 |
| 声音 | 原生完整人声/SFX一次，另加一份明确BGM；`studio_dark_native`生成同一帧时钟母带 |

规格中的元素框是组件求值包络，叶节点几何与曲线由精确版本官方运行时决定。修改规格中的包络不会修改画面。公开工作流和原生五组分别记录身份，不用组件库样片证明原生复刻等价。

项目出镜层位于外层`haike-composition`，官方内层工程的文件集合和源码保持完整。官方预览作为原生对照，最终交付画面另存并绑定同一原生预览SHA；两组都实际检查。导出用同一JS和帧钟合成画面，沿用官方声音，不能把原生对照的小圆窗误称最终出镜设计。最终版本与本期完整编码验收见根`docs/STABLE_THREE_TEMPLATES.md`及本地交付回执。

**当前取景链路已在已有完整亲子源实跑。** 新建/复制控制台实例及新人物源交接自动清除旧裁切并绑定人物SHA，不需用户写私有参数；`source-frames`先测六个原源帧，生成六幅实际FFmpeg满幅取景图，和原图一起审核。编译器只把同一原视频取景为9:16，保留原文件和完整原声；本轮旧/新talk及两条最终成片的AAC分别逐字节相同。取景、头像同声源证据和官方圆窗是三个不同对象，不能互换SHA。

首次计划审核后，公开有界preview真正导入人物（prepare只写准备文件）；再测七个720×1280导入帧，另存圆窗参数、七幅诊断和新计划。若仍返回`plan_review`，重新读取token，看齐新增诊断并再次`plan-review`，不能沿用旧seen。正式预览逐SHA验证七个重新导入帧。圆窗在保留实测头部/头发边界的条件下重定位，不通过缩小窗口掩盖越界；无脸、多脸、大幅移动或无合法窗口时明确失败。

早期未满幅人物的12态、55态候选及公开参数对照均保留为失败证据，不能拿检测成功代替原生呈现。当前满幅版实际查看六幅取景、七幅导入诊断及全部55个最终4:5状态：正常大/小圆窗顶部黑带已消除，原生短暂载体变换和退场仍保留。不同人物/新源API、完整成片/连续声画各自另验，不从当前同稿诊断推定正式第二期已通过。

合法原包、工具与参考输入由本机忽略配置`.local/motion-console/defaults.json`提供。原包、私人素材、人物、凭据与运行缓存不随公开源码分发。另一台机器先绑定自己的合法资源并重新验收。

## 每期制作

先读根`START_HERE.md`与生产端Guide，核对健康接口的workspace/edition。网页入口是现有模板选择中的“科技控制台”，独立地址为`/motiongit?section=templates`。其他本机Agent使用同一[HTTP/CLI契约](../../docs/MOTION_TEMPLATE_STUDIO.md)。

| 顺序 | input → action → output | 完成条件与恢复 |
|---|---|---|
| 1. 建立本期 | 看原版和当前能力；创建会话、从已保存变体新建，或读取原会话继续 | 保存本期id/revision和原包SHA；导入/验签成功不能代替模板接入。原包版本变化先重新适配 |
| 2. 绑定声音与人物 | 已有完整同声源输入可复用；新稿选择项目音色或上传完整录音，沿现有配音/ASR/数字人服务报价与生成 | 文案、原声SHA、真实词时码与完整人物相符；新费用按本期明确预算。未知付费结果查原job，版式修改保留已付费源 |
| 3. 替换内容 | 修改本期41槽；上传六路视频与实际入点，明确BGM | 每路实拍可用长度覆盖完整`works-fan`；素材内横幅文字属于固化实拍，不自动成为本期承诺。画面文案由Agent按台词语义编写 |
| 4. 检查来源 | `source-frames`读取素材与完整人物代表帧，人物适配时附六幅满幅图；看齐后`source-review` | 素材/台词匹配，头发/下巴完整、无补边，人物原源/派生取景身份齐全；更换来源重新审核 |
| 5. 计划与预览 | `prepare`及首次`plan-review`；新人物自动导入测量后返回新plan，实际看齐七诊断和源图，再次`plan-review` | 每次取当前token/seen；完整组/退场/真实素材范围通过。4:5预览包含全部字幕中段、原锚点及进退场 |
| 6. 审核与冻结 | 实际查看本期全部最终画幅图，提交`preview-review` | 4:5图须精确等于本期原生源图的冻结视窗，全部主文案/人物/素材/字幕完整；源图与省略HUD的审核范围分开写明 |
| 7. 导出与交付 | `submit`进入原native统一队列；读回原job、作品版本及video_url | 队列completed且文件存在、全解码/尺寸/帧率/帧数/音频通过；实际检查编码状态并连续听看后分别登记。失败`resume`原job |
| 8. 下期复用 | 审核冻结后`preset`保存命名变体；下期带preset_id新建或clone，再换本期输入 | 参数完整保留，旧源审核、预览、费用授权和制作任务不继承。实际换稿换料成片后才登记第二期通过 |

完整五组无法容纳新口播时，读取实际容量错误后重选已支持编排或适配新组合。保留原速完整语音和整组动作；素材不足时补真实来源。

中立客户端从仓库根调用：

```powershell
Haike_video/.venv/Scripts/python.exe Haike_video/scripts/motion_templates.py catalog
Haike_video/.venv/Scripts/python.exe Haike_video/scripts/motion_templates.py create --template motiongit-console-story-v1
Haike_video/.venv/Scripts/python.exe Haike_video/scripts/motion_templates.py get <本期mts编号>
Haike_video/.venv/Scripts/python.exe Haike_video/scripts/motion_templates.py review <本期mts编号>
```

后续写操作用`action <本期mts编号> <动作> --data <本期JSON>`；支持动作和上传参数以`--help`为准。先取当前revision，审核seen必须对应实际看过的本期全部图片。网页、HTTP和CLI操作同一会话和同一队列。

## 故障与恢复

| 现象 | 判断和恢复点 | 复验范围 |
|---|---|---|
| 新稿仍绑定旧声音 | `reuse_matches_script=false`；切到项目生成或完整本期录音，跟进原源任务 | 完整字幕、声源/人物SHA、计划和画面 |
| 新人物圆窗不正确 | 查看六幅满幅图、七幅导入测量与原生预览；检测不可靠直接失败，不用旧crop顶替 | 稳定大/小圆窗、进退场及标题避让；原源保留，不重做已付费人物 |
| 视频不足或句子跨组 | 读实际区间/完整组容量错误，补素材或调整已支持编排 | 全使用区间、真实句间隙、原生尾部 |
| 准备进程中断 | 读取原会话operation及本地版本目录，`local-resume`；仍在运行时跟进原操作 | 当前本地阶段，不重复云生成 |
| 圆窗测量后重试 | `local-resume`保留与本期原token/源图及当前计划SHA匹配的既有审核回执；未知或已改计划不继承 | 原有导入复用，成功后新圆窗另存新计划，不自动审核新诊断 |
| 队列运行中 | 查询原job和当前进程；观察超时不代表失败 | 原任务，不另开整片重做 |
| 源码/依赖在冻结后变化 | 保留旧请求；沿当前代码和同一已完成源重新准备/冻结新版本 | 受影响计划、预览、几何和导出；已有成片独立保留 |
| 4:5图与窗口不同 | 核对viewportReview、源图/裁切图SHA和逐像素对应 | 所有最终画幅状态，重新冻结 |
| 作品下载默认404 | 未确认最终版时带本期version查询media；先核真实文件/版本 | 下载与版本对应；不为补证再生成视频 |
