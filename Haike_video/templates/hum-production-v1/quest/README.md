# 任务口播 · 蓝白游戏字幕

文档类型：video-template-runbook
标准版本：video-template-v1
模板规格：[规格](video-template-spec.json)。蓝白v7竖屏效果已获用户定稿确认，范围由[定稿约束](approved-look-v1.json)记录；通用引擎和扩展能力继续按各自验证范围使用。

这是对指定 Vlog 参考的独立组件实现。借鉴蓝白黑节奏、游戏式对比和任务提示、解锁路径与人物变窗；不包含原作者人物、标识或 MotionGit 内部核心。当前十五种动作见 `layout.json.kinds`，独立横屏与9:16坐标见同一文件。4:5尚未接入此新风格。实现、实际样片和待验范围分别见[本机验证](VALIDATION.md)。

当前使用已有 `hum-production-v1` 的音频主钟、来源预检、冻结请求、独占生产队列、混音和编码器。唯一新增风格为 `props.visualStyle=quest`；场景使用 `module=quest` 和 `quest={kind,items,cues,accent,chapter,presenter}`。`cues` 是场景局部整数帧，需明确编排；不能声称它们由未提供的ASR自动生成。标题/字幕/人物/实拍均可替换，字幕和人声仍由同源真实时钟约束。

## 持续对象与动作

- `comment`：自拟提问署名、全文、输入起止帧；输入后依次出现已审素材的照片证据，保留最后一张的阅读窗。界面明确标注自拟提问，不冒充真实观众评论。
- `ranking`：`orders`声明每次完整原编号顺序，18帧换位；`strikes`引用原编号，划除跟随条目。必须写排序依据或示意说明，不把原片观点充当统计事实。
- `path`：`items`是固定节点，`cues`对应`path.stops`，移动时长12–45帧。相邻场景的相同图ID保留演员位置和已走路线；节点意义不可更换，重新讲述须显式`reset`。跨越中间节点不将其标成已完成。横屏路径降低到标题之下，竖屏按节点数拉开距离。
- `versus.variant=panel`是共享对战面板；`unlock.variant=tree`是同根二至三分支逐项变蓝。`radar`与`editor`分别明确标作扫描/编辑流程示意。
- 下一场的`transition=checker|iris`在上一场末12帧覆盖背景；棋盘从右向左，字幕与持续数字人在上层。`clear.photoIds`使用3–5张已审素材缩略图，围绕人物并避让当前收尾文字。

完整媒体窗口按来源方向重排：横屏装入竖素材时使用高窗与侧面说明，不能把竖画面塞入很宽的低窗后声称已适配。路径和横屏高窗/榜单/扫描/分支树使用单行标题；长内容留在完整字幕或拆镜头，不自动缩小字体。

9:16路径可选绑定场景`mediaId`，在保留同图移动、节点和黑白接力的同时显示右侧原片；位置由`layout.json.portrait.pathMedia`给出，坐标相对content。节点文字按实际44px字体核对左栏容量；此组合尚不开放横屏。路径中的大人物卡使用同文件`pathPresenter`画布坐标，避让左侧节点与底部字幕。工作台“实拍素材（保留当前动效）”可替换绑定，不需要换掉路径动作。没有mediaId的旧路径保持原来表现。

`headline`的竖素材使用高窗与侧边强调；高窗按标题行数、画幅和人物卡片避让。`timeline`节点使用固定32px字体，竖屏最多三行、横屏最多两行，真实字体超过容量会拒绝；结论与节点分别留框。`books`最多四本，以包含内边距的固定高度堆叠，横竖分别排布。这四种动作的边界图验收见VALIDATION，不能替代新一期完整视频检查。

## 核对与冻结

输入：完整PCM口播、同声源字幕、已审原始素材与真实窗口、可选数字人、字体、配乐与来源记录。运行 `Haike_video/.venv/Scripts/python.exe Haike_video/scripts/hum_production.py --input <input.json> --check`。通过条件是来源SHA、窗口、整数帧、字体容量与标签/动作时长均有效。缺素材或内容溢出会拒绝，不用缩字、循环或冻结补齐。已有付费产物保留。

## 开发样片与整片

使用同一脚本去掉 `--check`，可指定 `--output-dir`。脚本冻结素材和渲染器身份并经过统一队列输出；新增云服务调用为0。当前规格阶段只执行本次已授权的开发验收，完成实际技术/视觉证据后才提升可日常复用状态。中断从已保存的 `--request <request.json>` 恢复，避免重新生成上游配音/数字人。

## 验收与交付

核对每种本期使用动作的入场、中段、结果停留和离开；检查实际横竖布局、人物主体、字幕与实拍。再核对成片流、时长、全解码、>=20Mbps视频流和混音。技术、抽帧、连续听看、真机和用户审美分别记录。私人素材和个人.motion封套不进入公共模板。本机实际成片与抽查范围见VALIDATION；连续听看、口型和真机仍独立待验，不能仅凭参数校验或组件测试宣称成熟。

工作台“动效模板库”中可找到“蓝白任务口播”，制作页面选择“内置 · 蓝白任务口播”。它由项目源码提供，无需下载.motion。复制本期草稿可继承镜头和素材绑定；新建初始参数只有编排示例，绑定完整声音、真实字幕与来源后才能制作。

本轮新增[正式七镜预设](../../motion-presets/README.md)：从版本化配方新建独立草稿，再绑定本期声音、真实字幕、素材和事件帧，无需制作机器的v7草稿。已有已完成草稿仍可复制复用。升级包与升级后整片验收尚在实施，见[复用方法](../../../docs/MOTION_TEMPLATE_REUSE.md)；画面内容、同源素材与台词可以换，不能为了增加实拍而删除原来的持续路径或换位编排。

失效触发：组件、布局、字幕、动作节点、声音或素材改变；冻结新版本并只重验受影响项。历史例片不代表新稿、另一人物或异机验证。
