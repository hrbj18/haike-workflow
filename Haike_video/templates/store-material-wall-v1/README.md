# 店长账号·动态实拍素材墙

文档类型：video-template-runbook  
标准版本：video-template-v1  
模板规格：[规格](video-template-spec.json)  
状态：开发验收；`implementation + specification`。技术、视觉、连续听看、真机与用户确认分别记录。  
最近核验：2026-10-26；实际核验范围以本期冻结项目和产物证据为准。  
适用范围：1920×1080、30fps 的无口播素材墙短样；实拍封面卡片依次入场，分类与选择引导同一卡片放大播放，再缩回素材墙。  
权威入口：[实现](index.tsx)、[类型](types.ts)、[布局](layout.json)、[适配器](../../backlot/studio_store_material_wall.py)、[项目入口](../../AGENT_GUIDE.md)。

这是项目自有的可编辑视频模板。MotionGit 公开示例作为级联、选择、窗口变形与阅读停留的参考，本模板保持原 `.motion` 不变；不携带受保护代码，也不宣称原包支持实拍导入。素材墙是本片的视觉组织方式，不是某个已上线软件界面的操作证明。

前一版 4:5 单镜头展示路线及其独立样片仍保留：[实拍动效短片](../store-motion-showcase-v1/README.md)。两份模板分别维护，不把前版验收范围继承为本素材墙通过。

## 输入与参数真值

`types.ts` 定义字段，`layout.json` 与 `index.tsx` 定义空间、状态和动效，适配器定义冻结、队列、素材与声音门禁。正文说明参数职责，具体值从这些入口读取。

- 每张卡片绑定稳定 ID、分类、短标题、真实原片与实际源区间。封面来自该原片的明确源时间点，记录原片 SHA、抽帧时间与封面 SHA。
- 分类标签、卡片顺序和每次选择的卡片均可编辑。一次展开周期持续引用同一卡片 ID：先选中，再放大该卡，再播放它绑定的原片，最后返回同一卡位。
- 展开时使用 `contain` 保留完整机器人或门头；封面裁切可以不同于展开窗，但须实际查看，不能用封面代替采用区间的内容审核。
- 时间全部映射到最终 30fps 输出帧。各展开周期不重叠；播放使用原速源区间，素材不足时补选镜头或调整时长，不用循环、冻结或变速填满。
- 所有原片音轨静音，最终声音仅来自同一 `master.wav` 的音乐与动效音效；本模板不接入旁白、数字人、TTS 或 ASR。
- 品牌、标题、分类和地点只使用本期明确内容。原片内固化的店招、活动横幅和人物保持原像素，不能据此推出未确认的当前活动或服务承诺。

[示例参数](props.example.json)仅展示字段和状态顺序，未携带媒体、授权凭据或本期审核证明，不能直接作为已核验生产输入。

## 当前操作

命令从单仓库根目录运行。便携副本先按根安装入口初始化运行时，再使用本副本 Python。

### 1. 核对卡片、封面和原片

- `input`：本规格、本期 props/来源映射/标题 JSON、原片、封面、无口播母带及逐项回执。
- `action`：核对每个卡片 ID、分类引用、封面抽帧源身份和采用区间；实际查看封面与采用区间代表帧，保留来源、方向和 SHA。
- `output`：卡片与原片一一对应的本期输入、封面来源记录、实际观看证据和音频回执。
- `gate`：安全文件名和必需输入完整；分类与选择引用有效；封面确属相应原片与时间点，展开播放有足够原速素材；母带精确覆盖同一帧钟，明确无口播、原声静音、零云调用、不发布。
- `recovery`：补齐具体缺项并保留已完成素材。更换原片、封面、源时间或裁切后重新核对受影响证据。

### 2. 冻结并通过统一队列生成短样

```powershell
Haike_video/.venv/Scripts/python.exe -X utf8 Haike_video/scripts/store_material_wall.py --input 本期输入.json --output-dir 本期交付目录
```

- `input`：通过门禁的本期 JSON。
- `action`：`prepare` 复制并校验素材，冻结参数、封面来源和当前实现身份；`submit` 进入 `studio_investment_recompose` 本地合成通道，合同为 `store-material-wall-v1`。指定原任务由统一队列执行器领取后调用项目 `VideoCompose/Remotion`。
- `output`：冻结请求、原队列编号、完整编码短样、技术 QA 与作品候选记录。
- `gate`：队列和文件身份对应；素材墙、选中、放大、播放、缩回顺序覆盖本期声明范围；完整解码、尺寸、帧数、帧率和时长匹配冻结输入，视频流实测至少 20Mbps，AAC 真峰值不超过 −1.5dBTP。
- `recovery`：先读原请求和原任务，复用已完成本地产物。输入或实现变化时新冻结，保留旧工程和成片。此命令没有付费生成或真实发布步骤。

### 3. 检查原请求与恢复

```powershell
Haike_video/.venv/Scripts/python.exe -X utf8 Haike_video/scripts/store_material_wall.py --request 冻结请求.json --check
Haike_video/.venv/Scripts/python.exe -X utf8 Haike_video/scripts/store_material_wall.py --request 冻结请求.json --output-dir 本期交付目录
```

- `input`：实际返回的冻结请求路径及原队列编号。
- `action`：先用 `--check` 比较当前项目、素材、封面、实现与已有产物身份；通过后从同一请求继续。
- `output`：原任务当前状态或同 SHA 的已有结果。
- `gate`：不把新卡片或新时间线塞进旧请求，不覆盖不同 SHA 的历史成片；完成文字与实际产物同时存在。
- `recovery`：恢复缺失的同指纹文件；有意改动则新冻结。渲染错误不触发配音、数字人或其他云调用。

### 4. 验收并交付

- `input`：完整编码视频、冻结输入、技术 QA、封面来源记录、声音分轨和关键状态帧。
- `action`：查看级联开始/中段/完成，每次分类选中、卡片选中、放大中段、完全展开播放、缩回中段及返回卡位；核对全程同一卡片身份和原片内容。完整播放核对节奏与阅读停留；独立检查音乐/音效、首尾淡化、AAC 峰值及单声道折叠。设备外放、用户确认和平台呈现另验。
- `output`：实际看帧/播放范围、逐项结论、最终 SHA 与可播放交付。
- `gate`：静态图、计划 JSON、文件存在和队列完成都不代替实际动效检查；声音测量不代替听审。所有适用维度分别写通过、失败、待验证或不适用。
- `recovery`：定位具体卡片、状态和输出时间；修改参数真值后生成新版本，只复验受影响和关联范围。

每期保存冻结请求、卡片/封面来源、逐镜使用清单、音频回执、props、队列、技术 QA、实际观看记录及最终 SHA。私人原片、成片、凭据和运行日志留在忽略目录，公开模板仅含实现、规格与示意参数。

| 现象 | 阻断依据 | 恢复与复验 |
|---|---|---|
| 选中与展开不是同一卡 | 卡片 ID、封面与播放源映射不一致 | 修正本期引用，查看选择到缩回的全部边界。 |
| 封面变更或不属于原片 | 来源 SHA、抽帧源时间或封面 SHA 不符 | 从明确原片时间重新抽取并新冻结，保留旧封面。 |
| 分类引用失效、时间周期重叠 | 参数门禁不通过 | 修正分类与周期，重新核对完整状态顺序。 |
| 展开后主体被裁、标题被截 | 实际画面不符合完整性或可读性 | 调整已开放布局/短句并重验，不静默缩字或裁词。 |
| 原声说话混入 | 不符合无口播合同 | 保持所有实拍静音，核对母带及导出映射。 |
| 编码成功但缺音乐或动作 | 音频/视觉 gate 未通过 | 保留工程与原任务，修复对应阶段后验收实际成片。 |

实现、布局、封面身份、原片、字段边界、字体、主时钟或混音策略变化后，重验受影响维度。本页不追加逐次任务日志，也不升级其他模板的核验状态。
