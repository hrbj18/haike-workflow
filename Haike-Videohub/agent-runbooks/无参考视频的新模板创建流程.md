# 无参考视频的新模板创建流程

文档类型：operation-runbook
流程版本：1.1。
状态：待验证；创建方法取自既有模板设计与验证记录，本版统一流程尚未另用一个全新模板完成端到端实跑。
最近核验：2026-11-05（依赖恢复、封面接口及隔离界面；不代表新模板全流程或异机验收）。
适用范围：用户希望从零创建视频模板，没有具体参考视频，希望基于项目审美资源和现有动效提高设计效率；也适用于项目更新后继续创建新模板。已有模板精确复刻进入其原runbook和精确版本合同。
核验条件：当前源码提供Hallmark视频方向、taste-direction、动效选型目录及统一复刻合同；每次执行重新核对当前副本、实际实现、许可和依赖。本流程不固定组件总数、旧端口、24秒片长或某个主题。
权威入口：[依赖合同](../contracts/template-authoring-dependencies-v1.json)、[模板标准](视频模板编写标准.md)、[审美方向](../../Haike_video/skills/creative/hallmark-video.md)、[taste-direction](../../Haike_video/skills/meta/taste-direction.md)、[动效目录](../../Haike_video/motion-components/catalogue.json)、[统一复刻契约](../../Haike_video/docs/MOTION_REPLAY_STANDARD.md)。
完成证据：本期设计合同、实际选型与调用绑定、实现规格、同源可播放样片、关键状态及边界检查、分项验证、版本冻结与恢复入口；进入画廊还须完成下述源码封面与实际接口验收。历史依据仅用于解释方法。

固定执行过程，开放设计结果。没有参考视频时，以本期内容、视觉体系、可检查的动作机制和实际样片建立依据。Agent负责选择、组合和实现，用户比较有完成证据的方案；常规步骤由Agent连续推进，费用、发布及生产范围沿用项目当前授权。

可直接交给Agent的任务句式：“按《无参考视频的新模板创建流程》创建一个新模板。主题/观众是……，画幅/目标时长是……，可用素材是……。你负责选择审美方向与动效编排，交付可播放候选、设计理由、编号版本及恢复记录。”没有填完的非阻断项按步骤1处理。

## 新电脑接入（Windows / macOS）

本流程由**两份项目内skill＋项目现有能力**组成，MD规定Agent怎样做，[依赖JSON](../contracts/template-authoring-dependencies-v1.json)规定读取哪些文件、如何核对来源与恢复。没有另建工具包、安装器或渲染路线。

1. **取得项目并恢复skill。** 在用户提供的源码或发行包根目录读取本MD和依赖JSON，按仓库根解析路径。两份skill缺失时，Agent主动按`skills[].download_url`下载到临时目录，逐字节校验`sha256`后写入`path`指定位置；摘要匹配的已有文件直接复用。下载来源固定在`download_source.commit`，不自行替换为远端最新版。其他项目能力缺件按目标版本原安装入口恢复，不能只下载两个skill便宣称项目已可运行。
2. **准备本机环境。** 按当前项目入口使用其Python、Node、依赖锁、渲染浏览器及本期字体。Windows区分源码/便携入口；macOS用本机运行时安装锁定依赖，沿所选组件当前构建入口执行，不运行`.ps1/.cmd/.exe`或搬入Windows的`node_modules`。无需在Agent全局目录另装两份skill。
3. **核对现有能力。** 用目标机实际Python从仓库根执行JSON中`project.checks`列出的脚本及参数，查看参考库摘要、动效目录及源码检查结果。逐个核对本期选中动作的源码SHA、宿主依赖和适配器；公共组件已有固定来源清单，私有TalkCraft按所选动作需要恢复，不作为所有新设计的前置。安装和只读检查不产生付费调用。
4. **沿本文创建。** 用目标机本期合法素材和字体，从步骤1连续完成设计与样片；先验证开头和关键状态，再完成声明范围。交接记录目标系统、实际身份、可播放样片及分项结果；静态检查通过与新电脑真实跑通分别记录。

**参考库自动恢复：** Hallmark目录缺件时，Agent从`references.download_base_url`取得`UPSTREAM.json`，先核对`integrity_manifest_sha256`，再逐项按其`files`中的相对路径下载、核对摘要并落入`references.root`，包含主题MD/JPG、目录与许可。解析路径须保持在该目录内，下载和落盘使用字节。清单原摘要匹配时直接采用；仅对`text_transport_recovery`登记的两个文本文件，字节摘要匹配`download_sha256`时，按声明恢复UTF-8 CRLF字节，且恢复后必须等于UPSTREAM原摘要，才允许落盘。新克隆中已存在且符合该输运摘要的文件同样适用，先将其原字节备份到忽略目录再恢复。这用于还原Git规范化的换行，不放宽校验。其他已有文件不匹配时保留现场并核对版本，校验失败或网络不可用时停在缺件恢复点，不能把下载失败标为安装成功。该步骤由Agent调用现有网络与文件工具执行，不要求额外安装全局skill。

交给新电脑Agent可直接说：“先读取`Haike-Videohub/agent-runbooks/无参考视频的新模板创建流程.md`和它的依赖JSON，核对本机项目与依赖，补齐缺件后按本文创建模板。沿用已有项目入口，不另建工具链；真实付费和发布按本次授权执行。”

## 1. 接单：先确定要解决的观看问题

读取生产端[AGENTS](../../Haike_video/AGENTS.md)及Guide，再按模板标准确定本次是设计规格、开发候选还是正式制作。已有任务先读原设计和冻结输入，从未完成阶段继续。

把以下内容写入本模板的`DESIGN.md`；缺少且不阻断开发的参数由Agent作合理假设并注明，只有缺失会改变目标、费用或实际执行能力时才询问：

| 输入 | 必须写到的程度 |
|---|---|
| 用途与观众 | 谁看、要理解什么、最后记住哪一个关系或观点 |
| 内容样本 | 本期稿件或代表性示意内容；事实与示意区分；有口播时取得真实音轨及ASR后冻结最终时间 |
| 输出与角色 | 画幅、帧率、平台、目标时长范围，是否有数字人及其主角/辅助角色，字幕和品牌职责 |
| 素材条件 | 实际可用视频/图片/图表/屏录及授权来源；查看代表帧，确认动作、主体位置与真实长度 |
| 交付范围 | 低清样式候选或完整正式片；预算、允许调用的服务；可复用的已有音轨、人物和素材 |
| 差异目标 | 相对哪套已有模板改变主体组织、空间、动作过程或节奏；只做同款变体时直接声明变体 |

无正式稿可先用示意时钟开发，标为设计假设；正式声音到位后按真实语义重排并定向复验。正式输出读[画质与混音标准](../../Haike_video/docs/VIDEO_QUALITY.md)，检查代理与正式源分别登记。

**完成条件：**能用一句话说明“让谁看懂什么”，素材条件可定位，当前交付范围和未知项明确。恢复时读取同一设计合同，不重新生成已确定输入。

## 2. 定审美：先建立视觉合同，再动手做动画

读取Hallmark视频方向和taste-direction。Hallmark用于提供可分析的配色、材质、字体关系与构图参考；taste-direction用于确定变化程度、运动强度和信息密度。

1. 从本地[Hallmark目录](../../Haike_video/design/hallmark/catalog.json)筛选与内容匹配的方向，至多比较三个；实际阅读主题MD并查看JPG。已有品牌体系优先，匹配不到可自定义视觉方向，仍填写下面的合同。
2. 写一段具体的`design_read`，例如“用可游览的路线串起三次真实体验，让观众把现场理解为一个过程”。再确定三个1—10整数：`visual_variance`、`motion_intensity`、`information_density`，分别说明它如何影响布局、动作和阅读。
3. 把方向落实到背景/文字/强调色职责、中文字体来源、标题层级、间距与框线、材质、素材适配、人物/字幕避让。Hallmark网页尺寸、英文字数与交互规则按视频目的转换，画幅服从本期规格。
4. 为每类场景指定可查看的依据：主题图、真实素材代表帧、现有组件动作或自绘构图草图。没有外部参考视频时，把新构图和新时序记为“设计”，而不是“观察复刻”。

将主题slug、来源版本/摘要、选择理由、`taste_profile`及具体视觉决定写入`art-direction.json`或本期既有计划的对应字段；`DESIGN.md`解释取舍并链接该真值。同一参数只由一处持有。

**完成条件：**每个审美词都有画面决定和核对方法，能说明为什么适合本期内容。恢复时保留原方向；实际画面不成立时修改对应决定并记录影响范围。

## 3. 构思：让Agent提出动作机制，不从色板复制时间线

在编码前写最多三个简短方向，每个方向回答五件事：

- 主体是什么，以什么可见形态组织；
- 空间怎样变化：固定画心、轨道、折页、路线、镜头巡游或其他与内容有关的机制；
- 开场发生什么标志动作，后续怎样发展；
- 核心信息怎样从上一段交接到下一段；
- 为什么这种组织方式能帮助观众理解内容。

Agent根据内容适合度、素材可实现性、视觉记忆点、阅读与开发成本选一个实现，保存选择和放弃理由。用户已指定方向时直接深化，不额外制作多个候选。新方向可以组合已有动作、改变空间关系、设计新动作；动作数量和组件覆盖率都不是目标。

| 创建时应固定 | 交给Agent设计 |
|---|---|
| 内容事实、素材身份、实际能力、版本和授权 | 视觉隐喻、构图、镜头组织及场景家族 |
| 清楚主体、阅读预算、字幕/人物安全区 | 主辅动作组合、节奏与运动语言 |
| 真实时钟、可复现实现、验证与恢复 | 主题转译、自定义图形及有理由的风格突破 |
| 用户确认后冻结的模板与开放槽 | 定稿前候选的局部探索；实质修改建立新候选 |

**完成条件：**选中方向描述了可见的动作过程，能与最近的已有模板比较。只有色彩或字体区别时按变体交付，或继续改变编排。恢复时从已选机制推进，普通修复不重开全部构思。

## 4. 选动作：编号必须连到实际机制与版本

先查询[动效目录](../../Haike_video/motion-components/catalogue.json)，再阅读候选实际源码和设计参考。按本节记录来源、采用方式、实际实现、取舍与阅读预算。运行时选择以本期实现为准，以下命令从仓库根执行；便携包使用其初始化环境中的Python替换解释器路径。

```text
Haike_video/.venv/Scripts/python.exe -X utf8 Haike_video/scripts/motion_catalogue.py list --query 路线
Haike_video/.venv/Scripts/python.exe -X utf8 Haike_video/scripts/motion_catalogue.py list --mode direct
Haike_video/.venv/Scripts/python.exe -X utf8 Haike_video/scripts/motion_replay.py catalog
```

两类编号承担不同职责，均按当前文件读取，目录行号及列表下标不作为稳定编号：

| 身份 | 用途 | 本期必须绑定 |
|---|---|---|
| 组件目录ID，如`talkcraft:map-route-pin` | 查找动作语义、来源和可用运行时，为新设计选型 | ID、目录revision及文件SHA、组件source SHA；存在参考文件时记录其SHA；`direct/adapt/reference`与实际实现位置 |
| 模板内部动作ID，如`haike.chromatic-six-11.route-start` | 定位特定模板中的已实现动作、对象与内部事件，用于原样复刻及受控复用 | `template_id`、模板精确version、动作ID及动作精确version、源码SHA、真实符号/适配器、能力范围 |

组件目录当前用来源SHA识别源码修订，不虚构统一的语义版本字段。模板动作的精确版本从[复刻注册合同](../../Haike_video/config/motion-replay/)读取。画廊展示编号只帮助人查找，实际身份由合同解析。

按`haike.motion-selection/1`写`selection.json`，结构参照现有[真实视频选型](../../Haike_video/templates/chromatic-six-video-batch-v1/window-c/selection-11.json)，参数以本期值填写：

- 每场记录`purpose`、`subject`、`handoff`、`from/to/stableFrom`及真实考虑过的备选理由；
- 每个选中动作写来源SHA、`mode`、`reason`、`implementation`、`verification`，适配另写`changes`；
- `direct`表示真实运行时调用，`adapt`说明改了什么，`reference`只提供设计依据；实际调用图、代码符号和样片证明执行；
- 目录外的新动作先在独立候选中实现、命名、留证据；需要进入统一选型时按目录实际生成器及来源规则新增，并通过当前检查。原模板内复合动作先核对可拆性，开发新适配后才能作为可组合组件。

例如6–11历史原旁路的动作是不可分割的固定编排，`action_ids`只接受原完整顺序；它可以定位既有动作，却不授予任意换序、拆装或变长能力。其他版本以[统一复刻契约](../../Haike_video/docs/MOTION_REPLAY_STANDARD.md)指向的精确合同和实际适配器为准。私有上游的来源、许可和恢复条件按其现行规则处理。

**完成条件：**每个已实现动作能解析到当前实际执行位置和来源身份，模式与能力相符。缺必需来源时阻断依赖该来源的动作；新设计可显式改选并更新合同，旧模板精确复刻保留原身份并报告缺件。

## 5. 排分镜：用语义决定时长，用阅读期约束运动

先为每场建立以下表格，再把最终参数写入实现规格和选型真值；设计表可以引用这些字段，避免维护重复数值。

| 场景 | 观众此刻要理解什么 | 主体与状态 | 主动作/辅助动作及ID | 建立→强调→交接 | 落定与阅读区间 | 素材源范围/字幕/人物 |
|---|---|---|---|---|---|---|
| 本期实际场景ID | 一句话目的 | 对象ID、父级、画面位置与裁切 | 精确身份及采用方式 | 实际全局帧与局部事件 | stableFrom、结束帧及阅读依据 | 槽ID、源帧、遮挡及声音职责 |

每场首帧保留背景、主体、轮廓或明确构图作为视觉锚点；主体可辨后再补装饰。每拍一个主要注意力中心，辅助动作服从主体，保留跨场连续项，主动效后提供稳定阅读；同一模板统一运动方向、曲线与幅度。阅读期按本期文字与语音确定，不能把历史`minReadingFrames`当作所有稿件足够阅读的证明。

有声音时以完整真实音轨和ASR语义事件为主时钟；先安排信息，再安排动作。示意候选的固定秒数只属于该样片。时长改变时根据语义增加/减少节拍、重新分配场景与阅读期；短稿优先减少辅助动作，长稿发展场景关系，不能靠循环固定24秒时间线延长。只支持固定时钟的实现明确记录范围，变长另做适配。

主素材需要真实运动的任务，每个可见格均绑定真实视频。以实际解码长度检查每段：`sourceFrame = sourceStart + globalFrame - clipFrom`（同帧率、原速时）；采用起点含、末端不含区间。长度不足改选合法源段或声明顺序剪接，禁止用照片推拉、循环、冻尾或慢放冒充真实现场运动。人物按角色与当前模板规则安排，同源声音及可见域覆盖分别核验。

**完成条件：**全时钟连续覆盖，每场目的和交接明确，每个可见素材槽有合法源范围，文字有足够落定阅读期。缺少正式音轨仅阻断依赖其时钟的正式制作，仍可完成已授权示意开发。

## 6. 实现与短样：先验证标志动作，再扩展全片

1. 为新模板建立独立ID、候选版本及目录，按[Runbook骨架](视频模板Runbook骨架.md)写操作契约和符合现有schema的实现规格。源代码可复用底层积木，预览和正式出口消费同一组件、时间线、裁切与字幕合同。
2. 先复用已有授权素材、字体和成功音轨/人物；记录依赖锁、实际模块解析与源SHA。新付费素材沿项目供应商、预算与幂等任务规则执行。
3. 用实际存在的预览入口检查开头3—5秒和全片关键状态，覆盖建立、动作中、落定与场景交接；下一步扩展前先确认标志动作成立。声明独立编排或批量新方向时，两两比较主体组织、空间/镜头变化、动作顺序和节奏，至少三项有实际差异依据，颜色不计。现有预览脚本只在已适配本批入口时调用。
4. 使用本副本服务身份及可用端口，视频HTTP检查Range和解码。已存在可用预览与证据直接复用；正式父视频沿项目统一队列执行，开发脚本的存在不等于已接通生产。

**完成条件：**样片与规格/输入/源码身份一致，实际看到标志动作、中文字体和素材构图，主信息在稳定期可读。失败定位到元素、源段或时钟，只修对应项并复验其关联边界。

## 7. 评审：两次独立检查，失败项定向修复

沿项目Guide最多进行两次独立评审：一次结构/语义，一次视觉/输出；用户明确要求更多时再增加。这里是检查阶段，不要求额外启动Agent或增加用户逐步骤审批。

| 检查 | 必查内容 | 留存证据 |
|---|---|---|
| 结构/语义 | 实际动作解析与调用、信息顺序、素材覆盖、主次、开放槽和边界输入 | 规格/选型检查、调用位置、源时钟、最长/最短文案与异常比例等适用反例 |
| 视觉/输出 | 每场首帧、建立/动作/落定、转场、人物边界及尾帧；完整播放、随机定位、字体、裁切与阅读 | 实际查看帧与判断、可播放产物、分项检查；有声范围另记实际连续听看 |

对真实运动素材，在构图与相机稳定的窗口内，比较相隔至少约1秒的素材区域内容和源时钟；排除标题、卡片、数字人运动。短于该窗口的素材采用能覆盖其真实动作的间隔并说明理由。抽帧不代替连续播放，seek到尾帧不作为完整播放到尾的证据。

新模板与已有模板比较主体组织、空间/镜头、动作顺序、节奏；宣称独立编排或批量方向时按步骤6提供差异依据。清晰度、声音、口型、真机、生产接入和用户审美各自记录范围；自动通过或像素变化不能证明好看。

修复会影响观众理解或实际使用的问题，保留成功素材和已验范围；细微装饰差异可以记录。修复后只复验失败项及受影响边界，不重新开启整轮泛审。

**完成条件：**适用检查都有通过/失败/待验证/不适用结论及证据，实质问题关闭或有明确交付限制；用户可以直接比较完成的样片。正式定稿以用户对具体版本的确认记录为准。

## 8. 冻结交接：把创作变成可恢复的模板

### 进入画廊及main交付的完成条件

已有模板的“源码可用”“画廊可见”“实际可制作”分别验收。新的或实质改版的模板进入画廊时，执行以下闭环；已有模板升级只复用现成成果，不为封面重复制作视频：

1. **交付成片实际封面。** 已有成片时，直接复用对应视频原封面或选取已查看的代表帧，保留实际人物、素材、版式和文字；不能换素材重做演示图代替原成片。记录模板/画廊ID、当前选择版本、来源成片SHA及实际版本、截帧依据和图片SHA/大小/尺寸，确认分发范围。当前制作版本与来源片版本不同须分别记录；封面不能代替复刻、听看和异机验收。无成片的候选先制作已授权样片，未通过时明确候选状态。
2. **随源码携带并按ID绑定。** 动效公开图保存到 `Haike_video/templates/public-covers/`，更新该目录 `manifest.json`；原用户封面、样片和绑定继续保留。核对文件已进入Git提交/源码导出，而不是只存在忽略目录或待发资源包。使用main升级时，该步骤不依赖Release。
3. **干净副本实际检查。** 在没有原机器私有绑定的源码副本读取 `/api/studio/template-library`，确认本期新增模板没有丢失、分类正确；逐个请求poster，核对可解码、正确样式和清单SHA，打开该卡片的guide。当前18套首选用 `python Haike_video/scripts/motion_replay.py verify --preferred` 核对原来源及准备入口，展示对应成片；43张固定原封面及5张前端基础图也须保留。新候选按自身合同检查；不能只数条目或只检查HTTP 200。
4. **实际选择与准备。** 在实际构建的界面选模板、保存并重载草稿，确认精确ID/版本、原音频/人物/素材和参数保留；调用对应prepare核对返回的固定合同、producer/queue_admission及输入条件。空输入应明确阻断且不入队、不产生费用，不能静默走回普通口播。实际制作按模板既有入口和统一队列；界面保存/复制指令不代表一键出片已实现。
5. **区分验证范围。** 依赖/合同、封面、前端交互、准备/队列、短渲、完整视频及另一台物理机分别保存实际结果。当前可用探针是 `Haike_video/tests/backlot/test_studio_public_covers.py`、`test_studio_template_library.py` 和 `test_studio_motion_preferred.py`；测试通过不代替新模板的实际画面或连续听看。流程全量实跑仍须一个新任务的完整证据，不能因为增加本节就改为已验证。

同一模板目录保留以下职责；可以由现有文件承载，不要求为每项另造一套格式：

| 记录 | 必须可恢复的内容 |
|---|---|
| `DESIGN.md`＋视觉计划 | 本流程版本、目标与假设、审美skill/参考身份、机制选择和取舍；视觉参数由所链接的计划或规格持有 |
| `selection.json` | 当前动作目录身份、选型模式、真实来源、场景/阅读时序及实际实现 |
| 实现规格JSON＋模板runbook | 场景/对象/槽、参数真值、运行入口，按`input → action → output → gate → recovery`说明操作 |
| 验证与冻结记录 | 源码/配置/锁文件/字体/资产/输入/bundle或产物摘要，实际证据位置、版本和分项结论 |
| 交接入口 | 模板ID/版本、当前阶段、恢复命令及所需私有输入；存在统一复刻接入时附注册合同和动作绑定 |

源码checkout同时记录根提交；有dirty或未跟踪实现时绑定实际文件摘要，单个Git提交号不能代表当前运行内容。私有素材、凭据和逐次日志留在忽略目录，公共记录只保存允许分发的源码、身份和恢复条件。

模板需要进入统一复刻接口时，按[统一复刻契约](../../Haike_video/docs/MOTION_REPLAY_STANDARD.md)接入真实适配器、精确动作版本、内部事件、开放槽及调用方校验；注册JSON只描述能力，实际分派、准备与调用必须成立。没有完成接入的候选用自己的明确运行入口交接，标为尚未注册。

**完成条件：**另一Agent只读入口即可找到同一版本、输入条件与已验范围，必要来源可恢复；已知缺件有明确影响。定稿冻结后，变更实现、槽、时序或能力建立新候选，旧版证据保留。

## 项目更新后怎样继续使用

| 用户要做什么 | 解析与执行方式 | 必须重新验证什么 |
|---|---|---|
| 创建一个新的模板 | 沿本流程，读取更新副本当前目录/能力，再为本期锁定选中的ID、版本和SHA | 新组合的实现、实际画面与本期输入；旧组件通过不等于新组合通过 |
| 精确复刻已定稿模板 | 使用原模板runbook、原精确版本与实现/素材身份，保留同一对象、公式和时钟 | 来源完整性、实际准备/调用和关键动作；同输入优先用短区间对照原证据 |
| 用旧模板换稿或换时长 | 只填原适配器开放槽，按其已支持的语义重排能力准备 | 变化的素材/文字/时序、边界与全片覆盖；未开放能力交回作者适配 |
| 升级某个动作或渲染依赖 | 保留旧实现，建立独立候选精确身份，说明行为与兼容性差异 | 实际受影响的调用与输出，确认后再改默认；新版本不自动代替旧版 |

因此，流程可以随源码/发行包迁移，视觉结果靠精确实现和输入恢复。每次更新先检查本手册、所引用skill、目录、适配器、依赖、字体及合法资源是否实际到位；SHA漂移先定位差异，不就地回填旧冻结值。恢复原实现或建立新候选后，再验证依赖它的操作。

分发使用根[更新流程](../../docs/UPDATE_WITH_CODEX.md)和[交付边界](../../docs/DISTRIBUTION.md)。交付前在实际目标核对手册/引用文件、许可、必需组件及运行探针；本地新增文档尚未提交/发布时只对本工作区可用，不能宣称旧便携包或其他机器已经收到。迁移后完成一个明确新任务才记录该环境流程实跑通过。

## 方法依据与恢复示例

这是既有10/11模板的设计推导示例，不是新模板必须照搬的样式或固定时钟：

| 决定 | 10 黑柠节拍画报 | 11 深蓝蜜桃路线 |
|---|---|---|
| 审美依据 | Hallmark Brutal：暖白、黑色直角结构、柠黄强调 | Hallmark Blueprint：深蓝底、蜜桃路线、青色节点 |
| 编排机制 | 冲击开场→水平胶片动词接力→首词补句→三格收束 | 落钉→镜头巡游→步骤推进→缓拉全貌 |
| 来源选型示例 | `talkcraft:impact-open-title`、`talkcraft:word-relay-filmstrip` | `talkcraft:map-route-pin`、`talkcraft:step-timeline-vertical` |
| 适配决定 | 重点是字图节拍与稳定阅读 | 纵向折返保留更大的片尾素材；引线锚视频框边缘 |

历史选型可读[10选型](../../Haike_video/templates/chromatic-six-video-batch-v1/window-c/selection-10.json)和[11选型](../../Haike_video/templates/chromatic-six-video-batch-v1/window-c/selection-11.json)，对应实现边界见[10规格](../../Haike_video/templates/chromatic-six-video-batch-v1/window-c/template-10.spec.json)。正式要求见[系列正式版](../../Haike_video/templates/chromatic-six-video-batch-v1/FORMAL.md)，当前可执行精确版本从统一合同读取；历史记录不改写为新版实测，也不替代本期实际画面验证。

| 故障 | 判断依据 | 恢复点 |
|---|---|---|
| 只有“高级、科技感”等形容词 | 找不到具体对象、构图和动作过程 | 回步骤2/3补视觉合同与机制，再做短样 |
| 选了编号但画面没调用 | 来源引用存在，真实符号或消费链缺失 | 回步骤4补实际实现/适配及证据 |
| 关键主体变成细条或小点 | 实际裁切或全貌镜头中内容不可辨 | 定向修改框比例、焦点或世界构图，复验受影响状态 |
| 视频到后段静止或黑屏 | 可见窗口超出解码源范围，或定位失败 | 回步骤5修源范围/声明剪接，检查Range及实际源时钟 |
| 更新后无法恢复旧效果 | 版本、来源SHA、包或依赖不匹配 | 按旧身份恢复合法来源；不能恢复则明确阻断旧复刻，新候选另验 |
