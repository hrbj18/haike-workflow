## 触发条件与输入

- 中文触发：视频理解、快速分析视频、多宫格分析、抽帧看视频、分析参考片怎么复刻。
- 先读 [Haike_video 入口](../../Haike_video/AGENTS.md) 及其 guide；本手册是分析流程，制作阶段另按用户指定的生产呼叫名路由。
- 输入：本地原片或已导入项目的资产、要回答的问题、当前 agent 的真实模型标识。只有链接时先按相应下载流程取得原片；抖音见 [下载抖音视频](下载抖音视频.md)。
- 已有 `project_id`/`asset_id` 且结果要用于选材时走“项目路线”；只分析单个文件走“独立路线”。不要为了问答创建生产项目。
- 检查已有索引/任务是否属于同一原片、模型、问题和采样策略；完整结果可直接复用。问题或模型变化时重做判断，抽帧证据可复用。

## 当前操作

### 1. 选择最低够用的分析层级

| 目标 | 初始层级 | 升级条件与后续入口 |
|---|---|---|
| 看内容、风格、章节 | 文件探测＋多宫格概览 | 有小主体/文字/歧义时看原尺寸帧 |
| 拆参考片、上下换板 | 概览＋布局变化标记 | 切换处补密集帧；画面带旧字幕时单独判断处理方式 |
| 素材初筛 | 概览批量排除明显不相关素材 | 实际采用前走 V2＋源区间 QA |
| 口播提取、翻译、长视频找金句 | 概览定位＋已有转写 | 缺转写再按选定服务取音频证据；回听候选段 |
| 舞蹈、体育、操作演示 | 概览定位动作区间 | 播放区间或连续密集帧；不能只凭静帧判动作完成/因果 |
| 成片验收 | 概览查布局 | 连续播放、字幕时序、音轨/响度及技术 QA |

默认先概览，按目标补证据；满足本次问题即停止。ASR 是音频文字证据，画面文字来自画面核对，二者不能互相冒充。缺少播放器或音频工具时保留未知项，不声称已经听辨。

### 2. 独立路线：准备任务

在 `Haike_video` 仓库根目录使用项目 Python；Windows 可将 `python` 替换为 `.\.venv\Scripts\python.exe`。占位参数须替换为本次真实值。

```powershell
python scripts/video_understanding_cli.py prepare --source "<原片绝对路径>" --model "<当前真实模型标识>" --purpose layout --goal "分析版式变化并给出复刻建议"
```

- `--purpose`：`overview` 总览、`layout` 版式、`material` 素材初筛、`speech` 口播、`motion` 连续动作、`qa` 验收。
- 默认产物位于项目忽略目录 `.backlot/video-understanding/`。可传 `--output "<分析输出目录>"`。
- 已有概览可传 `--index "<material-overview-index.json>"`，核对同一原片后复用，不重抽帧。损坏证据会报错，不静默接受。
- 程序复用项目 FFmpeg 定位器；未找到时同时指定 `--ffmpeg "<ffmpeg路径>" --ffprobe "<ffprobe路径>"`，不自动安装或下载。
- 按项目现有时长策略生成 3×3/4×4 多宫格，保留时间覆盖锚点并补变化点。超过一小时先生成章节索引；再传 `--chapters CHAPTER-01 CHAPTER-03` 等明确选择。报告范围只能覆盖选择的章节。
- 返回 `task_path`、`evidence_path`、`template_path`。`task_ready` 仅说明可以开始看图。
- CLI 只准备本地图像和 JSON，不调用模型、云端 ASR，不创建生产项目或提交队列。

### 3. 读图并提交结构化判断

```powershell
python scripts/video_understanding_cli.py read --task "<task_path>"
```

1. 读取目标、范围、prompt、全部 `sheets[].path` 和 `cells`。调用可用的图像查看工具实际查看全部任务多宫格；仅列出图片路径不算完成。
2. 按时间顺序识别主体、可见动作、段落、布局、可见文字及模糊/遮挡。若图片文字给出产品名称或参数，只写“画面文字宣称”，不补充未经证实的身份和事实。
3. 小字/局部细节优先查看 `frames[].path` 原尺寸帧；需要新时间点时使用第 5 节精查。将关键未知项写入 `unknowns`。
4. 复制 `submission-template.json` 为本次 `submission.json` 并填充：
   - `model`、`task_fingerprint` 原样保留；`reviewed_sheet_ids` 填实际看过的全部 ID，不得仅填列表冒充观看。
   - `proposal.chapters` 严格遵循任务 prompt；主体/动作/候选段引用合法 `evidence_cell_ids`。不要编造时间码，程序从证据映射得到采样时间。
   - `answer` 回答本次目标；`answer_status` 只能是 `sufficient_for_goal` 或 `needs_more_evidence`。
   - `follow_up` 每项含 `kind`、`reason`、`required`、`evidence_cell_ids`；可用种类 `detail/fine/vision/audio/playback/source_check/window_qa`。全局音频或事实核对允许引用空数组。
   - 若还有必需证据，状态必须是 `needs_more_evidence`；`speech/motion/qa` 不能仅靠本 CLI 的视觉概览标为充分。可选的后续制作建议标 `required=false`。

```powershell
python scripts/video_understanding_cli.py submit --task "<task_path>" --submission "<submission.json路径>"
```

提交校验模型、任务和来源指纹、证据图片、章节/单元格 ID、看图声明及结论状态，生成 `analysis.json` 和 `report.md`。同一提交可重入；不同答案须在 prepare 时增加 `--revision "2"` 等新版本，不覆盖已完成结论。

独立报告明确 `production_ready=false`。原始抽帧索引仍可保持 `sheets_ready`，完成状态记录在独立的 `analysis.json`；不能手工改原始索引来冒充项目已理解。

### 4. 项目路线：沿用现有工作台合同

若结果将被正式选材消费，使用已存在的项目资产：

1. `POST /api/project/{project_id}/workbench/assets/{asset_id}/media-index/jobs`，明确传 `stage="overview"`、`execution_mode="agent"`、`model=<真实模型>`。视觉概览设置 `recognize_audio=false`，不要附带云视觉确认标记。
2. 跟随该任务状态；准备好本地证据后，`GET /api/project/{project_id}/workbench/assets/{asset_id}/agent-vision/overview` 读取图片和 prompt。核对返回的是当前 asset、model 和任务指纹。
3. 实际看完任务图片后，向同一路径 `POST` 提交 `{model, task_fingerprint, proposal}`；再次读取 `GET .../media-index/overview` 核对概览完成状态。
4. 正式选材还需 `stage="vision"` 的镜头级 V2 任务；用 `/agent-vision/vision` 同样读图、提交并读回。之后按[原生制片 skill](../../Haike_video/skills/creative/agent-native-video-production.md)执行匹配与最终源区间 QA。

后台兼容接口省略 `execution_mode` 时默认 `relay`；不能把它当成本地 agent 模式。工作台普通按钮与上述 agent API 的执行模式也不能混同。用户明确选择远端模型或 ASR 时，再按项目供应商、配置、费用与恢复合同执行。

独立报告可作为分析依据，但不能直接复制完成标志进入工作台；项目任务必须通过当前指纹及证据校验。

### 5. 需要深入时复用哪些能力

| 疑点 | 现有能力/入口 | 必须保留的边界 |
|---|---|---|
| 小文字、主体细节 | 原尺寸帧；`material_overview.prepare_detail_frames` 根据候选格回取，最多 12 帧 | 回取同一时刻的清晰帧不等于增加时间覆盖；查看与后续结论另留记录 |
| 布局切换、快速闪现 | `media_index.build_coarse_index`＋`build_fine_index`，指定局部起止点 | coarse 默认约 12 秒采样，不能替代短视频概览；fine 默认 2 fps 也不是逐帧剪切精度 |
| 镜头主体与动作匹配 | `media_index.build_material_vision_index`＋agent `vision` 提交 | 一个概览候选不等于已审核可用镜头 |
| 原声与口播 | 项目可选 ASR、转写缓存和音频证据层 | 无转写/没听音频要明示；云端操作遵守既有供应商授权与账本 |
| 最终源区间清洁度 | `material-selection/window-qa-task`；当前 3 fps、对应成片中心裁切 | 只在适用选材流程使用；不替代连续动作、音频或全片验收 |
| 素材人物、旧字幕筛查 | `scripts/remake_material_screen.py` 与素材复刻 skill | 自动筛查是线索，不能把未命中等同于没有字幕/人脸 |

## 完成判据与提速口径

### 竖屏内容的 UI 遮挡检查

当分析目标包含平台呈现时，同时看成片和平台页面截图：顶部导航/搜索、右侧操作栏、底部作者/描述可能挡住人物、字幕或产品。先确定截图中的实际视频视口，再检查等比缩放、居中裁切或留边；不能按整张手机截图直接等比换算视频坐标。保存无 UI 帧和带 UI 对照，注明真实截图还是模拟蒙版；模拟通过不代表真机通过。需检查最长字幕、主要切换和人物动作，不只检查首帧。

2026-09-28 用户实际抖音截图确认旧版圆框被顶部遮挡；调整后的三秒模板已获用户确认，新布局全片及真实播放仍待验证。复用规则与坐标真值见[数字人口播视频](数字人口播视频.md)，顶部 15% 是该模板设计余量，不是通用平台标准。

- 交付原片身份、覆盖范围、时长/画幅、概览图、段落结论、证据引用、未确认项、后续动作及完成层级。
- `overview_completed` 仅表示概览已读回；`sufficient_for_goal` 表示足够回答所写目标，仍不代表 V2 选材或成片验收通过。
- 多宫格减少图像文件和切换操作，但缩小了单帧细节；本项目尚无该通用流程的端到端提速倍数基准。不得把图像数量降低比例说成耗时或 token 降低比例。
- 优先复用已有证据，只对疑点补帧；竖屏小字看原尺寸帧。采样覆盖、准确率和耗时均达标后才调整默认采样/排版，不为“更快”删除关键覆盖锚点。

## 已知故障与安全恢复

| 现象 | 判断依据 | 当前安全恢复点 |
|---|---|---|
| 缺原片/FFmpeg | CLI 返回退出码 2 及中文原因 | 修正输入或指定现有二进制；保留已完成任务 |
| 缺图/证据 hash 不一致 | prepare/read/submit 拒绝 | 保留旧目录；使用新输出目录重新 prepare，不提交旧图结论 |
| 超过一小时未选章节 | 返回章节索引路径 | 读章节列表，明确 --chapters 后续跑 |
| 来源、模型或问题变化 | 指纹不一致 | 重新 prepare；能复用的原始图像仍可复用 |
| 提交 ID/字段无效 | 模板或校验报错 | 修正本次 submission，不重抽整条视频 |
| 已完成任务收到不同答案 | 冲突拒绝 | 新 revision 保存新结论，旧结果保留 |
| `.task.lock` 遗留 | CLI 提示正在写入或遗留锁 | 核对锁中 PID 和活动进程；确认没有任务写入后，仅清理该任务锁 |
| 只生成了图、没有结构化结论 | task_ready/sheets_ready | 继续读图并 submit；不要手工改 completed |
| 看不清或需音频/连续动作 | unknowns、必需 follow_up | 停在 needs_more_evidence，沿对应分支取证 |
