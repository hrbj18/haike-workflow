在 [正式基准目录](../../Haike_video/templates/avatar-card-explainer-v3/) 保存 `index.tsx`、`Root.tsx`、`Composition.tsx` 和 `template.json`，不携带媒体。稳定标识为 `avatar-template3-card-3x4-v001`。以下是已确认样片的名义坐标，单位为像素，原点在画布左上。

| 层 | 坐标 / 规格 | 复用规则 |
|---|---|---|

| 白色外卡 | x63、y72、宽954、高1296；圆角40 | 固定外壳与轻阴影，不随章节跳动 |

| 主内容板 | x114、y186、宽852、高708；圆角29 | 上方章节标签、标题和副说明；下方视频/示意卡 |
| 视频窗口 | 主板内 x32、y234、宽788、高441；圆角22 | 近似16:9；等比裁切，禁止拉伸，裁前检查主体 |

| 底部字幕 | x100、y1302、宽880、高60 | 单行居中、灰字蓝色重点，不压住人物和章节说明 |

- 中文字体栈为 `Microsoft YaHei / PingFang SC / sans-serif`；主文字 `#1D2330`、次级灰 `#7C818D`、强调蓝 `#316DD6`。跨机器渲染前核对实际字体，替代字体需要重新测宽。
- 主标题 60px，摘要标题 40px、说明 27px；字幕按真实字宽从 44px 缩至最低 36px。36px 仍超出 880px 会报错，应拆句并重对齐时间；不靠继续缩字解决。主标题和摘要尚无同级自动测宽保护，必须检查实际帧。
- 字幕按句切换，关键词是整句内静态蓝色强调，不是逐字卡拉 OK。字幕颜色与关键词可替换，但需保留普通字/重点字层级。
- **3:4 不是平台通用安全区承诺。** 参考片本体为 720×960，截图的大块上下黑区属于播放器外部区域，不能当作视频内置留白。当前字幕距画布底部较近；正式使用需按目标平台、入口和真机验证遮挡。转成 9:16 时应重新排版/补画布并验收，不能直接纵向拉伸或认定黑边必然保留。

## 节奏与组件

已实测三类章节：视频案例卡、路径对比卡、分步流程卡。外壳和人物位置保持稳定，主要切换上方内容板及右下摘要。样片章节边界为 0 / 3.6 / 8.68 / 15 秒，内容交叉淡化 0.25 秒；节点/流程卡以 0.4 秒缓出和轻微上移依次出现。所有动效跟随 Remotion 帧时钟，不使用随机或真实时钟驱动。

三章、15 秒和 AI 购物文案只是确认过的样例，不是每期固定篇幅。讲解结构与章节时间按本期语音组织；进度条反映本期章节，不把参考片章节数机械套入。

## 当前操作

1. **确认素材和时间轴。** 阅读项目 [Remotion 入口](../../Haike_video/skills/core/remotion.md) 与 [Atelier 合成规则](../../Haike_video/skills/meta/bespoke-composition.md)。探测视频尺寸、帧率、时长、音轨；核对字幕对应原始人物片还是后期组装 master。同一个人的两份文件不代表时间轴相同。记录来源、裁切区间、素材 ID/哈希及可用范围；本地已有不等于已获发布授权。
2. **复制基准到本期项目。** 将基准的三个 TSX 复制到新项目目录，媒体放本期 `public/`；按 `template.json` 提供 `avatar`、可空 `broll`、`audio`、`cues`。只在本期副本改章节文案、边界、总帧数和内容卡；不要改掉确认基准。当前章节/时长仍是源码常量，尚无任意主题、任意时长的一键参数化入口。
3. **准备声画。** 从同一母版按同一区间提取人物与原声，字幕减去同一开始时间；人物等比裁成正方形后交给圆形遮罩。人物层和 B-roll 静音，由独立音轨提供声音，避免双声。样片无 BGM；新增配音、数字人或音乐按本期需求与现行供应商/预算规则处理，不继承旧任务的付费参数。
4. **组织节奏。** 优先按语音停顿切章，每屏只承载一层核心信息。视频、比较图和步骤卡应与当前句子对应；标题负责章节结论，字幕负责原话，避免三处同时重复整段文字。需要结尾停留时，在完整话尾之后补停帧/静音，不变速压缩口播；检查末帧表情，张口停帧可换自然闭口帧。
5. **本地样片预检与渲染。** 核对当前 Node、Remotion、浏览器、FFmpeg 和字体，执行项目 composition preflight。向 `VideoCompose.execute(inputs)` 传入 `operation="render"`、本期 `project_dir`、新版本 `output_path`；`edit_decisions` 指定 `render_runtime="remotion"`、`composition_mode="atelier"`，并在 `bespoke` 提供 `entry`、`composition_id`、`props_path`、`public_dir` 与本期 `art_direction`。实际字段遵循当前工具 schema。该操作写入本地渲染产物，不触发云生成。样片不能通过直接调用注册的 review/full-preview runner 绕开统一队列。
6. **验收最终文件。** 检查视频流、音频流及容器时长一致、帧数正确、完整解码无报错；抽查开头、章节转换、最长文案、话尾与收尾。复核人物裁切、素材比例、字幕字宽、关键词及声画同步；连续播放并听辨后才能记为听看通过。最终成片与 manifest/QA 必须指向同一版本，旧渲染结果和默认自动审查字段不能冒充新版本证据。
7. **正式全片门。** 全片前需把 3:4 画幅、圆框几何、字幕组件和章节数据接入正式项目/工作台生产合同，保证预览与最终输出共用时间轴，再从统一队列提交。当前短样片成功不证明旧工作台的画幅或画中画约束已解除。完成全片与真机验收前保留“待验证”，交付 review-ready，不自动发布。

## 已知限制与恢复点

| 现象 | 判断依据 | 当前恢复点 |
|---|---|---|
| 字幕过长、标题越界 | 实际字体测宽与渲染帧 | 拆句/压短标题，按同一音轨重排字幕；不重做数字人 |
| 圆框切头或口型不同步 | 人物源尺寸、人脸位置、同源音视频选段 | 在本期项目调整裁切/区间；不能照抄旧源的像素或时间偏移 |
| 画面15秒但容器更长 | 分别探测视频、音频、容器时长 | 排查音频编码尾包/补齐边界，复用完成的视频轨局部修正；不重复云调用 |
| 默认审查报告与画面不符 | 对比最终文件、源码、manifest、人工检查 | 更正本期验收记录与版本引用，保留原始证据；不要只凭 pass 字样交付 |
| 平台 UI 覆盖字幕/摘要 | 指定平台入口的真机播放 | 按实际遮挡调整本期布局或输出变体，再核验；不写通用免遮挡结论 |
| 旧工作台强制既有几何/比例 | 当前工具能力和预览输出 | 先补正式适配，再跑全片；不能将独立样片标成生产集成完成 |
