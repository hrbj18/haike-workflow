# 视频模板 Runbook 骨架

文档类型：skeleton。
标准版本：video-template-v1

**新建或实质改版视频模板**时，先读[编写标准](视频模板编写标准.md)，复制下方骨架为具体模板文件，并创建符合[规格 schema](../contracts/video-template-spec-v1.schema.json)的 JSON。替换所有占位项；规则定义引用标准，具体步骤、输入和 gate 写在模板手册中。选择[类型扩展](template-standards/类型扩展.md)，按[验收量表](视频模板验收量表.md)记录状态。

骨架不是制片入口，也不是某个模板的验证记录。参考规格可以交付，但没有当前实现入口时保持规格阶段。

“模板规格”填写真实 JSON 的 Markdown 链接：标签写为 `[规格]`，紧接圆括号中的实际 `.json` 路径。教学展示：[规格](template-standards/examples/graphic.json)；复制为具体模板时换成本模板的实际规格链接。

按启用的类型扩展填写必需键：`avatar` 为 `face_crop`、`synchronization`；`graphic` 为 `text_policy`、`asset_fit`；`chart` 为 `data_mapping`、`label_policy`；`tutorial` 为 `step_mapping`、`callout_policy`；`material_edit` 为 `source_ranges`、`cut_policy`；`custom` 及额外模块为 `contract`、`rules`。字段中的 unknown marker 同时按 JSON pointer 登记到 `unknowns`，并填写补证据计划与阻断范围。

## 当前操作

按当前实现把步骤拆到每步都有唯一动作与穷尽完成条件；下列步骤名仅作组织框架。`action` 填当前已存在的工具/CLI/API/UI 入口及必要参数映射，恢复点使用本次任务事实。

### 1. 核对与冻结输入

- `input`：<规格、实现版本、本次 slots 与素材、现有任务/产物>。
- `action`：<解析与读回入口；比较版本/哈希、槽范围与当前能力>。
- `output`：<冻结输入与版本身份、已有任务处理结论>。
- `gate`：<所有必需输入可解析、取值合法、来源与版本一致、对应授权有效>。
- `recovery`：<缺失项补齐路径；发现已有任务时的核对和复用入口>。

### 2. 生成覆盖关键状态的开发验收短样

- `input`：<实现规格、已确定的样片参数与冻结输入、覆盖计划、当前预览入口、本次授权及工具能力>。
- `action`：<确定的调用方式；说明本步会写入/入队/产生费用的实际范围>。
- `output`：<短样、版本身份、检查所需坐标图/实际帧及日志定位>。
- `gate`：<声明范围内的关键布局、最长/最短内容、状态与转场覆盖；技术/视觉/听看适用项分别有结果。核对 ready 条件后再明确更新阶段；首次短样不推定其他状态通过>。
- `recovery`：<读回已有任务与产物；修复失败字段后重验受影响范围>。

### 3. 在已授权范围执行完整产物

- `input`：<ready 实现规格、通过的对应前置 gate、冻结完整输入、当前生产入口及本次生产授权>。
- `action`：<确定的调用方式、读回点与幂等/恢复约定>。
- `output`：<任务状态、完整视频及对应规格/输入身份>。
- `gate`：<终态与产物同时满足；完整解码、时长/流、全片覆盖及量表适用项通过>。
- `recovery`：<结果不明时先查询实际任务与文件；从已证实的恢复点继续>。

### 4. 验收并交付

- `input`：<完整产物、规格、预期变化范围、目标播放环境>。
- `action`：<量表逐项检查；按声明范围执行连续听看与真实目标呈现检查>。
- `output`：<验证矩阵、产物身份、交付范围与剩余待验证项>。
- `gate`：<所有适用项都有结论和证据；失败项关闭或明确阻断交付；声明未超出验证范围>。
- `recovery`：<定位问题元素/时间段；修改真值后只重验受影响项与关联项>。
