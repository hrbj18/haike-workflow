## 入口与边界

固定呼叫名：**动作迁移复刻 / 角色替换复刻**。示例指令：

> 按动作迁移复刻 runbook，用这条原片和檬檬三视图、正面照复刻；沿用已导入的 SCAIL-2 工作流，先测试前 8 秒，预算按本次指定上限控制，成片交付待审。

这是在 `Haike_video/skills/INDEX.md` 登记的用户指定工作流兼容操作，尚未接成正式父生产 pipeline。不能改用默认 InfiniteTalk 对口型 profile，也不能换成社区“应用”或其他按次付费模型。已注册的上下窗口二剪仍走工作台与统一队列。

本图视频阶段接受**单张场景参考图＋驱动视频**。三视图和正面照用于上游生成场景参考图，未验证视频节点同时输入多张身份图。原片提供动作、表情和机位；原音频在后期恢复，未独立作为音频驱动输入。参考图写“侧面”不会让原片的正面机位自动变成侧面。

## 开始前的最小核对

1. 读取本手册、生产端 Agent 入口和当前代码；指定抖音链接下载走[下载抖音视频](下载抖音视频.md)，已有素材直接复用。
2. 确定本次原片、角色参考、使用区间、横竖屏交付、字幕语言与预算。不要把“前 8 秒测试”自动扩为全片；已有授权覆盖后续时继续执行。
3. 在项目建独立任务目录，记录输入哈希、来源、原始音频、FPS、帧数、尺寸、分段表和输出路径。先查已有 state 和输出，复用相同输入及参数的成功片段。
4. 从本地秘密机制读取 `RUNNINGHUB_API_KEY`；API 地址使用配置的 `RUNNINGHUB_BASE_URL`，缺省 `https://www.runninghub.cn`。凭据不进入请求公开副本、手册或日志。
5. 记录工作流、模型、实例、当前计价、总预算、单段运行时间上限、重试策略。实测默认实例约按 **4 元/计算小时**计费，四段视频生成共 **2.261 元**；不含参考图费用，不是下一次报价承诺。新提交前核对累计费用和在途任务预计费用；预算不足暂停新增提交。本次历史脚本没有完整的自动总预算拦截器。

## 原片清理与参考图

先保存原片字幕文字和真实时间，再清理烧入字幕、水印和 LIVE 标记。实测使用部署的 video-subtitle-remover / **ProPainter**，按字幕出现区间制作贴合字形、适当扩边的 mask，再检查胸前衣服、手臂和背景。大片矩形覆盖可能造成衣服或背景变形；提示词中的“无字幕”不能替代去字幕。去除干净程度要用原字幕出现帧验收，不宣称所有片段无残留。

确认清理没有改变帧数、帧率和原声时钟。保留原片及无字幕母版；生成过程不覆盖它们。外部去字幕项目以其当前代码与配置为准，不依赖本次临时脚本路径。

用角色三视图、正面照和已确认的主场景图生成所需场景参考图；保持身份、发型、服装、光线一致。原片站着表演时，场景图使用站姿，并让头、肩、手臂有活动空间。先查看图片，避免把坐姿图或不合适的面部表情直接送入付费视频任务。

按原片镜头变化选择参考图；生成多个角度可以补充身份参考，但不等于改变成片运镜。图生成需按当前可用 skill 和费用约束执行，单独记录成本。

## 分段、提交与断点续跑

按镜头和表演节奏切段，用原片帧号定义半开区间 `[start_frame, end_frame)`，区间连续、不重叠，总帧数覆盖本次目标范围。音频是主时钟，不按字数均分台词，不加速或拉伸演唱。

当前图的驱动长度补齐规则：`N_driver = 4 × ceil((N_original − 1) / 4) + 1`。不足部分只复制末帧；生成结果拼接前裁回原始帧数，防止每段多出的帧累积音画偏移。

| 本次已验证的分段示例 | 原始帧数 | 驱动帧数 |
|---|---:|---:|
| [0, 220) | 220 | 221 |
| [220, 430) | 210 | 213 |
| [430, 640) | 210 | 213 |
| [640, 842) | 202 | 205 |

这是 30 FPS 案例，下一条片子的分段要重新制定。新帧率、尺寸或模型先做短段核验；不能沿用其他模型的 4n+2 规则。

1. 本地准备驱动：FFmpeg `trim=start_frame=...:end_frame=...`、`setpts=PTS-STARTPTS`、`tpad=stop_mode=clone`，最后 `trim=end_frame=N_driver`。补帧时长需覆盖缺帧；实测 30 FPS 使用 0.2 秒足够。本地检查实际帧数后再上传。
2. 每段 state 保存素材哈希、工作流图哈希、参考图、提示词、种子、原始区间、原始与驱动帧数、请求哈希。**提交前**原子保存 `submitting` 和时间；拿到 taskId 后立刻持久化再轮询。
3. 首次核验可先跑用户指定短段，合回相同时间范围的原声并查看身份、表情、手势、字幕残留。已有合格测试和后续授权时复用，不重复测试扣费。
4. 查询现有 taskId；成功后下载到临时文件，校验、原子改名、记录哈希和费用。失败记录阶段、错误、是否可重试和已发生费用。首次实测四段均成功，无付费重试。
5. 创建超时或响应丢失时，先查 state 和平台任务列表。同时间同输入的任务可能已创建；无法定位就停止该段新增提交，不能把网络超时直接当作“未扣费”。创建接口未验证通用幂等键。
6. 已有成功原始输出就跳过付费生成；下载中断只重下，拼接失败只重拼，字幕和音量返工只重做本地合成。

本手册提供 API 契约和执行检查点，当前没有专用的一键 SCAIL CLI。历史任务目录里的硬编码脚本是证据，不能作为新任务的长期入口或整条重新运行。

## 拼接、字幕、竖屏与验收

逐段检查视频可完整解码、尺寸/FPS匹配、帧数足够；不足不能用减速伪装，应定位该段原因。统一到目标尺寸后按原始 N 裁切，再顺序拼接。取原片目标区间的原声整体合回，**不用补帧驱动片段的音轨拼接**。全片复刻可流复制原音轨；无响度改动时验证音频哈希一致，局部测试验证所用区间正确。

先交付无字幕母版，再按已核对的真实时间重建 SRT/ASS。唱歌转写需人工校对；不要均分字幕时长。本次旧字幕的字形匹配脚本只适用于该原片，不能当通用字幕识别入口。

横转竖、上下标题、大字幕和响度返工走[基于上下窗口的复刻优化](基于上下窗口的复刻优化.md)，复用母版，经统一队列出待审视频。中间主体完整保留，字幕放上下留白；本次 1080×1920 案例中文 72px、英文 36px，需按最长句换行及手机实际显示复核。音量先测 LUFS/真峰值再调整，本次约提升 2.2 dB 至 −12.95 LUFS、−1.97 dBTP；不是所有输入固定加同一增益。音轨选择须读回实际 track ID 和来源，避免把排序最后一项当最新音轨。

验收至少包括：全片解码；总帧数和各段边界；画面与原声时钟；切点前后、强表情和手势帧；所有原字幕出现区间的清理；新字幕字号/换行/遮挡；连续播放听辨及口型；账单和各段状态。抽帧通过不能代替连续播放。身份漂移或手部明显变形只处理对应片段，新的付费重生成仍受本次预算与授权约束。

封面单独生成竖屏文件，文字短、居中并避开脸和底部 UI，缩到手机列表尺寸检查。平台有不同封面槽位，须在实际发布预览核对裁切；不能直接把横屏封面当竖屏封面。发布另走[短视频三平台发布](短视频三平台发布.md)，核对本次发布授权和作品状态，本流程到待审交付为止。

## 已知故障与恢复点

| 现象 | 判断依据 | 恢复动作 |
|---|---|---|
| 原字幕残留或衣服变形 | 原字幕帧与清理母版对照 | 调整对应区间 mask；先复核清理，再决定是否仅重做受影响生成段 |
| 坐姿、身份或手势不合适 | 场景图及测试段 | 修改参考图/参数并保留成功段，不重跑整片 |
| 图或节点已变化 | 实时图与保存哈希/类型不一致 | 更新映射并短段核验，不能套用旧数字人口播参数 |
| 创建请求无响应 | state 为 submitting，taskId 缺失 | 平台核对已有任务；未排除已创建前不重新提交 |
| 每段音画逐渐错位 | 拼接帧数大于原始区间总和 | 裁回原始帧数，整体合回原声 |
| 字幕太小、音量太低、要竖屏 | 母版和原声合格，布局/混音不合格 | 仅本地二剪，新增视频生成费用为零 |
