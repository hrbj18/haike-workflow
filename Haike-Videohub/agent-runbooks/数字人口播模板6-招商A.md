## 模板规格导航

| 项目 | 规格定位 | 本模板职责与约束 |
|---|---|---|
| 画布、时长与主时钟 | `canvas`、`extensions.avatar.synchronization` | 实际口播音轨为主时钟；数字人源与字幕共用同一原点，最终输出按 30fps 取整，不能为封面压缩语音 |
| 叙事与场景 | `narrative`、`scenes` | 封面进入人物口播；稿件重点按真实识别时钟出现；结尾封面覆盖话尾，不新增无声招商段 |
| 元素与固化内容 | `assets`、`elements` | 人物原背景、玻璃项目牌、贴纸、卡片、字幕、封面与数字人标识各自登记；固定品牌与可替换项目文案分开 |
| 层级、适配与避让 | `elements[].layout/constraints` | 人物完整 contain，外层同源模糊延展；重点卡与字幕分层，封面不隐藏当前字幕 |
| 状态、动效与时序 | `elements[].timing/states/transitions`、`extensions.investment` | 全片秒、ASR 毫秒、Remotion 帧明确换算，区间采用左闭右开；不均分稿件伪造强调时间 |
| 固定与替换槽 | `slots`、`studio_investment.settings()` | 本期仅填写开放字段；文字长度、重点数量、缺失与溢出均走当前校验 |
| 证据与待验项 | `evidence`、`unknowns`、`validation` | 参考观察、估读测量与重建设计分开；技术、视觉、听看、真机、用户确认和生产接入分别记录 |

参考片是手机录屏。其状态栏、平台按钮、账号文字和屏幕内风险/广告提示不能被误认成可复用素材；新模板重建视觉语言，不直接裁切参考片当底板。去 UI 后的 9:16 映射只是重建设计基准，未测得干净原视频边界。当前保留紫蓝科技色、玻璃牌和夸张贴纸，字幕使用清晰的白字细描边；原会议/培训 B-roll 只有取得独立来源与使用范围后才能使用。

## v002 当前操作

### 1. 核对与冻结输入

- `input`：本规格、当前实现、稿件/音轨/人物图、`input.investment`、费用上限及已有任务。
- `action`：读 `GET /api/studio/templates`、音色中心和原草稿；新建或更新 `POST /api/studio/drafts`，`template_id` 指向本模板。使用 `POST /api/studio/assets?draft_id=…&kind=image|audio&filename=…` 上传本期素材，再以实际 asset ID 保存同一草稿 revision。
- `output`：冻结草稿、素材 SHA 与引用、版本身份和已有产物复用结论。
- `gate`：所有资产归属本草稿且可解码；音轨长度与实际字节合格；配置通过 `studio_investment.settings()`；已明确模板、人物、声音、费用、联网开关和素材范围。用户明确提供完整音轨时使用 `soundMode=audio`，不能再次应用供应商已处理的 1.1 倍速。
- `recovery`：缺字段时补原草稿；已有 revision/报价/队列时先读回，发生版本冲突不新建替代付费任务。

`investment` 当前开放项目品牌 `brand`、封面 `headline`、引导 `cta`、`opening/closing` 开关和 `emphasis` 数组。品牌单行，封面和 CTA 最多两行且不含空白行；无显式换行且超过 12 字时二等分为两行，并按最长行动态适配字号。每条强调使用真实稿件片段 `match`，可指定显示标题 `text`、`sticker|card`、说明和注释；同屏最多 3 条，第四条会拒绝，不静默丢弃。其余字段上限、默认值与未知字段拒绝行为以适配器为准。招商数额、回购条款等均为用户稿件内容，模板并未核验商业承诺。需要保留条件的说明写入对应卡片 `detail/footnote`，不能只显示有利数字。

### 2. 生成覆盖关键状态的开发验收短样

- `input`：实现规格、已确定的短样时钟、项目内人物视频、开发演示音轨和手工示意字幕；覆盖开封面、纯人物、贴纸、卡片、最长文字、字幕与尾封面。
- `action`：使用正式[零云样片 CLI](../../Haike_video/scripts/avatar_investment_sample.py)：在 `Haike_video` 运行 `python scripts/avatar_investment_sample.py --portrait <授权PNG/JPEG> --evidence-dir <本工作区忽略目录> --base <本机工作台根地址>`，默认只准备；加 `--submit` 提交，之后同一证据目录用 `--status/--resume` 读回或恢复原队列，completed 后用 `--evidence` 生成完整解码和 5 帧证据。脚本先核对 edition、工作区和模板，再通过原生 `ProductionQueue.submit(kind="studio_avatar")` 私有合同执行；`quotes={}`、AI/联网关闭、全零 PCM16/24kHz 单声道音轨。普通 draft/quote/generate API 拒绝 `development_sample`；不得调用注册 runner 绕开队列。
- `output`：独立样片任务、`avatar-preview.mp4`、相同渲染器产生的 props/触发回执、技术探测与实际帧。
- `gate`：本次关键状态均覆盖，检查最终封装文件完整解码、尺寸/帧率/时长；实际查看稳定态、最长内容、进出转场和话尾。手工字幕或无声音轨只证明版式与动效，不能记为 ASR、口型、语音听辨或真实全片通过。
- `recovery`：从原任务与产物继续；调整本期文本/参数后仅重做本地合成，不清理付费素材或更换供应商。

### 3. 在已授权范围执行完整产物

- `input`：达到对应 ready gate 的实现、冻结完整草稿、真实驱动音轨、人物素材、ASR 配置和本次费用授权。
- `action`：`POST /api/studio/drafts/{draft_id}/quote` 传实际 revision，核对返回供应商/模型与已知上限；`POST …/generate` 传相同 revision、quote_id、max_charge_micros、confirmed=true。该入口提交 `studio_avatar` 统一队列，以 `studio:{draft_id}:{revision}` 幂等键运行。随后读 `GET …/avatar-job` 和 `GET /api/production-queue/jobs/{job_id}`。
- `output`：原队列终态、已保存供应商调用意图、真实 ASR 字幕、语义触发回执、最终 `renders/studio-{revision}/avatar-preview.mp4` 及作品版本。
- `gate`：原任务与本期冻结版本一致；最终文件存在且技术核验通过；`investment-triggers.json` 每个未匹配强调都已解释或修正文案/识别后重新本地合成。单有队列 `completed` 或中间 `avatar-render.mp4` 不算最终验收。
- `recovery`：queued/running 只跟随原任务。failed 且 retryable 时用原 `POST /api/production-queue/jobs/{job_id}/retry`；结果未知先读回原调用意图和产物。已完成 TTS/ASR/数字人继续复用，不能通过新 draft 或新调用清空未知费用。

当前输入不启用联网素材时，使用稿件绑定的图文卡表达信息，不能把卡片称为实拍证据。若启用可选源素材，沿现有 Agent 素材审核与 `agent-materials` 合同取得真实时钟、来源和使用范围；只搜索到候选不等于已采用。可选素材窗未验收的范围单独保持待验证。

### 3.1. 受控本地字幕或脚注修正版

- `input`：已完成且已登记作品的本模板正式 `studio_avatar` 原队列、原始素材/字幕/渲染回执，以及一种明确修正模式。当前范围只支持未启用 AI/联网/通用动效的成片。
- `action`：在 `Haike_video` 使用正式[本地修正 CLI](../../Haike_video/scripts/avatar_investment_recompose.py)，以 `--request <忽略目录内请求JSON> --source-queue <已完成原队列ID>` 选择原片，默认仅 prepare。字幕模式加 `--caption-style clear-v2`，固定合同 `investment-caption-style-local-v2` 与 patch `{"caption_style":"clear-v2"}`；它只采用已冻结的模板字幕样式。脚注模式加 `--footnote-index <0起始索引>`，省略 `--footnote` 表示清空，替换文字时显式提供；该模式保留 `investment-footnote-local-v1`。两种模式互斥。之后相同 `--request` 依次 `--submit`、`--run`，用 `--status/--resume` 读回或恢复；`--base` 指定已核对的本机服务。底层[模块](../../Haike_video/backlot/studio_investment_recompose.py)以原生 `studio_investment_recompose` 类型及请求指纹幂等入队，初态 paused，由 `ProductionQueueWorker.run_local_recompose(job_id)` 认领。该路径不构造 SDK、不报价，不重新识别、配音或生成数字人。
- `output`：字幕模式为独立 `renders/local-caption-clear-{指纹前20位}/avatar-preview.mp4`；脚注模式保留 `local-footnote-{指纹前20位}`。同时保存 `local-recompose-result.json`、新输出 SHA 和原作品新版本。原 draft/revision、原 props、原队列和原版 MP4 保留。
- `gate`：准备及渲染后重新核对原 source request、素材/音轨/字幕/原成片 SHA；原 ASR 已成功，字幕、时长与 props 完全一致。未渲染请求须保持冻结 runtime 源码 SHA；字幕模式要求 `layout.caption.styleId=clear-v2`。回执 `cloud_calls=0`、`sources_unchanged=true` 且登记同一 work_id。字幕模式还须验证全部 props、重点事件、文字和时钟保持原样；新 SHA 独立进行技术及实际视觉检查。
- `recovery`：保留 frozen request 和原本地队列，来源 SHA 变化时停止。未渲染请求遇到 runtime 变化须重新准备新指纹；已成功的原请求可在请求指纹、输出 SHA 和全部来源 SHA 核对后只读或恢复作品登记，不因源码维护重渲染。原版、修正版和历史验收分别保存，不重提供应商调用。

全局制作 lane 忙时保持同一本地队列等待；未领取不代表渲染失败，也无需重新 submit。恢复仍由既有 worker 领取原任务，完成后核对原队列和产物身份。

### 4. 验收并交付

- `input`：最终封装、当前规格与 props、驱动音轨、触发/供应商回执、技术报告及代表帧。
- `action`：按[验收量表](视频模板验收量表.md)逐项检查；使用 `scripts/codex_video_quality.py --project <本期项目> --video <avatar-preview.mp4> --template avatar-investment-a-v6 --audio <驱动WAV>`，并实际查看覆盖开头、长短句、重点密集段、每种卡片、回购条件和结尾的帧。需要连续听看及真机通过时取得对应证据，不由探测或 ASR 推断。
- `output`：规格验证矩阵、最终 SHA、可播放成片、封面/说明及明确交付范围；完整成片登记到作品入口。
- `gate`：自动检查与人工字段均对应同一最终 SHA；全部适用项有结论，未通过项与影响写清。未经事实核验不填写 `source_claims_verified=true`；只有制作授权时保留 `publishing.targets=[]`。

字幕继续按标点／语义边界与真实词端点组成短拍，目标9字、上限13字、最多两行；`captionBeats` 与 v004 相同。每短拍完整文字从首个有效帧即可读，整块弹入后稳定持读；最长匹配关键词依据真实词钟作一次短促回弹，金额与完整词组不拆成随机单字。章节标题、合作金额、要点和边线有独立的短暂动作，其精确幅度与曲线从当前源码读取，不再由手册另存一套力度。人物及来源说明不随字幕抖动，禁止全屏闪白、乱码滚动或缩放脸部。

真实素材仍只作“粤仔产品互动素材／粤仔产品互动定格”的例证，不能称海客门店实拍或指定邻居、孩子、成交的证明。源01／06两段沿用原机器狗／产品内容区间；源03／05画面只配“一款产品到底好不好用／这些都是可以拍的内容”，源02／04不新增真实B-roll。真实素材静音，来源标签稳定可读，不伪造门店／观众现场声音。

### 原创声音与时间合同

`assets/sound/PROVENANCE.json` 记录118BPM主配乐《铜流》、124BPM赤红配乐《即刻向前》、100BPM纪实配乐《日常向前》及 `dong/impact/whoosh/tick` 四类核心音效。它们由本地确定性 NumPy／DSP 作曲合成，无外部歌曲、录音、采样、下载或云音乐调用；canonical 文件路径、SHA、来源标签与生成脚本指纹均可追溯。用户人物、口播、真实视频及系统字体不随模板公共资源分发。

`audio-plan` 严格使用 `version=sound-motion-v1`、`mix_profile=speech-led-v1`，顶层只有 `version/mix_profile/music/assets/events`。每条 raw event 只有 `id/asset_id/anchor/pattern/gain_db`；anchor 只有 `type/index/boundary`，类型为 `word/cue/chapter`、索引为零基、边界为真实 `start/end`。不允许自由秒数。适配器派生 `timeMs`、`ceil(timeMs×30/1000)` 和量化误差，再把 `id/role/timeMs/startFrame/endFrame/strength` 六字段投影到 `art.soundEvents`。

`single` 是一次编辑击打；`triple-hit` 是同一真实锚点的0／0.12／0.24秒重复，只用于本期04金额。它不是三个词或新ASR时间戳。设备／首批货／培训、投入／选品／服务支持及AI选品／宣传／客服的轻叠打分别绑定各自真实词索引，不均分时钟。每片4–5处主落点、最多一组轻清单、2–3次轻过门；本期六片展开起音分别10／11／10／12／10／7，不给每字每句相同的大音效。

音效资产可选 `sync_ms` 默认为0；本期 whoosh 为430ms。它只令音频播放起点为 `anchorMs-sync_ms`，负起点裁素材头；真实 anchor、视觉 `timeMs/startFrame` 和人声／字幕时钟不动。其他三种核心资产为0。声音文件不足或SHA不符必须拒绝，不自动替换未知歌曲。

原视频提取24kHz、PCM16、单声道语音并保持文件与原速；混音阶段只对语音轨做一次 `-2.5dB`。配乐按六方向底电平加入，并被实际原声侧链压低；SFX按事件增益加入。准备阶段冻结唯一48kHz立体声PCM16 `mixed-master.wav`，预览和最终封装共用。母线峰值保护与必要总增益单独写回执，最终AAC真峰检查要求不高于 `-1.5dBTP`；最终mux不再重复volume/loudnorm，不再强制单声道。原声源文件逐字节保留不等于新混合AAC与旧AAC逐字节相同。

### 操作与恢复

- `input`：完整已有MP4、真实cue、每词绑定 `source_video_sha256` 的完整word-clock、`variant=art-v5`艺术配置、`--audio-plan`、title/brand，以及已核对工作区的本机服务。
- `action`：仓库根运行 `python Haike_video/scripts/avatar_investment_source_art_v5.py --evidence-dir <忽略目录> --source-video <MP4> --cues <cue.json> --word-clock <words.json> --art-config <config.json> --audio-plan <audio-plan.json> --title <标题> --brand <品牌> --base <本机工作台> --prepare`。同目录再 `--submit`、`--run`，以 `--status/--resume` 跟随原请求。
- `output`：冻结request、项目 `source-art-v5-request.json`、输入及来源副本、normalized audio-plan、mixed-master和mix receipt；最终为独立 `local-source-art-v5-` 渲染目录、scene plan、result、MP4及作品版本。
- `gate`：来源、runtime、原文、词钟、音效索引、声音时长／格式／SHA与已授权范围一致。完整制作沿统一 `studio_investment_recompose` paused队列，由worker全局单lane认领。母带／最终输出／作品版本与HTTP媒体分别绑定其真实SHA；队列完成或fixture混音回执不能替代最终验收。
- `recovery`：同指纹复用已有冻结请求及成功母带。lane忙等待原任务，结果未知先查来源／队列／文件／作品，不另提收费阶段。来源、runtime或声音计划变化时保留旧产物并冻结新身份，不覆盖旧请求，不重生TTS、ASR或人物。
