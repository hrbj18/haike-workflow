# 视频模板验收量表

文档类型：reference。
标准版本：video-template-v1（v1）。

**验收、交接或修订任意视频模板**时使用。先读[编写标准](视频模板编写标准.md)，按已声明的[类型扩展](template-standards/类型扩展.md)补验收项。本量表评价具体版本与范围，不把某次通过推广为整个模板永久通过。

## 判定与证据

每项记录：检查对象/字段、版本、输入、实际检查范围、方法、结论、证据定位、失败影响和后续动作。结论采用通过、失败、待验证、不适用，对应规格枚举 `pass`、`fail`、`pending`、`not_applicable`；不适用必须有理由。规范与 schema 是判据，工具返回值、实际帧、听看与目标环境读回是对应维度的证据。`illustrative` 示意证据仅用于展示填写方式。

**适用项全部有结论**才结束验收；平均分或高总分不能抵消一个必需 gate 失败。未知参数与尚未验证分开：前者表示规格未确定，后者表示已有规则但未取得该维度结果。

## 必查项

| 维度 | 通过条件 | 最低证据与失败影响 |
|---|---|---|
| 规格身份与真值 | 标准/规格版本明确；reference 与 implementation 分开；参数唯一真值、当前入口及版本可定位 | 规格和入口身份；真值冲突阻断依赖该参数的动作 |
| 覆盖与内容边界 | 画布、叙事、全部场景/独立元素、内嵌固化内容、音轨与允许空区间均已描述 | 元素/场景清单及覆盖检查；遗漏阻断规格完成 |
| 空间、依赖与时间 | 坐标/单位/锚点明确；父级、绘制顺序、遮罩、裁切、适配、避让及依赖可求值；全片/场景/素材时间与端点无歧义 | 结构检查和涉及相对规则的实际帧；循环依赖或不明主时钟阻断执行 |
| 状态、动效与替换 | 全部状态/转场有规则；固定与可替换范围明确；每个槽有类型、边界、默认依据和缺失/溢出处理 | 状态/槽检查及边界样本；替换后失控阻断对应输入范围 |
| 证据与 unknowns | 观察、测量、设计有各自定位；估读注明精度；全部未知项有补证据计划和完成判据 | 来源记录与未知项清单；ready 必需参数未定阻断执行就绪 |
| 操作与恢复 | 每步都有 input/action/output/gate/recovery；当前调用入口存在；能识别已有任务与产物、从明确点继续 | 入口检查、读回与恢复证据；未运行恢复分支标待验证 |
| 技术产物 | 产物可读取并完整解码；尺寸、帧率、时长、流与冻结输入一致；全片无非预期截断、黑段、静音或尾帧异常 | 探测/解码结果、产物身份及范围；进程退出 0 或队列终态不能单独通过 |
| 视觉 | 实际查看所有场景、关键状态/转场和替换边界；文字可读、层级明确、裁切正确、允许与意外遮挡可区分；偏离参考在允许范围内 | 坐标图与实际帧、时间点、逐项结论；不能用布局草图代替实际产物 |
| 连续听看 | 实际播放声明范围；检查叙事连贯、语音/字幕/画面同步、读完时间、转场节奏、音轨清晰度与衔接 | 播放范围、问题时间段、实际听看结论；抽帧或 ASR 输出不能替代 |
| 目标平台/真机 | 在声明的实际设备/平台检查比例、清晰度、UI 遮挡、裁切、字幕/小字可读和声音 | 平台、设备、版本与真实呈现记录；本地模拟只证明模拟条件 |
| 生产接入 | 当前入口、参数传递、实际队列读回与端到端产物对应，恢复范围已经确认 | 实际任务及产物身份；独立脚本渲染不证明工作台接入 |
| 交付与复现 | runbook、规格、实现、输入和产物版本对应；独立执行者能按相同契约找到参数、检查并恢复 | 引用/版本检查和实际复跑记录；尚未复跑就保留待验证 |

数值阈值由具体模板、类型扩展及目标环境规定，并保存依据；本量表不统一所有视频的画幅、字幕行数、字号、色彩、节奏或响度。允许有意留白、静音和重叠，前提是规格明确并经对应检查。

## 阶段 gate

1. **规格交付。** schema/静态可检项通过，全部核心项目已有确定规则或合格 unknowns；参考观察和设计决定明确。完成条件：可以交付规格及补证据计划，不能宣称实现已就绪。
2. **开发验收短样。** `implementation + specification` 在本次授权、当前工具能力及样片所需参数已定时可生成限定范围的样片；reference 保持取证与规格交付。样本覆盖声明范围的关键布局、内容长短边界、状态、转场及适用类型风险；技术、视觉与适用听看项分别验收。完成条件：实际证据仅支持该样片范围，首次样片不自动升级其他状态。
3. **执行就绪。** 实现入口和参数真值当前可用，必需参数无未知/占位项，技术与视觉通过实际产物检查和实际查看帧，真实证据文件和哈希可核对，操作契约与适用前置 gate 完整。完成条件：作者明确将阶段更新为 `implementation + ready`，声明与实际证据一致；受控模板复用及正式生产再核对对应 gate，生产接入、听看、用户确认和真机状态分别记录。
4. **全片通过。** 核对完整产物与冻结输入，完成全片技术验证、覆盖性视觉检查及连续听看；失败项修复后复验受影响和关联项。完成条件：可声明该版本、输入范围的全片产物通过，目标平台未验时仍单列待验证。
5. **目标环境通过。** 在声明的真实设备/平台完成呈现检查；用户确认按本次任务要求记录。完成条件：证据仅支持实际平台、设备、版本与范围；其他环境保持独立状态。

静态检查：在 Videohub 根目录运行 `python verify/check_template_standards.py --workspace` 或 `python verify/check_template_standards.py --spec <规格JSON路径>`。`--workspace` 本地只读，无写入、采集或扣费；自动检查只能证明它实际检查的结构和约束。

## 跨 Agent 一致性检查

用相同规范版本、模板需求和证据包，由两个独立 Agent 填写规格与骨架；比较必填覆盖、真值选择、元素粒度、坐标/时间定义、slots 边界、未知项处理和状态声明。每个差异定位到规则或证据：规则不足就修规则，信息不足就登记 unknowns，再按量表复核。若要声称跨模型一致，记录实际使用的模型与比较结果；未运行只能记录验证计划。

复现目标是同一契约、受控变化和相同验收判断；新文案、素材及设计扩展的画面可以不同。随机生成能力需要记录种子/模型/版本及允许容差，无法保证逐像素一致时说明实际复现范围。
