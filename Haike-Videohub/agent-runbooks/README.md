# Agent 操作知识库

本目录只保存**当前可执行、跨仓可复用**的操作流程。`contracts/` 定义接口与硬约束；各项目的代码、配置和专项 skill 是功能真值；`docs/pitfalls.md` 保存历史事故。本目录不复制整份开发文档、逐次任务日志或本机环境记忆。冲突时停下核对当前代码与用户本次指令，不用旧手册覆盖实时状态。

## 使用方法

1. 读匹配手册和它指向的契约、项目入口；确认手册的适用范围及最近核验条件。
2. 核对用户本次授权、当前代码／配置、输入文件、账号或来源状态、已有任务。历史 ID、路径、模型和页面状态不能当成当前参数。
3. 按手册的读回点执行；遇到不符时停下核对，不盲目重试或切换来源。
4. 用完成证据验收。发现新经验时按下述提案规则处理；无新发现无需改动手册或刷新日期。

## 谁可以改

- **所有执行 Agent**：可读手册。发现差异时，向任务负责人提出“现象／当前代码或结果证据／受影响步骤／建议修改／是否已验证”；不直接把自己的推测写成正式结论。
- **知识库维护者**：须得到用户对本次知识库维护的明确委托，并能核对当前代码、契约与实际结果。维护者修改正式手册；新增或实质改变高风险步骤（真实发布、扣费、删除、手工改状态）应由用户审定后才列为可执行步骤。
- **审阅与合并**：不同 Agent 在独立分支或工作树提交提案；指定维护者逐个核对和合并。共享工作树有未提交改动时，不自动 `pull --rebase`、不覆盖他人文件、不自动提交其他 Agent 的修改。只有 Git 提交并推送到可访问的远端，跨机器 Agent 才能获得更新；本仓目前的远端配置须另行确认。

仅靠本页不能限制同一文件系统账号的写权限。需要强制隔离时，应在仓库托管端配置写入权限、受保护分支和必要审阅。

## 收录、替换与退出

- **新增**：流程要反复使用，且现有项目文档或 skill 没有覆盖关键跨仓操作；或一次高损失事故暴露了必须持续执行的防错步骤。先用 [TEMPLATE.md](TEMPLATE.md) 写明适用条件、依据和恢复点。临时脚本要先进入其所属项目的正式位置，才可成为长期依赖。
- **命名**：新建知识库文档默认使用中文文件名，方便按中文任务检索；工具或上游明确要求的固定文件名除外。既有英文文件名不因本规则批量改名；如确需改名，必须同步更新所有引用。
- **已实测**：只表示所记录的版本、平台和条件下有完成证据，不代表永久通用。没有完成证据、当前代码变化未复核、平台行为不明时标「待验证」，禁止冒充现行可靠流程。
- **修订**：修改现行步骤时**替换旧结论**，合并重复条目；只保留理解当前操作所需的简短说明。历史任务 ID、旧模型、逐次日志依靠 Git 历史或所属项目证据保存，不持续追加到正文。
- **停用**：流程被新代码取代、长期无法核验或可能误导操作时，从上表移除或标「停用」，给出替代入口；不让过期手册继续作为 Agent 的默认路径。平台或契约变化时主动复核受影响手册。
- **本机经验**：只在某台机器出现的环境配置留在本机记录。若问题在其他机器可复现，把**适用条件与诊断办法**写到所属项目或跨仓事故文档，不复制本机路径和秘密。

修改前运行 `python verify/check_runbooks.py`，并核对适用条件、当前代码和实际证据；仓库接入 GitHub 后，同一检查也在 PR／推送时运行。单独检出 Videohub 时无法检查不存在的兄弟仓库路径，维护者仍须在完整工作区核对。禁止写入密钥、Cookie 值、浏览器 Profile、完整日志或媒体文件；检查器只扫描结构、本地链接和明显的凭据文本，不能证明流程正确，也不能替代人工审阅。
