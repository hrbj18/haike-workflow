# 模板图文视频生产手册

状态：已实测（2026-09-30：共享素材库分级选材接四条DevDay模板，三条通过生产验收、一条按用户要求保留原题为事实待核验预览；历史手机安全区v2保持）。
最近核验：2026-09-30。仅验证当前执行者、本地既有素材、裁切证据和模板入库；未实测ds4.1、新一轮网络采集或平台发布。

适用范围：**模板图文视频**（9 秒竖屏图文快剪）——1080×1920、30fps、9 秒；版式为顶部 3 行大标题＋黑底结论条／中部 3 景×3 秒 B-roll／底部 3 段详情卡。本手册覆盖从「主题已定」到「该主题成片进入项目库可审核」的全过程，含选题边界、词表与文案条目、采集、选段、渲染、QC、项目库回写、交付汇报文档闸门。**不适用**：数字人口播长片（另一条链路）；窗口复刻（保留参考片中间画面、只换上下板）；任何公开发布动作（那是 [短视频三平台发布.md](短视频三平台发布.md)）。
核验条件：完整兄弟仓布局、Haike_video/.venv、项目内BGM与YuNet、当前素材库V1。素材保留原文件位置，SHA256登记多位置；确认秒段与实际裁切后才采用。本轮未登录或重新下载，不把历史Cookie、账号或检索状态当成当前状态。
完成证据：每条冻结spec、来源与授权清单、三场景脚本/场景计划/资产清单、成片报告、快照、3:4封面与来源证明、L1/L2/L3和响度记录；API和项目库可读。事实待核验项目报告为`fact_pending`，不能算可交付新闻。具体验收见 [DevDay四期验证文档](../../Haike_video/docs/development/2026-09-30-DevDay四期生产验证与runbook同步.md)。

权威入口：`../copy_skill/copy_skill-main/docs/tasks/2026-09-23-template-douyin-clean-broll.md`、`../copy_skill/copy_skill-main/config/content_intelligence.json`、`../copy_skill/copy_skill-main/scripts/build_report_doc.py`、`../Haike_video/docs/tasks/2026-09-23-autonomous-material-selection.md`、`../Haike_video/docs/MATERIAL_SELECTION_POLICY_V1_ZH-CN.md`、`../Haike_video/scripts/template_video/README.md`（流水线脚本清单与路径口径）、`../Haike_video/scripts/template_video/_paths.py`（路径收口点＝唯一真值）、`contracts/candidate-pool-v2.md`、`../Haike_video/docs/MATERIAL_LIBRARY_V1.md`（素材库、证据、分级与补采的当前合同）。这些路径都从 Videohub 仓库根目录定位。本手册只记录可复制的操作顺序与安全恢复；新闻事实、素材权利状态与用户本次授权以所属项目和用户指令为准，冲突时停下核对当前代码与用户指令。相关历史事故见 [../docs/pitfalls.md](../docs/pitfalls.md)。

## 2. 主题与文案（先备料，再动手）

### 2.1 选题边界

**本手册不管「今天做什么」。** 选题由上游的每日热点候选池负责：生产端 `copy_skill/copy_skill-main/src/douyin_intelligence/daily_hot_candidate_pool.py`，消费端 `Haike_video/backlot/copy_skill_hotspot_feed.py`，目录与校验规则见 `contracts/candidate-pool-v2.md`。

### 2.2 下载前先写分级需求，下载后确认画面

需求JSON明示`topic/entities/series/brands/domains/single_source`；默认仅精确主题，除950启动词族外不自动推断别名。实体、上位系列和品牌分别给A/B/C；D仅行业氛围，unknown/conflict禁止自动采用。A表示目标相关画面，资料页、发布会转录与产品实拍仍须区分。

先查共享库，缺口才扩检索词：精确实体→同系列→同品牌相关画面，不能以无关行业镜头代替全部9秒。每条至少3秒A/B/C。检索失败须区分无结果、下载受限、裁切不可用、身份未知，不能笼统写“全网找不到”。

CopySkill词表位置仍为`config/content_intelligence.json → jobs.material_replication`的`theme_keywords/theme_subject_terms`；关键词3–10个，主题字符上限以当前配置为准。不要用“25倍用量”之类待核事实作检索依据。补采合同默认最多两轮、每轮10词/180MiB/600秒；由采集执行者落实，程序不自动联网。当前补采默认词族偏硬件，本轮软件主题复用本地素材，**软件网络补采尚未实测**，不能照搬真机/机柜词族。

步骤、需求/提交格式与补采CLI详见 [素材库V1](../../Haike_video/docs/MATERIAL_LIBRARY_V1.md)。

### 2.3 给构建脚本补文案条目

位置：`../Haike_video/scripts/template_video/build_923.py` 的 `SPECS` 字典，每个主题一条：

| 键 | 含义 |
|---|---|

- `SPECS` 里已有的主题，**不要顺手改文案或 BGM**，那属新闻事实层，改动即超出本手册范围。

### 5.1 版式 v2：手机端安全区（2026-09-29 新增，t23 起生效）

**起因**：v1 成片在真机上被用户指出「最上面太靠上，会和抖音最上面的搜索等功能按键重叠」。原因是此前所有版式常量都只按**画布坐标**设计，从未与**手机屏幕上抖音 UI 的实际占位**对过账。

**做法：用实机截图反解坐标映射，而不是凭感觉留白。**

1. 取一张该机型的抖音播放页**原始分辨率截图**（含状态栏、头像行、频道 tab、底部 tab）。
2. 把截图里的视频画面区域与成片画布对齐，解出线性映射。本机实测（1080×1920 播放页截图）：
   `screen_x = -96.5 + 1.364 × canvas_x`，`screen_y = +5 + 1.364 × canvas_y`（`s ≈ 1.364`）。
3. 用**帧级 MSE 反查**验证映射是否正确：把截图的可见条带反算回画布，与成片某一帧逐像素比 MSE。正确比例下 MSE 应降到两位数，错误比例会到 1000–9000 量级——**这一步不能省，否则会拿着一个错的比例去改版式**。
4. 读出抖音 UI 的实际占位，换算回画布坐标：
   - 抖音横向裁切后，**可见画布 x 仅 71..1008**（不是 0..1080）——左右各有约 71px 被 UI 压掉，所以顶板/结论条的有效安全宽度是 **x72..1008**；
   - 顶部功能区（状态栏＋头像行＋频道 tab）下沿 = 画布 **y170**；
   - 另有一种浮动热搜条（半透明，非固定），实测底沿可到画布 y≈200，属**动态元素**，版式只能保证不与固定 UI 重叠。

**v2 常量（`build_923.py` 顶部，全部按画布坐标）**：

| 常量 | v2 值 | v1 值 | 含义 |
|---|---|---|---|
| `TOP_SAFE` | **212** | 100 | 首行文案**墨迹顶**的起排线，须越过抖音功能区下沿 y170 |
| `TOP_PLATE_BOTTOM` | **650** | 570 | 顶板下沿**下限**（实际取 `max(此值, 结论条底沿 + 12 + 100)`，见下） |
| `BAR_H` | **100** | 118 | 结论条高度 |
| `BAR_X0／BAR_X1` | **72／1008** | 40／1040 | 结论条左右边界＝可见画布宽 |
| `CARD_X0／CARD_X1` | **78／1002** | 60／1040 | 详情卡左右边界 |
| `GAP_BEFORE_BAR` | **12** | 26 | 最后一行标题与结论条的间距 |
| 顶部字号 `F_TOP` | **80** | 88 | 见 §2.3 |
| 结论条字号 `F_BAR` | **54** | 62 | 见 §2.3 |
| `BOTTOM_PLATE_TOP` | 1280 | 1280 | 底板顶沿，未变 |

**顶板自适应（v1 的老隐患，v2 一并修掉）**：`make_top()` 必须**先量排版、再画底板**：

```
y = TOP_SAFE
for text, _f, _s, sw in lines:
    b = d.textbbox((0, 0), text, font=F_TOP, stroke_width=sw)
    y += (b[3] - b[1]) + int(F_TOP.size * 0.18)
plate_bottom = max(TOP_PLATE_BOTTOM, y + GAP_BEFORE_BAR + BAR_H)
d.rectangle((0, 0, W, plate_bottom), fill=PLATE_COLOR)
```

v1 是先按固定高度画底板、再往上排字，实测结论条下沿比底板低 **32px**——素材画面会从结论条底下那条未覆盖的缝里透出来。**只要总行高变化（改文案、改字号、换字体），这个缝就会再现**，所以必须写成自适应的。

**安全区余量实测（t23@0.5s，叠在真机截图上的实机预览）**：首行墨迹顶 = 画布 211 → 屏幕 293；抖音固定功能区下沿 = 画布 170 → 屏幕 237，**净留白 ≈ 57px**；浮动热搜条底沿屏幕 ≈ 273，余量 ≈ 20px（紧但不重叠）。

**这件事的通用教训**：任何「上下留白」类版式调整，**必须拿实机截图反解坐标后定值**，不能拿画布坐标拍脑袋。画布坐标与手机可见区之间隔着一个 ~1.36 的缩放和一次横向裁切，凭感觉留的 100px 在屏幕上只剩 73px，且位置整体下移。

## 6. 渲染 9 秒成片（含 BGM 与响度）

```
../Haike_video/.venv/Scripts/python.exe ../Haike_video/scripts/template_video/build_923.py t2
```

输出 `short_out/t2_9s.mp4`。脚本负责：三景顺序拼接、上下不透明字板（顶 0–`plate_bottom`（v2 默认 650，自适应，见 §5.1）／底 1280–1920，先各自生成为 PNG 再 overlay）、BGM 裁剪＋尾部 1.2 秒淡出、响度处理。

**BGM 曲库与响度**：

- 本机曲库在`../Haike_video/song/`，由`_paths.MUSIC_DIR`解析，支持`OPENMONTAGE_MUSIC_DIR`覆盖。**song被Git忽略，不随检出分发**；换机先同步合规曲库或配置现有目录，缺曲不能开始渲染。
- 响度两模式，由 SPECS 决定：
  - 默认：`loudnorm I=<lufs_target 缺省 −11> : TP=−1.5 : LRA=11`；
  - `loud_mode: "limit"`：`volume=<boost_db>dB` ＋ 限制器硬拉。**当 BGM 峰值余量不足时，loudnorm 会被 TP 天花板卡住、响度上不去**，这时才改走 limit 模式并调 `boost_db`。
- **须测最终AAC成片**；loudnorm的TP参数不保证编码后达标。超限时保留原版本，仅修音轨并复测，不重采/重做所有镜头。
- 验收口径沿用音频通用判据 `|I − target| ≤ 1.5`、`TP ≤ −1.0`（见 [../docs/pitfalls.md](../docs/pitfalls.md) 第 10 条）。注意那条里的「成片 −9 LUFS」是**口播链路的项目 target**，模板图文视频缺省是 −11，别照抄。

归档：把 `short_out/<t>_9s.mp4` 复制为 `final_923/<序号>_<主题>_9s.mp4`，序号与该主题在项目库里的既有编号一致。

## 7. QC 与回写项目库

**QC 三层门禁（缺一层不算过）**——「文件正常」不等于「内容合格」（2026-09-29 事故主因）：

| 层 | 做什么 | 判据 |
|---|---|---|
| **L1 文件层** | `ffprobe` 元数据 ＋ 全解码扫描 | 1080×1920／30fps／9.0s／含音轨；`ffmpeg -v error -i <成片> -f null -` 无 error 输出 |
| **L2 内容层**（硬门禁） | 中央可见区（归一化后 **y650–1280**（v2；v1 为 y570–1280））**按 ≤0.5 秒步长密采样**：人脸＋亮度＋文本 | `face_big`（人脸宽 ≥ 中央区宽 ×0.22）命中 **0 帧**；亮度不低于下限（`V ≥ 45`）；中央区无外挂字幕／源作者水印 |
| **L3 目视层** | 从**成片**抽 ≥8 帧拼全片联系表，人工复核 | 逐格确认主体相关、无字幕水印、顶底板完全不透 |

- L1、L2、L3分别留证据。运行`qc_ep.py <成片> <t_key>_9s 0.3333333333`做3fps检查，输出`qc_final_<t_key>_9s.json`；**它仅做中央画面QC，L1解码/元数据、音频、事实需另外验证**。退出非0不得归档完成。
- 当前自动文本判据为置信度≥0.6且≥2个CJK字；并未覆盖所有语种。英文水印、外挂字幕须人工分流，原生产品UI/logo/展示资料文字可接受。已确认文字或受限时空区域进入冻结spec；不能用白名单覆盖作者字幕。
- 任一自动暗帧/大脸/未确认中文字风险未解决即失败，不把“目视似乎可用”直接改成pass。换窗口或修改裁切后创建新证据/冻结spec再复检；不能关闭门禁。
- L3至少8帧实际查看，本轮9帧；抽样不能证明所有帧无问题。检查上下板不透、文字无溢出、主题画面正确。
- 文件QC通过不等于新闻核验通过：未获一手证据且用户保留原题时，报告`status/editorial_status=fact_pending`，只入待核验预览；不混入已通过新闻归档。发布授权与版权另核对。

新批次使用可复用manifest回写入口：

```powershell
& $python scripts/template_video/rewrite_923_projects.py --manifest writeback.json '<t_key>'
```

writeback为t_key到配置的JSON映射，字段：`project/label/title/final/final_dir/source_batch/editorial_status/qc_file`，以及可选`caption_review/evidence_files`。editorial_status只接受verified或fact_pending，必须给当前QC文件；QC须对应`<t_key>_9s`、覆盖0–至少8.5秒、采样间隔≤0.5秒、逐帧风险为false且汇总pass=true/risks为空。evidence_files为目标纯文件名到来源路径的映射，建议存事实核验、冻结spec/plan、L1/响度和L3记录。不填写虚假的模型/生图来源。

脚本拷成片、写四清单（资产保留media/clip/selection ID、等级与裁切）、抽三张场景快照；新增批次不再需要硬编码THEMES。先写`artifacts/script.json`三段cue-001..003，带文本和0–3/3–6/6–9秒；封面1080×1440与proof说明既有底图复用还是本轮生成。未知生成者保持unknown。

完成读回：`GET /api/projects`有3场景与渲染；`GET /api/project/<pid>/state`有三段脚本和资产；项目库卡片可打开预览。兼容模板无统一流水线checkpoint是预期，不能把通用自动生产未开始当模板失败，也不能启动其他旁白/队列覆盖模板。新导演台可看三段，成片播放可从旧版看板Renders进入。报告completed仅代表模板产物完成，前端仍待人工审核、未发布。


## 8. 交付目录与汇报文档闸门

交付目录在采集阶段就已生成骨架，`汇报文档.md` 由管线在交付收尾阶段自动写入（配置项 `jobs.material_replication.report_doc.enabled = true`）。文件分两类内容：

- **自动段**（一、结论速览／四、交付物清单／五、管线结果与诊断／七、文档索引）：每次运行刷新，不要手改；
- **人工段**（二、产品是什么（事实层）／三、参考视频拆解要点／六、风险与待办）：留 `<!-- HUMAN-TODO -->` 标记，**必须人工填完**。

**闸门（交付前必过）**：

```
cd ../copy_skill/copy_skill-main
python scripts/build_report_doc.py --delivery "output/复刻视频/<目录名>" --check
```

- `--check` 只检查人工段是否填完，**不写文件**。**退 0 才算过；人工段未填完退 2**。
- 批量检查：`python scripts/build_report_doc.py --all --check --root "output/复刻视频" --since "<业务日期>"`，会汇总「完整／待人工填写／免检（早于生效日、dry-run 排练）」三类。
- `00-交付说明.md` 里的「## 汇报文档」段会自动反映当前状态与待填小节名，可直接对照。
- **重跑安全**：重跑交付时人工段按 carry-over 保留；`--force` 会**丢弃已填的人工段、整份重写**，不要随手加。
- ⚠️ **这条闸门曾长期失效**：该检查原先是 `src/` 全树零引用的裸脚本，管线既不产出也不校验，已发布交付里绝大多数缺这份文件，而状态、体积、清单自校验全部照常通过。**看到「管线 done」不等于交付合规**，必须单独跑 `--check`。
