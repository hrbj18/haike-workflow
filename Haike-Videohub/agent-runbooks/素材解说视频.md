权威入口：[生产端合同](../../Haike_video/docs/MATERIAL_COMMENTARY_V1.md)、[导演 skill](../../Haike_video/skills/pipelines/material-commentary/director.md)、[CLI](../../Haike_video/scripts/material_commentary_cli.py)、[API](../../Haike_video/backlot/commentary_api.py)、[自动化测试](../../Haike_video/tests/backlot/test_material_commentary.py)。

用户本次指令与实时状态优先。题材、镜头数量、顺序、段长由素材决定，本手册固定制作过程而不固定故事框架。

## 触发条件与输入

- 用户要求“素材解说视频”“电影解说”“直播切片解说”或同类基于已有画面的旁白/原声编排时使用；先读 [Haike_video 入口](../../Haike_video/AGENTS.md)。
- 输入为本次目标、素材库身份及来源、画幅、已有音轨/音色选择、音乐方案和费用边界。只有媒体链接时先按对应流程取得并登记素材；抖音下载见 [下载抖音视频](下载抖音视频.md)。
- 打开 `/material-commentary`，或执行 CLI 的 `list/brief/versions`，读回已有草稿、配音、冻结版本与队列。复用已完成步骤，沿用本次会话已有授权。
- 本地素材取证和合成为本地 FFmpeg。若需新 TTS/ASR，先按现有供应商规则核对配置、音色、模型、预算；独立可做的本地步骤继续推进。

## 当前操作

### 1. 建立项目并从素材定位题材

在 `Haike_video` 根目录使用项目 Python，或在工作台选择“创建素材解说”。先查共享库，缺少时登记原片及来源。新项目返回 `project_id`，保存其工作流登记和当前 `revision`。

```powershell
python scripts/material_library_cli.py query "<本次片名、人物或主题>"
python scripts/material_commentary_cli.py create "<本次项目标题>"
python scripts/material_commentary_cli.py --output "<brief.json>" brief "<project_id>"
```

完成判据：项目、素材身份和授权范围明确，尚在运行的任务已识别；不重复建立同一生产任务。

### 2. 概览、定位，再精查采用窗口

按 [视频快速理解与分层分析](视频快速理解与分层分析.md) 先概览。长电影/直播先读章节和已有转写，找到与本次目标相关的事件或问答，再查看局部窗口。转写不能代替画面观察，静帧不能证明动作完整或已听辨台词。

工作台选择素材及源起止点，点击“准备区间证据”；或 CLI：

```powershell
python scripts/material_commentary_cli.py evidence "<project_id>" "<evidence-request.json>"
python scripts/material_commentary_cli.py review "<project_id>" "<evidence_id>" "<review.json>"
```

字段格式见 [生产端合同的 CLI 与 HTTP](../../Haike_video/docs/MATERIAL_COMMENTARY_V1.md#cli-与-http)。单次窗口最多 120 秒。查看返回的 `sheet.jpg` 和所需连续播放片段，再记录观察、前后文、台词、未知项、原字幕与配乐状态。只有实际回听才填写 `audio_reviewed=true`；确实可用才填写 `usable=true`。

电影重点查人物、时序与因果；直播保留问题与回答的限定条件；演示和现场关注动作完成、结果及反应。自动得分、文件名和素材标题只能帮助定位。

完成判据：每个拟采用镜头有可核对的源窗口与已确认观察；未知内容被保留为未知或补证据，不能写成事实。

### 3. 由素材形成自由叙事

读回 `brief` 的观察，填写解说目标 `intent` 和编排理由 `structure`，添加自由数量段落。每段保存叙事作用 `purpose`、素材依据 `basis`、声音方式及已确认镜头。允许先结果后原因、完整问答、并列对照、连续原声或跨源解释。

镜头引用证据中的源秒数；程序检查越界及裁切身份。需要换裁切时重新取证。首版不要求开头/正文/结尾、不要求三镜头、不限制为 30—60 秒。资源上限见生产端合同。

完成判据：每段内容、顺序和声画关系都能由观察解释，没有为凑固定框架编造情节或补无关镜头。

### 4. 确定声音与字幕

旁白段选择 `narration`，原声段选择 `original`，需要旁白和现场声共存时选 `mixed`。优先复用或导入匹配文案的现有音轨：

```powershell
python scripts/material_commentary_cli.py audio-import "<project_id>" "<audio-import.json>"
```

如需生成配音，工作台先“核对本次配音”，或 CLI `quote` 读取配音中心已有音色的完整冻结参数和估算，再按本次授权执行 `tts`。明确供应商、模型、音色/语速、单次字数上限与估算费用上限，并核对项目/当日预算。估算为零不表示免费；不能静默换音色或换供应商。

音轨决定旁白段时长，镜头须提供足够覆盖。文案改变要匹配新音轨；只换镜头或顺序复用已有配音。原声按源区间保留，缺音轨的源会补静音。

先核对原字幕与配乐。原字幕存在/未知时，新字幕置顶并写处理说明，或关闭新字幕；原声里已有音乐不会自动移除。新增配乐须说明混音策略。估时字幕保留待校准提示，准确字幕使用逐句时间戳。

完成判据：文案、音轨和字幕对应，原声/旧字幕处理明确，未完成的回听仍标待核对。

### 5. 保存、预检、入统一队列

保存请求用 `brief.draft` 或页面导出的编辑清单，保留读回的 `revision`。保存后使用新返回版本号：

```powershell
python scripts/material_commentary_cli.py save "<project_id>" "<draft.json>"
python scripts/material_commentary_cli.py preflight "<project_id>" <revision>
python scripts/material_commentary_cli.py submit "<project_id>" <revision>
python scripts/material_commentary_cli.py versions "<project_id>"
```

`preflight` 不渲染、不入队、不生成配音；取证和音轨导入会写本地文件，`submit` 会冻结并入队。素材不足返回 `needs_material`、段落及缺口秒数；补充已确认镜头或缩短旁白后重新保存，不循环素材、拉伸语音或定格补时。

提交生成 `material_commentary` 统一队列任务，并为实际镜头绑定 `MREF`、登记版本使用台账 `MUSE`；由工作台现有队列执行器处理。读取返回任务，已冻结的同 `revision` 恢复原签名和任务；不要另启直接渲染脚本。新版本仅用未归档素材，已归档来源的历史冻结版本仍可恢复。HTTP 等效入口为 `POST /api/material-commentaries/{id}/preflight` 和 `/render`，请求体都是 `{revision}`。

完成判据：预检通过，冻结版本与队列任务能相互对应，现有单通道队列正常执行。

### 6. 检查并交付待审片

通过 `versions` 或 `GET /api/material-commentaries/{id}` 读取版本、技术检查与关联队列。技术完成条件是 `status=completed`、`qa.status=passed`；页面应能播放该版本并取得 SRT。`review_status=pending_review` 表示仍待人观看。

按项目最多两轮独立审查：一次查结构、语义、来源和未知项；一次查代表帧、连续播放、字幕时序、原声切口及混音。人工/agent 没有实际回听的部分明确标出。修正局部段落时生成新版本，保留旧版本，复用未变段落与已有配音。

完成判据：可播放预览、技术报告、素材来源、版本和剩余人工检查已交付；内容只停在待审。发布需另行进入已授权的发布流程。

## 已知故障与安全恢复

| 现象 | 判断依据 | 当前安全恢复点 |
|---|---|---|
| 画面不够覆盖配音 | `needs_material`、`missing_seconds` | 为该段补已确认镜头或改短配音，其他段保留 |
| 保存或提交遇到版本冲突 | CLI 3 / HTTP 409 | 重读 `brief`，合并本次修改后保存；不强写 revision |
| 源文件/证据哈希变化 | 校验提示旧证据不可沿用 | 恢复原文件，或重新登记新媒体并取证；旧版本保留 |
| 素材已归档 | 新取证/新版本拒绝 | 使用可用素材，或按素材库管理流程恢复；历史冻结版本直接重试，不把归档状态写回冻结清单 |
| 原片移动后旧路径失效 | 素材库找不到原片 | 在素材库管理中重定位同一指纹文件，再重试已有任务；内容改变需重新登记取证 |
| 需要更正已有观察 | 不可变 `review.json` 冲突 | `evidence` 请求增加新的 `review_revision`（最多 80 字），重新查看并提交观察，再替换草稿的证据引用；保留旧证据和冻结版本 |
| 配音与文案不符 | 文案校验失败 | 选回对应音轨/文案，或只为改动段生成新配音 |
| TTS 状态不确定 | `submitting/ambiguous` | 核对供应商原任务或导入已获得音轨；保留账本，禁止自动重发 |
| TTS 已生成但导入中断 | 账本 `generated` 且原音轨存在 | 相同请求继续导入，不再提交供应商 |
| 原字幕或源音乐冲突 | 预检拒绝及中文原因 | 核对实际源片，修正字幕位置/说明或音乐方案；重新裁切须重取证 |
| 字幕超安全宽度 | 渲染返回具体段落 | 改成更短的逐句字幕并保存新版本；不覆盖冻结请求 |
| FFmpeg、字体或编码失败 | 任务 failed / result.json error | 检查媒体依赖、磁盘、`OPENMONTAGE_COMMENTARY_FONT`；修复环境后在统一队列重试同版本，复用有效缓存 |
| 已冻结字体内容变化 | 字体指纹验证拒绝 | 恢复原字体；有意换字体时先在草稿中记录修改说明并保存出新 `revision`，预检后提交；旧 `revision` 重提仍恢复旧版本 |
| 技术完成但原声/字幕有警告 | result 的 warnings / pending_review | 连续播放和回听，必要时局部修改；不把技术通过称为人工验收通过 |
