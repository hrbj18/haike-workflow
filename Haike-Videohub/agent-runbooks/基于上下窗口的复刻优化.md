## 1. 呼叫名与默认要求

- 固定中文呼叫名：**基于上下窗口的复刻优化**。复用 `window-remake` 兼容工作流，不新建素材拼接或 AI 视频生成生产线。
- 中间主体按原顺序播放，保留原时长与音画同步，不擅自加速、镜像、换镜、裁掉主体或加音乐。
- 默认 1080×1920，简约背景、清晰大字、少量强调色；不加新 Logo。用户要求移除顶部装饰 Logo 时，仅处理上下区域；位于主体内部的标识不可为清理版面而扩大遮挡。
- 原有文案默认保留，可重新分行和排版；新增标题依据视频内容，固定说明不能伪装成台词。新文档中文命名。
- 本流程交付优化视频。只有用户要求发布时，才衔接 [短视频三平台发布.md](短视频三平台发布.md)，自行编写各平台标题、详情与话题，生成封面并随视频上传，读回实际封面。

## 2. 先看源片，再定板位

1. 核对绝对路径、ffprobe 的视频/音频流、尺寸、帧率、时长和 SHA-256。新项目使用稳定 ID，记录源片和派生素材关系，不覆盖原文件。
2. 按 [视频快速理解与分层分析](视频快速理解与分层分析.md) 先生成概览，再对首尾、切镜、文字和版式变化处补证据；注意首帧/前几帧可能是独立封面。分辨黑边、装饰标题、烧入字幕和真实画面；概览采样点不直接作为板位切换的精确时刻。
3. 已有上下留白：记录实际主体像素边界，换算 `plate_top_h` / `plate_bot_y`。运行 `measure` 留档，人工核对；算法把主体中的字或高光当成边界时，以已看过的画面为准。
4. 横屏源：先通过 FFmpeg 等比缩放并补齐 1080×1920 的中间素材，完整保留画面，不拉伸；随后进入相同项目流程。原始及中间素材均留出处、参数和哈希。
5. 主体高度随镜头变化时，用分时图层避让，或按实际片段等比装入统一窗口。不能让整片统一板位遮住开头或其他镜头。极短独立封面可完整保留，换板从主体镜头开始。

## 3. 文案、字幕和音频

- 固定标题/说明与台词字幕分别记录。原片主体内部的烧入字幕默认保留，避免新增一份形成重影。
- 需要重建台词时，读取当前语音转写技能，以音频转写并校对；已有准确字幕则优先复用时间戳。专名、数字和听不清的内容须检查，不能猜词。
- **禁止将对话字幕按总时长平均分配。** `subtitles.cues` 是连续铺满音频的场景时钟；`subtitles.overlay` 是实际字幕出现区间，允许间隙。二者不可混为一谈。
- 明确设置 `subtitles.mode`：`overlay` 请求只画定时图层字幕；`system` 只用工作台字幕；`source` 请求不生成字幕，保留源片字幕。`composition_layers` 可提供完整的自定义图层列表，使用时须自行遵守同一字幕模式，不重复加入字幕。
- **当前工作台的渲染限制**：`source_audio_only` 渲染仍会烧录 cues 文字，字幕样式的 `enabled:false` 没有在渲染器完全生效。仅切模式不够。本次兼容处理将 `system_y` 设为 0.94、系统字号设为 24，并用全程不透明底板覆盖该区域；实际对观众显示的文字另用 overlay。必须检查系统文字的完整范围和底板覆盖，不能照搬坐标到没有足够底板的视频。无安全覆盖区域时，须修复渲染器后再交付。此法是换板流程的兼容处理，不代表底层字幕开关已修好。
- 关键底部文字底边小于画布高度的 0.80；上方标题不能超宽。空间不足时调整窗口布局或字号，不能裁掉机械手等主体来容纳文字。
- 保留原声时，通过 FFmpeg 单独提取同一区间音轨；将该音轨放入 `assets.bgm`（这是旧 CLI 的音轨上传参数名，**不表示添加背景音乐**）。不另叠音乐，音频与视频起点一致。
- 保存本项目的响度目标，依据实测选择；不能为通过检查一味抬音量。True Peak ≤ −1 dBTP，实际响度与项目目标差不超过 1.5 LU。

## 4. 可复用执行入口

先检查正确工作区的工作台服务可访问，再执行（在 Haike_video 根目录，解释器使用该项目环境）：

```powershell
& .venv/Scripts/python.exe scripts/remake_window_cli.py measure <本期spec绝对路径>
& .venv/Scripts/python.exe scripts/remake_window_cli.py prep <本期spec绝对路径>
```

`prep` 会写项目、素材、音轨、时间线与图层，并将全片预览送入统一队列。它不是只读命令。长任务保留进程/队列 ID 并查看日志；不得因暂时无结果重复入队。同 ID 复用资产时必须核对哈希，不能仅凭素材名相同推定内容相同。

spec 至少记录 `project_id`、`source`、`layout`、`titles`、`subtitles`、`assets`、`queue_preview: true`、独立的 `queue_idempotency_key`；可设置 `output_target_lufs` 和完整 `composition_layers`。修改布局后使用新的预览版本键，保留成功资产。

通过预览核对且满足项目审批要求后，执行：

```powershell
& .venv/Scripts/python.exe scripts/remake_window_cli.py final <本期spec绝对路径>
```

`final` 会批准预览并正式渲染，不能仅因文件存在就调用。测试任务可交付已核验的全片预览 MP4，并明确仍待用户观看，不需要为了交付测试片虚构人工审批。

## 5. 测试和交付

1. 结构检查：队列完成、音视频流存在、时长/帧数与源片一致（容许编码封装的一帧级尾差）、画面 9:16、主体不变形、无额外配音音乐。
2. 视觉/输出检查：首尾、切镜、文字切换点及字幕起止点；没有旧标题露边、字幕重影、超框或遮主体。记录音频响度与 True Peak；按源片与成片相同时间位置核对音频时钟。
3. 交付可点击的成片/测试片、代表帧和 runbook；说明保留内容、修改区域及真实待审事项。运行产物留项目目录，不放进知识库。

## 已知故障与恢复

| 现象 | 处理 |
|---|---|
| 自动板位覆盖主体 | 回看代表帧并手工定板；分时处理不同主体高度，不照抄历史比例。 |
| 上下出现两份同样字幕 | 检查 overlay 与工作台字幕是否同时启用；明确模式后重做预览，不能直接 final。 |
| `enabled:false` 后仍出现内部场景文字 | 当前源音频渲染路径忽略此开关；按上面的完整底板覆盖方法处理，逐帧确认首尾和切板时刻。没有覆盖条件时修复渲染路径，不交付带内部文字的片子。 |
| 图层 API 报 height 过小 | 当前最小高度为 0.01（1080×1920 时约 19 像素）；不要直接提交更细的色块图层。 |
| 开头遮住一帧主体或片尾露出黑底 | 同时核对解码帧编号和输出流 start_time，图层时间可能受输出 PTS 影响。全程板/文字使用 CLI 的 FULL_END 哨兵，不能照搬文件名义时长作为末帧结束时间；以实际导出首尾帧验证。 |
| 台词与声音不一致 | 回到转写/原字幕时间戳，只修改字幕及预览，不改音频速度迁就错误字幕。 |
| 无音轨或误换背景音乐 | `assets.bgm` 应指向源音轨；读取项目 music_library 返回的 track_id，不能手写 ID。 |
| 响度未达验收目标 | 读取实测响度与峰值，在项目级设置可达目标后重做预览，不跳过验收。 |
| 旧索引引用不存在的窗口复刻 SKILL.md | 本流程使用当前 CLI、模板与 FFmpeg 技能为权威入口；不依赖旧机器的技能路径。 |
