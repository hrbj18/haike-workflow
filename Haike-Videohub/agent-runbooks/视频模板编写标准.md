# 视频模板编写标准

文档类型：reference。
标准版本：video-template-v1（v1）。
适用范围：任意视频模板的新建、实质改版及 v1 规格的执行交接。

本文规定模板如何描述、编写和验收，不证明任何模板已接通生产。用户本次指令及当前项目 Guide、接口和配置决定本次可执行范围。旧模板渐进迁移：本次制定标准不升级旧核验状态，也不要求全部旧手册立即补规格文件；新建或实质改变版式、动效、替换范围、时序或实现入口时采用 v1。

## 入口与交付

- **编写或实质改版模板**：先读本文，再用[视频模板Runbook骨架](视频模板Runbook骨架.md)；按实际元素和任务加载[类型扩展](template-standards/类型扩展.md)。
- **开发验收样片或执行具体模板**：读该模板 runbook、它声明的规格和当前项目入口；按下述阶段边界核对本次动作的门槛。用户明确呼叫既有模板时，保留工作区入口规定的同名路由。
- **验收或交接**：按[视频模板验收量表](视频模板验收量表.md)逐项记录结论和证据。

每个新模板交付一份 runbook 和一个规格 JSON；规格可分阶段完善。字段、类型与枚举以[规格 schema](../contracts/video-template-spec-v1.schema.json)为准，[示例目录](template-standards/examples/)只演示填写方式。参数从规格或其声明的源码/配置入口读取；正文引用参数位置，避免再保存一套数值。

## 作者流程

作者完成规格、实现边界与验证记录；制片执行者填写受控替换槽并运行已声明入口。把需要重新设计、测量或开发的事项交回作者，执行手册只承载已确定的行为。

1. **确定任务与真值。** 核对用户本次目标、参考材料、现有模板、源码/配置和运行状态；声明 `spec_kind`、`stage`、权威入口及所需扩展。完成条件：能区分参考规格、实现规格与本次生产输入，每个入口可定位，缺失项已登记。
2. **清点场景与元素。** 建立叙事/信息层级、场景时间范围和元素清单；逐项写内容、空间、依赖、状态与时序。完成条件：全部可独立控制的对象有 ID，全部内嵌内容有边界，引用、空画面及音轨安排可解释。
3. **确定替换与证据。** 为可变内容定义 `slots`，记录每条规则来自观察、测量还是设计；未知项登记补证据计划。完成条件：每个替换槽都有范围与缺失/溢出处理，每个未知项都有阻断范围和解除条件。
4. **写操作契约。** 以骨架填写当前入口、输入、动作、产物、检查与恢复。完成条件：执行者无需猜测必需参数或重新选择流水线；参考规格尚无实现时明确停在规格交付。
5. **检查并验证。** 先运行静态检查，再按量表完成已授权的阶段验证；用实际证据更新各维度状态。完成条件：必需静态项通过，所有适用验收项有结论，待验证项与执行限制明确对应；未执行的阶段保持待验证。
6. **冻结交接。** 保存规格版本、源码/配置身份、验证条件及恢复点；按知识库索引与部署入口交接。完成条件：新 Agent 可由入口找到同一版本，全部本地引用有效，模板状态没有超出证据。

## 规格核心

以下是覆盖要求；机器字段名与结构以 schema 为唯一结构真值。

| 规格部分 | 必须确定的内容 |
|---|---|
| `canvas` | 输出尺寸、比例、帧率、时长规则、坐标单位、主时钟；平台安全区须说明目标平台与依据 |
| `narrative` / `scenes` | 信息优先级、章节/场景目的、出现顺序、全片范围；允许空白、静止或静音的区间与原因 |
| `assets` / `elements` | 素材身份与路径规则，全部可独立布局、替换、显隐、动画或验收的对象；背景、人物、文字、卡片、图表、图标、素材窗、品牌和装饰均按实际存在登记 |
| 元素内容 | 文字、图表数据、素材及内部标注；标明可编辑内容与已固化在图片/视频中的不可编辑内容，关联对应输入或素材 |
| 元素空间 | 父子关系、绘制顺序、锚点、尺寸、对齐与间距；遮罩、裁切、适配、溢出和避让规则；依赖的对象及计算顺序 |
| 元素行为 | 状态及触发条件、转场与动画的起止值/时间/曲线；静态对象也需明确显隐范围 |
| 元素时序 | 全片时间与场景/素材局部时间的区别，入出点、素材截取点、循环与冻结行为，声画同步关系及端点规则 |
| `slots` | 固定与替换字段、可变范围、默认值依据、长度/数量/素材约束、缺失与溢出处理；本次输入只填写已开放的槽 |
| `evidence` / `unknowns` | 来源种类、定位方法、测量/估读精度、设计依据；未知字段、原因、补证据动作与阻断范围 |
| `validation` / `operations` / `authority` | 验证维度和范围、操作契约、当前实现入口、版本与恢复点 |

**元素粒度。** 能独立控制的对象才成为独立元素；组件可以有子元素，字幕可以用组件内部规则管理逐字强调。作为整张素材使用的截图，其内部文字登记为固化内容；需要单独替换文字时，将其改为可编辑层并重新验证。元素不限定为二维图层：三维对象、镜头或程序生成过程可用自定义扩展说明坐标、依赖与行为，并保持相同的来源、替换和验收要求。

**空间与时间。** 坐标明确相对画布还是父对象，时间明确相对全片、场景还是素材；指定单位、锚点和区间端点。父级变换、遮罩及裁切的继承行为同处说明。依赖关系形成可求值顺序；同一属性受多个规则控制时写清优先级。数值、枚举或确定计算规则代替“大一点”“合适时切换”等描述，取值依据与容差一起保存。

**类型扩展。** 通用核心约束描述方法，类型扩展增加所需内容。模板可同时使用多个扩展，也可声明自定义扩展；按实际元素加载，类型名称不限制色彩、画幅或风格。音频主时钟、人物裁切等口播特性仅在对应能力需要时适用。

## 真值、证据与状态

`spec_kind: reference` 描述参考片的观察结果及明确标注的设计决定；它不能证明源码已实现。`spec_kind: implementation` 描述当前实现，`authority` 指向源码/配置及其版本。参考要求与实现有差异时记录差异、原因及本次接受范围，保留各自身份。

参数真值只能有一个：规格直接持有参数，或规格声明当前源码/配置为该参数的真值并绑定版本。参考视频是观察证据，截图和坐标图是定位与核对证据，样片是特定条件下的产物；它们分别承担职责，不相互替代。

证据来源与验证状态使用两个轴：

| 来源 | 记录要求 |
|---|---|
| 观察 | 参考材料身份、时间点/帧、所见内容与尚不能判断的部分 |
| 测量 | 测量对象、画布与方法、原始值、精度/容差；估读明确注明估读 |
| 设计 | 采用的规则、理由、允许偏离参考的范围；新决定进入实现规格后才约束执行 |
| 示意（`illustrative`） | 教学样例或字段演示，说明用途；它不证明参考观察、实际渲染或生产接入 |

每个验证维度分别记录通过、失败、待验证或不适用，对应 `pass`、`fail`、`pending`、`not_applicable`，以及版本、输入、范围、检查方法和证据位置。不适用需理由。技术成功、视觉抽样、连续听看、平台真机呈现、用户确认和生产接入各有范围；抽帧不能证明已听音，短样不能证明全片，隔离副本不能证明真实异机。

`stage: specification` 可保留 `unknowns`；每项写清目标字段、缺失原因、补证据方案、完成判据与受阻步骤。schema 允许的字段中可填写 `status: unknown` 的未知对象，并在 `unknowns` 同时登记对应路径和阻断范围。参考规格只用于取证和规格交付。

`implementation + specification` 在本次授权、当前工具能力与样片所需参数均已确定时，可以做范围明确的开发和验收样片；记录本次实现、输入、覆盖范围及实际产物，用于补齐技术/视觉证据。未确定的参数阻断依赖它的样片动作；首次样片不要求提前取得 ready，也不自动升级其他验证状态。

`stage: ready` 表示当前声明范围内的执行契约已完整：采用实现规格，当前入口存在，必需执行参数明确且无未知或占位值，技术与视觉已通过实际产物检查及实际查看帧，并有对应文件和哈希证据，适用前置 gate 已满足。阶段就绪与各验证维度分别记录；听看、生产接入、用户确认或真机待验证时，按量表限定交付声明。可选能力未启用时声明降级范围和对应验收，而非推断该能力已经通过。

受控模板复用及正式生产要求 ready 与该动作对应的 gate；开发验收样片通过后，由作者核对就绪条件并明确更新阶段。

## 操作与检查入口

每步写 `input → action → output → gate → recovery`：输入可定位，动作使用当前入口，产物可读回，gate 覆盖该步全部完成条件，恢复说明如何识别已有产物/任务并从哪里继续。正文 gate 在规格中写入 `operations.completion`，当前调用入口写入 `operations.entrypoint`。前置输入缺失时停在对应 gate；只有规格阶段可以继续独立取证。

在 Videohub 根目录运行：

```powershell
python verify/check_template_standards.py --workspace
python verify/check_template_standards.py --spec <规格JSON路径>
```

检查器验证规范文件、结构和可检查的约束；`--workspace` 为本地只读检查，无写入、采集、入队或扣费。静态通过不证明画面、音频、实际队列或平台已经通过。生产、付费和发布步骤继续遵循本次授权及各项目现行门禁。

修订 schema、实现入口、素材身份、布局、字幕、动效、替换范围或主时钟后，重验受影响维度。正式手册替换旧结论，运行产物与逐次日志留在项目证据中；知识库只保存可复用规则和证据定位方法。
